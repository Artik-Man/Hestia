# Процесс работы с git

## Ветка для работы

- Не выполняй работу в ветке `master`. Для каждой задачи создай отдельную рабочую ветку.
- Не сливай изменения в `master` без явной просьбы пользователя.
- Обычный порядок — подготовить изменения в рабочей ветке и передать их пользователю для самостоятельного слияния в `master`.

## Сборка перед коммитом

Перед каждым коммитом запусти сборку проекта и убедись, что она завершается успешно. Если сборка не проходит, не коммить изменения: сначала исправь проблему и повтори сборку.

## Частые коммиты

Делай небольшие, логически завершённые коммиты часто, по мере готовности изменений. Каждый коммит должен оставлять понятную точку, к которой можно вернуться при необходимости откатить последующие изменения.
