# Доступ к роутеру по SSH

## Условия доступа

Подключайся только к явно выбранному роутеру и только в рамках поручения на эту операцию. Для физического роутера требуется отдельное поручение владельца и, если операция меняет состояние, согласованное окно обслуживания. Доступ к рабочему Keenetic требует отдельного разрешения даже при подключении через `hestia-client`.

Используй настроенный SSH alias `keenetic-hestia` из приватного файла `private/keenetic/ssh/config`. Конфигурация закрепляет host key. Не отключай проверку host key, не подменяй конфигурацию и не подключайся к непроверенному адресу или ключу. Закрытый ключ и другие секреты храни в `private/`; не копируй их значения в документацию, отчёты, историю команд или журналы.

## Подключение

Сначала проверь наличие приватной конфигурации и затем выполняй команды через неё:

```sh
SSH_CONFIG=private/keenetic/ssh/config
ssh -F "$SSH_CONFIG" keenetic-hestia 'id -u; /opt/bin/opkg print-architecture'
```

Используй SSH для удалённых команд администрирования, preflight, резервного копирования, установки и проверки. Передачу бинарников и IPK выполняй через предназначенный для этого канал [hestia-cli](router-artifact-upload.md); SCP/SFTP и передача содержимого файлов через stdin SSH в текущем процессе поставки не используются.

Перед изменяющими командами проверь цель подключения, текущее состояние и разрешённый объём операции. Порядок установки Hestia приведён в [процессе установки на роутер](router-installation.md).
