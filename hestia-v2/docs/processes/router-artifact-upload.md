# Загрузка артефактов на роутер с помощью hestia-cli

## Назначение

Передавай IPK и исследовательские файлы на Keenetic через HTTP-сервер `hestia-cli`, работающий на доверенном LAN-адресе. Сервер принимает файл в заданный каталог, но не запускает его и не устанавливает IPK. Запуск исследования или установка пакета выполняются отдельной SSH-командой после проверок.

В текущем процессе сервер принимает файлы размером до 128 MiB. Не публикуй порт `8081` в WAN и не передавай токен по недоверенной сети.

## Порядок загрузки

1. Убедись, что `hestia-cli` и token-файл заранее установлены на роутере. При первоначальном bootstrap бинарник и token-файл помещаются в Entware локально; работающий `hestia-cli` не может загрузить сам себя.
2. На роутере создай отдельные каталоги `inbox` и `outbox` с закрытыми правами и запусти `hestia-cli serve`, привязав его к LAN-адресу.
3. На доверенном компьютере выбери готовый артефакт, проверь его происхождение и локальный SHA-256. Имя файла в endpoint должно быть простым именем без пути.
4. Отправь файл на `/v1/files/upload/{name}` с Bearer token из `private/hestia-cli.token`.
5. Через SSH вычисли SHA-256 загруженной копии в `inbox` и сравни с локальным значением. При несовпадении не запускай и не устанавливай файл.
6. После отдельной проверки выполни нужную SSH-команду. Для IPK следуй [процессу установки Hestia на роутер](router-installation.md); загрузка сама по себе не меняет состояние пакета.
7. Если нужно вернуть отчёт, положи его в `outbox` и скачай через `/v1/files/download/{name}`. Не включай токен или секретные данные в отчёт.

Токен хранится в `private/hestia-cli.token`; не печатай его и не сохраняй значение в журнал. Полные параметры сервера, команды `curl`, ограничения API и обработка ошибок описаны в [документе hestia-cli](../../../docs/features/hestia-cli.md#http-сервер-передачи-файлов) и [процедуре поставки Keenetic IPK](../../../scripts/deploy/keenetic-ipk.md#управляющий-доступ-и-передача-пакета).
