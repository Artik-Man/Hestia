# Адресное переключение UDP внутри группы подключений

Проверяем переключение новых потоков по паре «реальный IPv4 назначения, протокол». Группа содержит два доступных подключения, FI-1 и FI-2. Исходный выбор — FI-1. Клиент использует один и тот же порт сервиса для всех проб.

| Фаза | UDP до X | TCP до X | UDP до других контрольных адресов |
|---|---|---|---|
| До внесения потерь | Ответ через FI-1 | Ответ через FI-1 | Ответ через FI-1 |
| Потери внесены, выбор ещё не изменён | Потери на FI-1, независимая проба FI-2 получает ответ | Ответ через FI-1 | Ответ через FI-1 |
| Исключение применено при сохранении потерь | Ответ через FI-2 | Ответ через FI-1 | Ответ через FI-1 |

Для приёмки сопоставляем пробы клиента с ответами сервера и захватами выходов. Для контрольного UDP используем другой реальный адрес с тем же портом. Это позволяет обнаружить случайное переключение всего UDP группы или всего трафика к адресу X. Границы опыта — IPv4 и новые потоки.

## Как устроено правило

Стенд использует отдельный selector для UDP к `203.0.113.77/32` и общий selector для остальных финских потоков. Перед сравнением адреса sing-box разрешает тестовое имя в реальный IP. Явное правило российского домена обрабатывается первым: даже когда российское и финское имена указывают на один реальный IP, исключение финской группы должно затронуть только финское имя. У всех контрольных адресов один порт.

Для контроллера это задаёт ключ исключения: **группа подключений, реальный IP назначения, протокол**. Сначала определяется группа, затем внутри неё применяется исключение. В экспериментальной конфигурации один возможный адрес исключения задан заранее. Добавление произвольных исключений на работающем шлюзе — отдельная задача.

## Результат 4 ноября 2026 года

На ARM64-ВМ до отказа оба выхода вернули 5 из 5 контрольных UDP-проб к X. Сервер затем начал отбрасывать входящие UDP-пакеты только с интерфейса FI-1 к X. Оба интерфейса оставались включены. В новом измерении FI-1 вернул 0 из 5, а FI-2 — 5 из 5. Скрипт сравнил потери, переключил только селектор `udp-x` и прочитал состояние обоих селекторов обратно. Правило потерь продолжало действовать.

| Новый поток | После переключения |
|---|---|
| UDP к X (203.0.113.77), напрямую по IP и по FakeIP финского имени | Ответ через FI-2 |
| TCP к тому же X, напрямую по IP и по FakeIP | Ответ через FI-1 |
| UDP к Y (203.0.113.78) и Z (203.0.113.79), напрямую и по FakeIP | Ответ через FI-1 |
| TCP и UDP российского домена с тем же реальным X | Ответ через RU-1 |

В трёх фазах проверены 30 новых клиентских потоков и 20 контрольных UDP-проб. У каждого потока отдельный маркер. Фактический выход проверялся по источнику, увиденному сервером, и непрерывным захватам на всех трёх интерфейсах. Простая выборка из пяти пакетов на выход нужна для детерминированного опыта со 100% потерями. Пороги при частичных потерях, рабочее окно 60 минут и перенос открытого UDP-сеанса здесь не проверялись.

## Повторение

Подготовить [стенд Debian ARM64](../fakeip/README.md) с sing-box 1.14.4 и Clash API. В госте нужны также curl и iptables. Из корня копии проекта выполнить:

```sh
out=$(mktemp -d)
sudo bash experiments/scoped/lab.sh "$out"
sudo cat "$out/verification.txt"
```

Сохранённые результаты можно проверить отдельно на машине с Python 3 и tcpdump:

```sh
python3 -B experiments/scoped/probes.py verify experiments/scoped/evidence
```
