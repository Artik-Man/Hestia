# Read-only проверка TPROXY и socket match на KN-1012

## Вопрос и границы

Показывают ли метаданные ядра и справка уже установленных утилит KeeneticOS на KN-1012 наличие поддержки цели TPROXY и socket match? Проверка ограничена чтением `/proc`, метаданных ядра/модулей и справки или версии существующих исполняемых файлов. Она не добавляет правила, не загружает модули, не открывает сокеты, не отправляет пакеты и не изучает клиентский трафик. Исследования IPv6 SOCKS/direct/block, Hysteria 2, FakeIP и VLESS в этот отчёт не входят.

До отдельного сообщения координатора о прохождении организационного gate работа с роутером не разрешена. Подготовительный этап выполнен локально; фактические запросы к устройству не выполнялись. Выделенных файлов, процессов, интерфейсов, сокетов и портов нет. Метка свидетельств: `codex-kn1012-netfilter-ro-20261106`.

## Среда и подготовка

- Целевое устройство по существующему протоколу: Keenetic Giga KN-1012; ранее полученная версия KeeneticOS 5.2 Beta 3 (`5.02.B.3.0-2`), архитектура `aarch64`. Эта версия взята из предыдущего read-only отчёта и не перепроверялась в рамках текущей задачи.
- Рабочее дерево: `/private/tmp/hestia-kn1012-rci-readonly`, ветка `codex/keenetic-kn1012-rci-readonly`.
- Пinned SSH host-key fingerprint из существующего свидетельства: `SHA256:u5mFSUOHtvmfjURyMmAe8N2BVONvSiTAoV7OLn2Czoo`. Он должен быть перепроверен в `known_hosts` при открытии gate; несовпадение завершает работу без соединения.
- Из предыдущего протокола известны SSH-параметры, однако их использование в новом исследовании требует открытого gate. Не использовать выделенные для другого исследования пути, процессы, порты или ресурсы.

## План наблюдений

После подтверждения gate выполнить только запросы из [плана прототипа](prototype/README.md). Для каждого вызванного бинарного файла сначала записать его путь и SHA-256 существующего файла, затем сверить ключ до запуска. Сохранять только отфильтрованные имена TPROXY/socket, версию ядра, необходимые сведения об утилитах и точные результаты/коды завершения. Не сохранять полные таблицы, сетевые адреса или несвязанные имена модулей. Неуспешные попытки сохранять как свидетельства.

## Ожидаемый и фактический результат

Ожидалось подготовить безопасный перечень источников, по которым можно определить наличие уже загруженных или встроенных TPROXY/socket компонентов и поддержку синтаксиса существующими iptables-утилитами, не меняя состояние устройства.

На момент подготовки плана фактических данных о ядре, модулях или утилитах нет: роутер не опрашивался. Поэтому поддержка TPROXY и socket match на текущей прошивке остаётся неподтверждённой. После разрешённых запросов вывод должен разделять: (1) наличие загруженной цели/модуля; (2) наличие компонента среди метаданных модулей или встроенных компонентов; (3) наличие соответствующего расширения в справке установленной утилиты. Эти признаки не равнозначны проверке фактического перехвата пакетов, которая вне границ этого исследования.

## Ошибки и ограничения

Пока сбоев запросов к устройству нет: запросы не выполнялись. Ошибка проверки host key, невозможность безопасно удостоверить исполняемый файл, отсутствие файла/утилиты или отказ чтения фиксируются в отчёте и завершают соответствующую ветвь без альтернативных проб. Нельзя создавать, добавлять, удалять или менять Netfilter-правила, вызывать загрузчик модулей, создавать сокеты, посылать трафик, смотреть клиентские данные или обращаться к другому стенду.

## Свидетельства и воспроизведение

- Предварительный перечень безопасных запросов: [prototype/README.md](prototype/README.md).
- Свидетельства фактических запросов будут размещены в `evidence/`; до открытия gate их нет. См. [README каталога свидетельств](evidence/README.md).
- Локальное архитектурное основание и объяснение выбора TPROXY находится в [исследовании платформы Keenetic](../../docs/keenetic-platform.md#что-применимо-к-гестии); оно не подтверждает наличие нужных компонентов на KN-1012.

Воспроизводить можно только после открытия gate координатором и с соблюдением предварительных проверок host key и SHA-256. Команды и условия остановки перечислены в прототипе.
