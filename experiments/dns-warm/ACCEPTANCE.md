# Критерии эксперимента с прогревом

[Требование к N, X и Y](../../docs/requirements.md) уже описывает, когда имя должно участвовать в прогреве. На стенде короткие интервалы позволяют наблюдать порог, обновление и прекращение запросов в одном прогоне.

| Случай | Наблюдаемый результат |
|---|---|
| Имя набрало N клиентских запросов в окне X | После смены A на стороне сервера и до истечения исходного TTL в захвате виден внешний запрос без нового клиентского запроса. Следующее обращение использует обновлённый ответ. |
| Имя ниже порога N | Клиент может получить ответ обычным путём. В паузах нет фоновых DNS-запросов к этому имени, в том числе после истечения TTL. |
| Клиент перестал запрашивать частое имя | Когда в скользящем окне осталось меньше N клиентских запросов, внешние фоновые запросы прекращаются. Контрольная пауза охватывает несколько интервалов Y. |
| После паузы клиент вернулся один раз | Это одно новое посещение. Оно не возобновляет прогрев до повторного достижения порога N. |
| Явная маска разрешает только группу FI | Прогрев обращается к разрешённому резолверу через FI. На выходе RU нет запросов к этому имени. |

Число клиентских запросов подтверждается захватом LAN. Попытки обновления и выбор резолвера сверяются с захватами на выходах и журналом тестового DNS-сервера. Отдельно фиксируем, какой реальный адрес обслужил новое клиентское соединение. Серия без прогрева показывает, что один только спрос клиента не мог дать наблюдаемого обновления заранее.
