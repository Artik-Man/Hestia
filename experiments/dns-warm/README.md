# Прогрев DNS для часто используемых имён на ARM64

На отдельной Debian ARM64 сравнили обычное обновление по спросу и прогрев. Порог — три пользовательских DNS-обращения за восемь секунд, интервал фонового обновления — одна секунда. TTL авторитетных A-записей — четыре секунды. Интервалы сокращены для опыта. Все сети и сервисы работают внутри одноразовой ВМ.

Клиент сделал три настоящих DNS-запроса к каждому из двух горячих имён и один к редкому. К редкому имени он затем открыл четыре новых TCP/UDP-потока через уже известный FakeIP. После начала опыта оба DNS-сервера начали выдавать `203.0.113.22` вместо `203.0.113.11`. После исходного срока TTL клиент ещё по разу запросил горячие имена и открыл четыре дополнительных TCP/UDP-потока к новым адресам. В обеих сериях метки запросов и пользовательских пакетов сверили с LAN- и WAN-захватами, а полученный адрес — с журналом удалённого сервера.

Обычный кэш дошёл до нового ответа по спросу клиента. В режиме прогрева новый A был получен заранее, ещё до окончания предыдущего TTL. Запросы клиента после первоначального TTL попали в действующий кэш без внешней DNS-попытки в интервале ответа. TCP и UDP к горячим именам действительно достигли нового адреса через FI. На редкое имя пришёлся только один обычный внешний запрос через каждый разрешённый резолвер. [Серия без прогрева](evidence/demand/verification.txt), [серия с прогревом](evidence/warm/verification.txt).

Для неограниченного горячего имени проверены внешний RU-резолвер через RU и внешний FI-резолвер через FI, для явной финской маски проверен только FI. Оба резолвера в этом сценарии возвращали одинаковую A-запись данного поколения. Захваты измеряют принадлежность каждого запроса к резолверу и интерфейсу. Срок жизни обновлённого ответа задаётся TTL DNS-сервера. [Настройки и ограничения](CACHE.md).

Чтобы повторить испытания, перенесите каталоги `experiments/dns-warm`, `experiments/dns-rotation` и `experiments/dns-geo` на одноразовую Debian ARM64 с sing-box 1.14.4, TUN, iproute2, tcpdump, Python 3 и python3-dnspython и выполните в гостевой системе:

```sh
sudo bash experiments/dns-warm/lab.sh demand /var/tmp/demand-only
sudo bash experiments/dns-warm/lab.sh warm /var/tmp/prewarm
```

Каталоги результатов должны быть пустыми. Для повторной проверки сохранённых пакетов выполните `python3 experiments/dns-warm/verify.py warm experiments/dns-warm/evidence/warm` в Linux с tcpdump. Это экспериментальный Python-компонент для IPv4 IN/A. В опыте нет браузера, измерений задержки открытия страниц или производственных DNS-узлов.
