# Сохранение списка на stage1

4 ноября 2026 года проверили, сохраняет ли редактор новый список после перезагрузки страницы и продолжает ли работать тот же процесс AWG. При предыдущей попытке шлюз перезапустил AWG, не дождался подтверждения туннеля и откатил изменения. На время транзакции чтение снимка отвечало 503.

После исправления Playwright открыл панель в Chromium, создал список с маской `*.e2e.invalid` без группы, получил ожидаемый HTTP 201 и проверил строку после перезагрузки. Снимок API подтвердил ID, название, маску и отключённое состояние. PID и InvocationID службы AWG совпали до и после записи. Передачу трафика через привязанный список этот прогон не проверял. Версия установленного обработчика, результат теста и идентификаторы процесса приведены в [протоколе](evidence/stage1.txt).

Во втором прогоне Playwright проверил карандаш и корзину. Переименование вернуло HTTP 200 и сохранило ID, отмена оставила список доступным после перезагрузки, а подтверждение вернуло HTTP 204. После повторной загрузки записи уже не было в таблице и снимке API. До и после теста на стенде оставались две группы и два списка, идентификатор запуска AWG сохранился. [Протокол действий](evidence/row-actions.txt).

Для повторения на разрешённом stage1 выполните из каталога фронтенда `HESTIA_E2E_URL=http://192.168.1.133:8080 npm run test:e2e:domain-list`. Каждый запуск создаёт отдельный список без группы и удаляет его после проверки.
