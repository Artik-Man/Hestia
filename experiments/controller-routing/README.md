# Go-контроллер применяет решение на работающем шлюзе

На Debian ARM64 с ядром `6.1.0-53-cloud-arm64` исполняемый файл Гестии, собранный из `cmd/hestia`, выбирал выход по конфигурации и доступности подключений. Оба селектора sing-box запускались в состоянии `deny`. Только проверяемая Go-команда изменяла их через локальный API. Сценарий отдельно читал выбранный выход и проверял фактическую доставку по захватам.

| Доступность и решение | Результат в сети |
|---|---|
| Оба выхода доступны. Финская маска выбирает FI-1, для российского домена действует группа по умолчанию. | Новые TCP и UDP достигают FI-1 или RU соответственно. |
| FI-1 отключён. Go выбирает FI-2. Затем подан ошибочный снимок со ссылкой на неизвестную группу. | Команда отклонила снимок. Прежний выбор FI-2 сохранился. Оба протокола прошли через FI-2 по ранее полученному FakeIP. |
| Оба выхода отключены. Go сообщает `block_no_available_exit` и применяет `deny`. | Попытки к старому FakeIP видны на LAN, на трёх выходах отсутствуют пакеты сервиса и DNS-запросы нового финского имени. Российский контроль проходит. |
| Оба физических выхода восстановлены при том же решении `deny`. | Ни TCP, ни UDP, ни внешний DNS для финского имени не появляются на выходах. |
| Доступность FI-2 подтверждена и отправлена в новом снимке. | Новые потоки снова получают ответы через FI-2 по первоначальному клиентскому адресу. |

Проверено 24 новые попытки TCP и UDP в шести фазах. Для исходного финского имени клиент запросил DNS ровно один раз. Имена для проверки внешнего DNS уникальны. Положительная проба подтверждает, что наблюдаемый резолвер ответил через FI-1. Для фаз запрета проверены пакеты, включая попытки TCP до отправки полезных данных. ## Границы

Go-команда применяет выбор для группы по запросу оператора. Стенд заранее настраивает в sing-box доменные маршруты, теги выходов, резолверы и привязки интерфейсов. В Linux стенд создаёт изолированный запрещающий выход и таблицу маршрутов. Наблюдаемый запрет достигается совместной работой этих компонентов. Изменение выводов доступности, обновление масок в работающем sing-box, полный жизненный цикл защиты Linux и журнал фактического выхода каждого потока остаются отдельными задачами. Проверено локальное исходящее IPv4-соединение sing-box после приёма трафика клиента в TUN.

## Воспроизведение

Подготовить изолированную Debian ARM64-ВМ, установить sing-box и инструменты по [инструкции базового стенда](../fakeip/README.md). На хосте с Go из корня проекта собрать исполняемый файл:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o /tmp/hestia ./cmd/hestia
```

Перенести в ВМ исполняемый файл и каталоги `experiments/controller-routing`, `experiments/failover`, `experiments/fakeip` с сохранением взаимного расположения. Из корня копии проекта в гостевой ВМ:

```sh
out=$(mktemp -d)
sudo bash experiments/controller-routing/lab.sh /tmp/hestia "$out"
sudo cat "$out/verification.txt"
```

Для проверки опубликованного архива достаточно Python 3 и tcpdump:

```sh
python3 -B experiments/controller-routing/verify.py experiments/controller-routing/evidence
```
