# Два домена на одном IP через разные выходы

Эксперимент от 4 ноября 2026 года. Проверяем, сохраняет ли sing-box 1.14.4 соответствие между доменом и подключением при одинаковом реальном IPv4 **и порте** назначения. Для каждого из двух доменов клиент делает обычный DNS-запрос типа A, затем открывает TCP-соединение и отправляет UDP-датаграмму. Четыре пробы запускаются конкурентно. Приложению доступны только выданные ему виртуальные адреса. Политика в этом опыте — фиксированный выход для каждой группы.

## Топология

Сценарий создаёт три временных network namespace в Linux-ВМ: клиент, Гестия и сервер. У Гестии два выхода, `ru0` и `fi0`, соединённые двумя отдельными парами veth с одним сервером. Внутренний тестовый DNS sing-box содержит два имени с одной записью A. Один сервер слушает TCP и UDP на `203.0.113.77:19091`.

DNS клиента перехватывается действием `hijack-dns` на входе TUN. FakeIP возвращает адрес из диапазона `198.18.0.0/15`. При обработке пакета к FakeIP правило по доменному имени направляет соединение через соответствующий direct outbound с `bind_interface`. Таблицы маршрутизации по выходному интерфейсу ведут к одному общему серверу. У namespace Гестии намеренно нет общего маршрута по умолчанию: сообщение `missing default interface` в диагностике ожидаемо для этой топологии.

## Что получилось

| Домен | FakeIP | Реальный адрес | Фактический выход | Ответил сервер |
|---|---|---|---|---|
| `ru.lab.test` | `198.18.0.2` | `203.0.113.77:19091` | `ru0`, источник `10.88.1.1` | TCP и UDP |
| `fi.lab.test` | `198.18.0.3` | `203.0.113.77:19091` | `fi0`, источник `10.88.2.1` | TCP и UDP |

У каждой пробы уникальный маркер. Сервер сообщает клиенту реальный адрес источника и полученный маркер; клиент проверяет их. Проверка захватов отдельно подтверждает, что маркер запроса присутствует на правильном выходе и отсутствует на другом. Это подтверждает разделение потоков в прозрачном режиме для IPv4, без изменения приложений. Эксперимент не измеряет скорость, не поднимает внешний SSTP и не проверяет GeoIP, конкуренцию внешних резолверов или переключение при отказе.

## Повторный запуск

Нужна Linux-ВМ с root, `/dev/net/tun`, network namespaces и veth, а также bash, iproute2, sysctl, tcpdump и Python 3. Установить [sing-box 1.14.4](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4) для архитектуры гостя. Запустить из этого каталога в ВМ:

```sh
sudo env SING_BOX="$(command -v sing-box)" bash lab.sh "$(mktemp -d)"
```

Сценарий выводит каталог результатов; он должен быть пустым при запуске. После завершения тестовые namespaces удаляются. PCAP, расшифровка пакетов, ответы клиента и сервера и журнал sing-box остаются для независимой проверки. Интернет после установки инструментов не требуется.

Собственный модуль ядра не используется. Процесс sing-box работает в userspace; туннельный интерфейс, veth, network namespaces, системные сокеты и policy routing предоставляет ядро Linux. У [официального образа ROCK 5T](https://docs.radxa.com/en/rock5/rock5t/download) своя сборка Debian Bookworm с ядром 6.1. На плате нужно проверить наличие тех же возможностей ядра и реальные Ethernet-интерфейсы.
