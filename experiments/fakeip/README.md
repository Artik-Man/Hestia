# Два домена на одном IP через разные выходы

Исходники проверки: [tests/lab/fakeip](../../tests/lab/fakeip/). Отчёт и свидетельства остаются здесь. Перед повторным запуском применяйте [правила выбора стенда](../../agents/virtual-machines.md); исторические имена ВМ не являются указанием создать или запустить их.

Имена ВМ в описании приведены к принятой 6 ноября 2026 года схеме [prod/dev/client](../../AGENTS.md#виртуальные-машины). Исходные имена в свидетельствах и путях резервных копий сохранены.

Эксперимент от 4 ноября 2026 года. Проверяем, сохраняет ли sing-box 1.14.4 соответствие между доменом и подключением при одинаковом реальном IPv4 **и порте** назначения. Для каждого из двух доменов клиент делает обычный DNS-запрос типа A, затем открывает TCP-соединение и отправляет UDP-датаграмму. Четыре пробы запускаются конкурентно. Приложению доступны только выданные ему виртуальные адреса. Политика в этом опыте — фиксированный выход для каждой группы.

## Топология

Сценарий создаёт три временных network namespace в Linux-ВМ: клиент, Гестия и сервер. У Гестии два выхода, `ru0` и `fi0`, соединённые двумя отдельными парами veth с одним сервером. Внутренний тестовый DNS sing-box содержит два имени с одной записью A. Один сервер слушает TCP и UDP на `203.0.113.77:19091`.

DNS клиента перехватывается действием `hijack-dns` на входе TUN. FakeIP возвращает адрес из диапазона `198.18.0.0/15`. При обработке пакета к FakeIP правило по доменному имени направляет соединение через соответствующий direct outbound с `bind_interface`. Таблицы маршрутизации по выходному интерфейсу ведут к одному общему серверу. У namespace Гестии намеренно нет общего маршрута по умолчанию: сообщение `missing default interface` в диагностике ожидаемо для этой топологии.

## Что получилось

| Домен | FakeIP | Реальный адрес | Фактический выход | Ответил сервер |
|---|---|---|---|---|
| `ru.lab.test` | `198.18.0.2` | `203.0.113.77:19091` | `ru0`, источник `10.88.1.1` | TCP и UDP |
| `fi.lab.test` | `198.18.0.3` | `203.0.113.77:19091` | `fi0`, источник `10.88.2.1` | TCP и UDP |

У каждой пробы уникальный маркер. Сервер сообщает клиенту реальный адрес источника и полученный маркер; клиент проверяет их. Проверка захватов отдельно подтверждает, что маркер запроса присутствует на правильном выходе и отсутствует на другом. Это подтверждает разделение потоков в прозрачном режиме для IPv4, без изменения приложений. Эксперимент не измеряет скорость, не поднимает внешний SSTP и не проверяет GeoIP, конкуренцию внешних резолверов или переключение при отказе.

## Повторный запуск

Нужна Linux-ВМ с root, `/dev/net/tun`, network namespaces и veth, а также bash, iproute2, sysctl, tcpdump и Python 3. Установить [sing-box 1.14.4](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4) для архитектуры гостя. Запустить из каталога `tests/lab/fakeip` в ВМ:

```sh
sudo env SING_BOX="$(command -v sing-box)" bash lab.sh "$(mktemp -d)"
```

Сценарий выводит каталог результатов; он должен быть пустым при запуске. После завершения тестовые namespaces удаляются. PCAP, расшифровка пакетов, ответы клиента и сервера и журнал sing-box остаются для независимой проверки. Интернет после установки инструментов не требуется.

Собственный модуль ядра не используется. Процесс sing-box работает в userspace; туннельный интерфейс, veth, network namespaces, системные сокеты и policy routing предоставляет ядро Linux. У [официального образа ROCK 5T](https://docs.radxa.com/en/rock5/rock5t/download) своя сборка Debian Bookworm с ядром 6.1. На плате нужно проверить наличие тех же возможностей ядра и реальные Ethernet-интерфейсы.

## Историческая подготовка на macOS с Apple Silicon

Приведённые ниже команды относятся к [старому комплекту подготовки](../README.md#историческая-подготовка-вм), который теперь извлекается из Git в отдельный каталог. Они сохранены для понимания прежнего опыта. Сначала извлеките комплект по указанной инструкции; управление питанием и подготовку ВМ отдельно согласуйте по действующим правилам.

Конфигурация Lima фиксирует Debian 12 ARM64 и SHA-512 образа. Для запуска нужны Lima (проверено на 2.2.1), 2 ГиБ RAM, место для виртуального диска до 7 ГиБ и доступ к источникам Debian и GitHub. У гостя собственный диск, каталоги хоста не монтируются. Версии дополнительных пакетов выбирает репозиторий Debian на момент подготовки.

Из каталога `$archive_dir/experiments/fakeip` извлечённого комплекта на хосте используйте существующую ВМ разработки `hestia-dev` с `LIMA_HOME="$HOME/.lima"`. Архив sing-box проверяется по закреплённому SHA-256 внутри гостя перед установкой. Команды ниже проверяют повторное применение подготовки; воспроизведение исходной проверки на чистом образе требует отдельно согласованного пересоздания dev-стенда или временной ВМ.

```sh
export LIMA_HOME="$HOME/.lima"
export PATH="/private/tmp/hestia-vm-run/bin:$PATH"
vm=hestia-dev
archive_dir=$(mktemp -d)
curl --fail --location --output "$archive_dir/sing-box.tgz" \
  https://github.com/SagerNet/sing-box/releases/download/v1.14.4/sing-box-1.14.4-linux-arm64.tar.gz
limactl start --tty=false "$vm"
limactl copy config.json lab.sh traffic.py vm/provision.sh "$archive_dir/sing-box.tgz" "$vm:/tmp/"
```

Дважды примените подготовку и после каждого применения запустите тест. Команда сравнивает список версий установленных пакетов и атрибуты бинарного файла sing-box между прогонами. Для очередного запуска создаётся новый каталог результатов.

```sh
limactl shell --workdir=/tmp "$vm" -- bash -c '
  set -euo pipefail
  work=$(mktemp -d)
  for pass in 1 2; do
    sudo bash provision.sh sing-box.tgz
    dpkg-query -W | sha256sum > "$work/packages-$pass"
    stat -c "%a %Y %i" /usr/local/bin/sing-box > "$work/binary-$pass"
    sudo bash lab.sh "$work/pass-$pass"
    test -z "$(sudo ip netns list)"
  done
  cmp "$work/packages-1" "$work/packages-2"
  cmp "$work/binary-1" "$work/binary-2"
'
limactl stop "$vm"
```

4 ноября 2026 года на новой Debian 12.15 с ядром `6.1.0-53-cloud-arm64` оба прогона подтвердили четыре маршрута по TCP и UDP. Повторная подготовка сохранила состав пакетов, inode, режим и время модификации sing-box. После каждого теста гостевой список сетевых пространств был пуст.
