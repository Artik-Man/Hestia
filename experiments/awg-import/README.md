# Импорт профиля AmneziaWG через панель

4 ноября 2026 года проверяли загрузку и удаление файла `private/hestia_amnezia_for_awg.conf` через Chromium на персональной Debian ARM64 ВМ `hestia-stage1`. Для прогона владелец разрешил работу с панелью на порту 8080, диагностику и обновление Гестии. Проверяемая версия — рабочее дерево на основе `44bb04d`.

До исправлений выбранный файл исчезал при обновлении данных формы. Прямая проверка файла через API возвращала HTTP 503. После создания закрытого каталога управляющих сокетов и выдачи службам доступа к нему шлюз подтвердил handshake. На следующем шаге создание выхода вернуло HTTP 422: компилятор отклонил лишнее поле в записи существующего выхода типа `direct`. Регрессионная проверка с настоящим компилятором также выявила потерю обязательного пустого массива при удалении последнего профиля.

Тест выбирает существующую группу, ставит выход с уникальным ID последним, проверяет сохранение после повторного открытия страницы, удаляет только свой выход и снова открывает страницу. Для повторения из каталога `frontend` на разрешённом стенде выполните:

```sh
HESTIA_E2E_URL=http://192.168.1.133:8080 npm run test:e2e
```

По умолчанию тест берёт файл из каталога `private`. Нужны установленный Chromium для Playwright либо путь к Chrome в `CHROME_BIN`. [Наблюдения прогона](evidence/stage1-20261104.txt)

После исправления компилятора файл сохранился. При первом удалении runtime отказался очищать маршрут с атрибутом `scope link`. После исправления проверка распознала маршрут Гестии, удаление вернуло HTTP 204. В итоговом сквозном прогоне все шаги через панель прошли за 8,66 секунды. Тестовый выход удалён. Опыт подтверждает жизненный цикл профиля на этой ВМ; скорость, длительная устойчивость соединения и физическая плата в этот прогон не входили.

### Редактор на stage1, 5 ноября 2026

Ожидали сохранить рабочий туннель и открыть его параметры после обновления. Проверка служб и браузер подтвердили оба результата. Для повторения открыть «Подключения», выбрать «Добавить» → WireGuard, отменить, открыть редактирование awg-home, проверить заполненное поле PrivateKey и отменить. Запись и удаление проверяли на синтетическом профиле локально. [Свидетельство](evidence/stage1-editor-20261105.txt).

Редактор awg-home открыт и закрыт без записи, полей изменения места в группе нет. После установки четыре службы активны, smoke-проверка успешна, awg-home в состоянии ready.
