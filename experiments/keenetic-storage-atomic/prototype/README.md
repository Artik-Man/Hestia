# Протокол ограниченной проверки замены файла

Прототип `replace-and-cleanup.sh` предназначен для одного запуска на KN-1012 только после сообщения координатора об открытии gate. Не запускать его на локальном компьютере для имитации свойств целевого устройства.

Сценарий проверяет точное фиксированное имя приватного каталога и прекращает работу, если оно уже существует. Он не выполняет рекурсивное удаление. Внутри тестирует замену маленького файла временным файлом из того же каталога; временный файл закрывается до `mv`. Вспомогательный reader выполняет ограниченное число чтений и принимает только два целых синтетических маркера. Сценарий не создаёт сеть и не вызывает системные механизмы Keenetic.

## Подготовка перед удалённым выполнением

1. Получить от координатора явное подтверждение, что Product Owner получил сведения об этой выделенной области ресурсов и gate открыт.
2. Проверить закреплённый SSH host key отдельной командой; использовать только ранее согласованный SSH endpoint/учётную запись и `StrictHostKeyChecking=yes`.
3. Зафиксировать локальный commit, SHA-256 сценария и точную команду отправки/исполнения. Проверить отсутствие точного каталога `/opt/tmp/codex-kn1012-atomic-20261106/` до его создания. При наличии остановиться без чтения или удаления содержимого.
4. Сверить SHA-256 удалённого сценария с локальным перед запуском. Записать UTC-время, stdout, stderr и exit code каждой команды. Не делать повторный запуск после любой ошибки без передачи факта координатору.
5. После успешной пробы сохранить конечные хеш и режим marker-файла, проверить завершение reader, удалить только известные файлы этой пробы и выполнить `rmdir` точного приватного каталога. Проверить отсутствие каталога. Если `rmdir` не проходит, остановиться и не удалять неизвестные записи.

Каждая удалённая попытка документируется, включая отказ host-key verification, передачу, выполнение, проверку и очистку. Исполняемый хеш и хеш исходного сценария указываются в отчёте вместе с режимами файлов. Команду удаления нельзя расширять wildcard-путями или `rm -rf`.
