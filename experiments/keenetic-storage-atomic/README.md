# Атомарная замена и очистка временного файла на KN-1012

## Вопрос

Поддерживает ли проверенная конфигурация Keenetic Giga KN-1012 ограниченную атомарную замену обычного синтетического файла внутри одного каталога `/opt/tmp` с сохранением целостного содержимого и последующей очисткой только принадлежащего опыту каталога?

## Границы и критерии

Опыт ограничен одним закрытым каталогом `/opt/tmp/codex-kn1012-atomic-20261106/` и короткоживущим процессом с меткой `codex-kn1012-atomic-20261106`. Используются только синтетические строки-маркеры. Не читаются и не изменяются существующие данные, секреты, настройки или файлы приложений. Не создаются порты, слушатели, интерфейсы и сокеты. Не выполняются команды изменения маршрутов, правил, firewall, DNS, sysctl, VPN, служб или постоянной конфигурации; пакеты не устанавливаются, устройство не перезапускается.

До открытия окна доступа выполняется только локальная подготовка отчёта и прототипа. После открытия gate перед созданием точного удалённого каталога проверяется его отсутствие; если он уже существует, опыт прекращается. Каталог создаётся с правами только владельцу. Внутри создаётся маленький marker-файл и файл в том же каталоге, который заменяет marker операцией `mv` (rename). Ограниченный reader проверяет, что видит только два целых ожидаемых значения; записываются хеши, режимы и коды возврата. Затем удаляются только файлы и каталог этого опыта, после чего проверяется отсутствие каталога.

Критерии успешной пробы:

1. Проверенный SSH host key совпадает с закреплённым ключом.
2. SHA-256 исходного shell-сценария совпадает с локальным хешем до его исполнения.
3. Точный целевой каталог отсутствовал до создания и имел режим `700`.
4. Источник и временная замена расположены в одном каталоге; после `mv` конечный файл содержит целиком одно из заданных маркерных значений и имеет ожидаемый режим `600`.
5. Ограниченное число чтений не обнаруживает частичного или неожиданного содержимого; каждый шаг завершается в заданных границах.
6. После очистки отсутствует только каталог опыта; удаление иных объектов не производится.

Проверка конечных значений не является доказательством гарантии атомарности при сбое питания, устойчивости данных на носителе, поведения другого типа файловой системы или любых режимов конкурентной записи. Сбои питания и перезагрузки не испытываются.

## Среда и версия

- Устройство: Keenetic Giga KN-1012; перед прогоном заново сверить модель/прошивку с уже имеющимися подтверждёнными материалами и зафиксировать фактически прочитанные сведения.
- Доступ: SSH Entware с обязательным `StrictHostKeyChecking=yes` и закреплённым ключом; никаких подключений до открытия gate координатором.
- Каталог и метка процесса: `/opt/tmp/codex-kn1012-atomic-20261106/`, `codex-kn1012-atomic-20261106`.
- Прототип `prototype/codex-kn1012-atomic-20261106.sh`, SHA-256 `854d322e057a29055cb82c5d1c9f506d6e2ad4b33d87f917b21632e05a74d2ae`; синтаксис проверен командой `sh -n`, сам сценарий не запускался.
- Локальная ревизия и журнал удалённых команд: будут заполнены только после открытия gate и фактического аппаратного прогона.
- Текущий статус: подготовка; аппаратный прогон не начат, результат не заявляется.

## Протокол и свидетельства

Ограниченный прототип и порядок его проверки описаны в [инструкции прототипа](prototype/README.md). Каталог `evidence/` будет содержать точные команды, временные метки UTC, хеши, stdout, stderr и коды возврата всех попыток, включая неуспешные. Неудачные свидетельства сохраняются.

Локальная подготовка и проверка синтаксиса без исполнения записаны в [свидетельстве](evidence/local-preparation.txt). Это не является испытанием файловой системы роутера.

## Результат

Неизвестен до разрешённого аппаратного прогона. Не выводить поведение `/opt` на KN-1012 только из локальных проверок или общих свойств POSIX `rename`.
