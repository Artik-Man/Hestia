# Проверка создания и удаления TUN на KN-1012

Инструмент `probe.go` выполняет одну короткую пробу: проверяет отсутствие выбранного имени, открывает `/dev/net/tun`, запрашивает `IFF_TUN | IFF_NO_PI | IFF_TUN_EXCL`, проверяет появление интерфейса, закрывает собственный дескриптор и проверяет исчезновение интерфейса. `IFF_TUN_EXCL` не позволяет подключить дескриптор к уже существующему TUN с таким именем; предварительная проверка даёт читаемый отказ при коллизии.

Команда завершает пробу не позднее чем через 10 секунд. При истечении срока helper завершает процесс; ядро закрывает его файловые дескрипторы, удаляя созданный непостоянный интерфейс. Обычные ошибки проходят через `defer`, который закрывает принадлежащий fd и проверяет исчезновение интерфейса. Команда не задаёт адрес, не поднимает интерфейс, не меняет маршруты, правила, firewall, модули, sysctl или постоянную конфигурацию. Интерфейс не помечается persistent. Проба не генерирует трафик и не подтверждает VPN или пересылку пакетов.

## Сборка на Mac

Из корня репозитория, используя локальный Go 1.26+:

```sh
gofmt -w experiments/keenetic-tun/prototype/probe.go
GO111MODULE=off go vet experiments/keenetic-tun/prototype/probe.go
GOTOOLCHAIN=local GOPROXY=off GO111MODULE=off GOOS=linux GOARCH=arm64 CGO_ENABLED=0 \
  go build -trimpath -ldflags='-s -w -buildid=' -o /private/tmp/hestia-tun-probe experiments/keenetic-tun/prototype/probe.go
file /private/tmp/hestia-tun-probe
shasum -a 256 /private/tmp/hestia-tun-probe
```

Ожидается статический ELF Linux/AArch64. Перед отправкой сверяйте локальный SHA-256 с записью текущего прогона. Не используйте уже занятый каталог назначения.

## Одноразовый прогон

Владелец разрешил аппаратную пробу на Keenetic Giga KN-1012 через SSH Entware `root@192.168.1.1:222`. Проверяйте ключ узла; используйте настроенный SSH-ключ и `StrictHostKeyChecking=yes`. Если другие участники меняют маршруты или интерфейсы, сначала согласуйте короткое окно; параллельные read-only операции можно отметить в отчёте. До и после запуска получите SHA-256 одинаковых снимков всех IPv4/IPv6 routes и rules. На BusyBox `ip` проверенная команда снимка — `ip route list table all`, `ip -f inet6 route list table all`, `ip -f inet rule list`, `ip -f inet6 rule list`. Сохраняйте только хеши и количество записей, не содержимое таблиц.

Создайте уникальное короткое имя интерфейса вида `htun<8-значный-суффикс>` (до 15 символов) и отдельный каталог вида `/opt/tmp/hestia-tun-<случайный-суффикс>` с правом чтения/записи только владельцу. Сначала проверьте имя через `ip link show dev <имя>`: если оно существует, выберите другое и не запускайте probe. Перед выполнением сравните удалённый SHA-256 файла с локальным. Например, для новой пары `htun1234abcd` и `/opt/tmp/hestia-tun-a1b2c3`:

```sh
ssh -p 222 -i "$HOME/.ssh/hestia_keenetic" -o BatchMode=yes -o IdentitiesOnly=yes \
  -o StrictHostKeyChecking=yes root@192.168.1.1 \
  'umask 077; test ! -e /opt/tmp/hestia-tun-a1b2c3 && mkdir -m 700 /opt/tmp/hestia-tun-a1b2c3'
scp -O -P 222 -i "$HOME/.ssh/hestia_keenetic" -o BatchMode=yes -o IdentitiesOnly=yes \
  -o StrictHostKeyChecking=yes /private/tmp/hestia-tun-probe root@192.168.1.1:/opt/tmp/hestia-tun-a1b2c3/probe
ssh -p 222 -i "$HOME/.ssh/hestia_keenetic" -o BatchMode=yes -o IdentitiesOnly=yes \
  -o StrictHostKeyChecking=yes root@192.168.1.1 \
  'sha256sum /opt/tmp/hestia-tun-a1b2c3/probe; ip link show dev htun1234abcd'
```

Если `ip link show` обнаружил имя, остановитесь, выберите новое имя и подтвердите его отсутствие. Выполните ровно один запуск и сохраните JSON stdout, stderr и код возврата. До запуска запишите маршруты/правила во временные файлы внутри своего закрытого каталога, выведите их `sha256sum` и число строк; после завершения повторите те же четыре команды и сравните снимки побайтно командой `cmp`. Выполните `./probe htun1234abcd`; helper сам завершает процесс через 10 секунд, если проба зависла. В evidence запишите результат интерфейса сразу после TUNSETIFF и после закрытия.

Для очистки удалите только собственный временный каталог после проверки, что процесс probe завершился и интерфейс исчез. Не удаляйте интерфейс вручную, если он остался: остановитесь и передайте точный факт оператору, чтобы не затронуть чужой объект. Если хеш любого route/rule снимка изменился или снимки разных этапов не совпали, не приписывайте изменение пробе; результат по инвариантности состояния считайте неопределённым.
