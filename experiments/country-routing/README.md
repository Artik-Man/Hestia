# Приоритет страны назначения и доменной маски

Исходники проверки: [tests/lab/country-routing](../../tests/lab/country-routing/). Отчёт и свидетельства остаются здесь. Перед повторным запуском применяйте [правила выбора стенда](../../agents/virtual-machines.md); исторические имена ВМ не являются указанием создать или запустить их.

Имена ВМ в описании приведены к принятой 6 ноября 2026 года схеме [prod/dev/client](../../AGENTS.md#виртуальные-машины). Исходные имена в свидетельствах и путях резервных копий сохранены.

5 ноября 2026 года на выделенной ВМ Lima `hestia-dev` проверили, применяет ли sing-box к *новым* соединениям базовую страну IP, уточнение для отдельного адреса и явную доменную маску. Использовали рабочее дерево на основе `dac27d6`, Linux ARM64, sing-box 1.14.4 и временное сетевое пространство только с loopback. [Версии, контрольные суммы и результат](evidence/arm64.txt).

Клиент открывал новые соединения SOCKS5 по IPv4 до локального HTTP-сервера. К его входу применили тот же порядок правил, который компилятор строит для помеченного клиентского TUN. Одна группа выпускала поток на сервер, другая направляла его в закрытый порт. Для проверяемого адреса в тестовом наборе DB-IP указали RU, в группе RU разрешили выход. Включили все 249 файлов уточнений. Для проверки маршрута требовалось получить маркер от HTTP-сервера.

| Условие | Ожидание | Наблюдение |
|---|---|---|
| Реальному IP назначена RU, маска отсутствует | Получить маркер | Получен |
| Без перезапуска атомарно заменили уточнение FI для того же IP | Следующий поток через группу FI перестал получать маркер | Обновление подхватилось, поток заблокирован закрытым портом |
| Запросили тот же IP с HTTP Host, подходящим под явную маску для RU | Явное правило доставляет поток | Маркер снова получен |

В macOS пробный прогон упёрся в число открытых файлов при одновременном наблюдении каталога через kqueue. Для проверки эксплуатационного поведения использовали целевую Linux-платформу. На ВМ для опыта повысили лимит экземпляров inotify со 128 до 1024 и восстановили его после проверки. Опыт проверил исходящие TCP-соединения, распознавание HTTP Host и горячее чтение уточнений. Физический выход на провод, пользовательский TLS-сеанс VK, сопоставление адреса внешним сервисом и достоверность сведений провайдера имеют собственные условия проверки.

Для воспроизведения перенесите на отдельную Linux ARM64-ВМ `deploy/profile.py`, `backend/internal/geoip/countries.txt` и скрипт опыта, сохранив структуру каталогов. Положите sing-box 1.14.4 для Linux ARM64 рядом с корнем этого дерева. Запустите из корня:

```bash
old=$(sysctl -n fs.inotify.max_user_instances)
trap 'sudo sysctl -qw "fs.inotify.max_user_instances=$old"' EXIT
if ((old < 1024)); then sudo sysctl -qw fs.inotify.max_user_instances=1024; fi
sudo unshare --net --pid --fork --mount-proc sh -ec \
  'ip link set lo up; python3 -B tests/lab/country-routing/verify.py "$PWD/sing-box"'
```

## Сохранение карты стран на KN-1012 — 10 ноября 2026 года

Запрос сохранения карты стран не проходил, потому что на Keenetic отсутствовали каталог GeoIP с базой и country overrides; после добавления этих файлов исходные JSON-наборы правил исчерпывали память sing-box при проверке кандидата. Исправление собирает GeoIP в пакет и использует для базовых стран бинарные `.srs` rule sets, оставляя точечные overrides в JSON. На KN-1012 профильный компилятор и `sing-box check` приняли кандидат с включённой картой стран, RU по умолчанию и остальными странами в группе «Остальной мир».

IPK `20261110-215624-d9a573386528` скомпилировал 249 `.srs` файлов, но установка не прошла post-install smoke, а `opkg configure hestia` завершился ошибкой `managed service operation failed: smoke`. Для восстановления установлен ранее рабочий пакет `20261110-205949-d9a573386528`: статус `install user installed`, supervisor readiness, managed-profile и sing-box checks проходят. IPv4 default route hash остался `f06c293b969676f64f57820103587f105084b9f90ca6c30640a925da0eba3871`, IPv6 default route отсутствует. Rollback удалил новый каталог GeoIP. Поэтому сохранение через UI после отката не подтверждено; нужно устранить startup smoke/lifecycle блокировку и повторить установку нового IPK. [Диагностика, проверка кандидата и восстановление](evidence/keenetic-country-map-save-20261110.txt).

**Установка новой версии, 11 ноября 2026 года:** после свежего preflight, root-only backup и сверки хешей тот же IPK установлен штатно: `install user installed`, supervisor ready, maintenance marker снят. Профиль, controller snapshot и sing-box проходят проверку; установлены все 249 `.srs`. IPv4/IPv6 default route hashes не изменились. Панель открывает страницу карты стран, но сохранённая политика остаётся выключенной, все страны назначены группе «Россия», кнопка «Сохранить» неактивна. Настройки в панели не менялись, фактическое сохранение новой карты и клиентский country routing ещё не проверялись. [Свидетельство установки](evidence/keenetic-country-map-install-20261111.txt).

**Попытка сохранения, 11 ноября 2026 года:** в панели `0.1.1-keenetic` на `http://192.168.1.1:8080/#/country-map` переключатель «Выбирать группу по стране назначения» был включён, затем нажата кнопка «Сохранить». Интерфейс перешёл в состояние «Сохраняем…» и оставался в нём при последующем наблюдении; подтверждение сохранения не получено. Это подтверждает зависшее ожидание в UI, но не подтверждает, что изменение записано. Предыдущий прямой API-ответ с отсутствующим `/proc/sys/net/ipv4/conf/all/src_valid_mark` требует сопоставления с версией и операцией установленного пакета; причина зависания пока не установлена. [Свидетельство попытки](evidence/keenetic-country-map-save-20261111.txt).

**Диагностика и первое исправление, 11 ноября 2026 года:** GET подтвердил исходную версию карты и выключенное состояние; повторный PUT вернул HTTP 503 `Применение изменения не подтверждено`, а GET после ответа показал, что политика не изменилась. Журнал panel записал `managed service operation failed: smoke`. Controller events показывали быстрый переход группы из `deny` на доступный выход. Первичная версия проверки повторяла чтение selectors до пяти секунд, но после установки IPK `20261111-115617-d9a573386528` PUT всё ещё завершался 503. Сверка свежих selector и quality report показала, что ожидаемая цель меняется одновременно с обновлением health/quality report и controller confirmation. [Свидетельство исходных запросов и диагностики](evidence/keenetic-country-map-save-20261111.txt).

**Уточнённое исправление и успешное сохранение, 11 ноября 2026 года:** smoke теперь заново вычисляет ожидаемые цели из актуального quality report и ждёт совпадения live selectors со свежими controller events. IPK `20261111-121609-d9a573386528` установлен после preflight, root-only backup и удалённой проверки хешей. Supervisor ready; managed profile, controller snapshot и sing-box проверки прошли, status — `install user installed`. После включения карты PUT вернул HTTP 200; ответ, последующий GET и `/opt/etc/hestia/snapshot.json` подтвердили `enabled=true` и все 249 прежних назначений. После перезагрузки страницы переключатель остался включён, кнопка «Сохранить» стала неактивной, назначения не изменились. Supervisor roles controller, router и binding-watch активны, `smoke-current` проходит. IPv4 default route hash сохранился, IPv6 default route отсутствовал до и после. Перезагрузка устройства и клиентский трафик через страновые правила не проверялись. [Детали сборки, установки и readback](evidence/keenetic-country-map-fix-20261111.txt).
