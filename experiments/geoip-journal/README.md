# Выбор выхода для VK и отображение страны

5 ноября 2026 года с разрешения владельца проверили, почему посещение VK по правилу `*.ru → Россия` не видно при выборе `keenetic-direct`. До обновления на stage1 была включена карта стран, а в группе «Россия» был доступен прямой выход. Исходная ревизия рабочего каталога — `dac27d6`. Ревизию установленного до опыта бинарника отдельно не определяли.

С ВМ `hestia-test-client` выполнили `curl -4 -sS -o /dev/null -w '%{remote_ip} %{http_code}\n' https://vk.ru/`. Ожидали, что поток попадёт в группу «Россия». Фактически VK вернул 302, а sing-box выбрал Hysteria 2 из группы «Внешний мир». У потока сохранился реальный IP без домена. Проверили это через `GET /api/traffic?query=87.240.137.164` и строки sing-box с одним идентификатором потока. Настройки Keenetic в опыте не меняли.

Метка последнего разрыва подписки совпала с остановкой и запуском служб панели, контроллера и DNS. Это установлено для одного перерыва. [Свидетельство](evidence/stage1.txt).

После обновления сохранились назначения стран и доступность всех четырёх служб. С того же клиента повторили HTTPS-запрос, зафиксировав исходный IP через `--resolve vk.ru:443:87.240.137.164`. VK снова вернул 302. В записи № 1326 есть домен, страна RU, совпавшая маска `ru` и выбранное подключение `keenetic-direct`. Контрольный HTTP-запрос прямо к IP вернул 404. В записи № 1327 причиной выбора прямого подключения стало отдельное правило `geoip-RU`. Фильтр API вернул обе записи при поиске по IP. Подтверждение внешнего интерфейса захватом пакетов в этот опыт не входило.

При высоте окна Chromium 1000 пикселей область прокрутки занимала 677 пикселей. В рабочей таблице видны домен VK, страна «Россия» и прямое подключение. Ключ 2ip на stage1 отсутствовал. Фоновый обработчик, включая пропуск ответов 400 и 500, проверен отдельно с тестовым HTTP-сервисом.
