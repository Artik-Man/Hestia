# Проверка физических подключений

5 ноября 2026 года на выделенной ВМ `hestia-load-01` проверяли, какие подключения можно испытать с действующим ядром. Ядро `6.1.0-53-cloud-arm64` предоставляет Ethernet-адаптер virtio `eth0` с активным линком. Второй интерфейс — `lo`. В гостевой системе отсутствуют модуль `mac80211_hwsim`, беспроводной адаптер, `iw`, `hostapd`, `wpa_supplicant` и `nmcli`. Поэтому радиосоединение с точкой доступа и передачу трафика по Wi-Fi на этой ВМ проверить нельзя. [Инвентаризация стенда](evidence/load1-environment.txt).

Воспроизвести инвентаризацию на этой ВМ можно командами:

```sh
uname -srmo
ls /sys/class/net
readlink -f /sys/class/net/eth0/device
cat /sys/class/net/eth0/carrier
/sbin/modinfo -n mac80211_hwsim
```

Собранный для Linux ARM64 обработчик `hestia -physical-list` прочитал реальные устройства из sysfs. Профиль стенда связывал один выход с `eth0`, второй — с отсутствующим `eth-missing`. Обработчик вернул для `eth0` признаки `present=true` и `online=true`, для отсутствующего интерфейса оба признака равны `false`. Имена выходов соответствовали привязкам. В ответе отсутствовал `lo`, список Wi-Fi был пуст. Сценарий запускался с временными `/etc` и `/run` внутри отдельного пространства монтирования. [Точный хеш сборки и публичный ответ](evidence/inventory.txt).

Для повторения на выделенной ВМ передайте ARM64-бинарник и `inventory.sh` в один временный каталог. Выполните в нём:

```sh
sudo unshare --mount bash ./inventory.sh ./hestia
```

В Chromium сборка Angular прошла десять браузерных тестов с синтетическим REST API. Вручную заданный Wi-Fi использовал выбранные `wlan1`, диапазон 5 ГГц и SSID. После перезагрузки профиль сохранился; изменение на 2,4 ГГц отправило запрос без пароля, а подтверждённое удаление убрало запись. Отдельно проверено поведение шлюза без радиоустройства. Проверка браузера подтверждает формирование запросов и отображение данных. [Журнал браузерных проверок](evidence/browser.txt).

Для воспроизведения в каталоге `frontend` выполните `npm run build`, затем `CHROME_BIN=/путь/к/chrome npm run test:browser`.

На той же ВМ распаковали Debian NetworkManager 1.42.4 в `/tmp`. Утилита `nmcli --offline` прочитала реальные сгенерированные keyfile-профили для 2,4 и 5 ГГц. При повторной сериализации сохранились диапазон, SSID с пробелами и специальными символами, пароль WPA, правило исходящего интерфейса, отдельная таблица маршрутов и запрет использования DHCP DNS шлюзом. Службу NetworkManager не запускали. В том же прогоне отдельные тесты с подменой команд проверили откат, удаление, отклонение файлов другого владельца и появление чужого активного подключения во время сохранения. [Версия, хеш и журнал](evidence/offline-keyfile.txt).

Воспроизведение офлайн-проверки с доступным `nmcli` на Linux:

```sh
HESTIA_NMCLI_OFFLINE=/usr/bin/nmcli go test -count=1 -v ./internal/physical
```
