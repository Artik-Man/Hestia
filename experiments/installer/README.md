# Приёмка установки Гестии на чистой Debian ARM64

Исходники проверки: [tests/lab/installer](../../tests/lab/installer/). Отчёт и свидетельства остаются здесь. Перед повторным запуском применяйте [правила выбора стенда](../../agents/virtual-machines.md); исторические имена ВМ не являются указанием создать или запустить их.

Испытаны три независимые ВМ из [образа Debian 12 ARM64](../README.md#историческая-подготовка-вм). Гестия установлена обычным способом в гостевую ОС с systemd как PID 1. Сервисы запускаются автоматически после перезагрузки. В хост-систему Гестию не устанавливали.

| Сценарий | Результат |
|---|---|
| Архив sing-box подменён до первой установки | Установка завершилась с ошибкой контрольной суммы. Бинарник контроллера и его unit не появились. |
| Первая установка bootstrap | Оба сервиса активны и включены. Селектор выбирает deny. Автоматическая проверка готовности завершилась за 2 с. Экспорт bootstrap создал файл с правами 0600 и отказался перезаписать существующий. |
| Повторная установка с настройками оператора | Контрольные суммы обоих файлов конфигурации сохранены. Контрольный HTTP-ответ получен через локальный SOCKS до и после установки. Проверка готовности заняла 1 с. Маршрут хоста по умолчанию сохранился. |
| Конфигурация формально корректна, но контроллеру задан недоступный тег выхода | Установщик дошёл до автоматической проверки готовности, сообщил об ошибке и вернул ненулевой код. |
| Перезагрузка гостя с изменённой конфигурацией | Изменился ID загрузки. Оба сервиса активны, контрольные суммы совпали, повторный запрос через SOCKS получил ответ. |
| Профиль с WireGuard в отдельной чистой ВМ | Для установки использовали только самораспаковывающийся установщик, JSON, `ru-wg.conf` и `fi-wg.conf`. Проверены два userspace-endpoint, два селектора, локальный сокет SOCKS, группа по умолчанию и порядок правил для `deepseek.com` и `com`. Установка с отсутствующим `fi-wg.conf` была отклонена с сохранением рабочих конфигураций. |
| Экспорт и восстановление в третьей чистой ВМ | До экспорта включили `ru-wg`, оставив `fi-wg` недоступным. Экспорт сохранил группы, порядок правил и доступность; в JSON остались ссылки на файлы, туда не попали значения ключей. Импорт на другом госте с отдельно переданными тестовыми файлами воспроизвёл селекторы `ru-wg` и `deny`. Совпали SHA-256 содержимого нормализованного снимка и байтов конфигурации sing-box. Обе профильные установки прошли проверку готовности за 1 с. |

Время относится к одному прогону проверки готовности при уже подготовленных зависимостях. Проверка SOCKS в bootstrap-опыте использует временный слушатель и отражатель на loopback. У примера WireGuard тестовые адреса и ключи. Этот опыт проверяет доставку, установку профиля и воспроизводимость, а подключение к настоящим VPN-провайдерам требует отдельных испытаний. В репозитории сохранены только проверенные результаты и хеши. Экспортированные пользовательские профили и исходные файлы VPN сюда не копируют.

## Повторение

Использовать выделенные свежие гости без существующей установки. В bootstrap-ВМ из корня копии проекта выполнить команды ниже. Поместить собранный для ARM64 бинарник и официальный архив sing-box на постоянный диск гостя. `/var/tmp` подходит для размещения на время этой проверки.

```sh
out=/var/tmp/hestia-installer-proof
sudo bash tests/lab/installer/lab.sh first /var/tmp/hestia /var/tmp/sing-box.tgz "$out"
sudo systemctl reboot
```

После загрузки из того же каталога:

```sh
sudo bash tests/lab/installer/lab.sh reboot /var/tmp/hestia /var/tmp/sing-box.tgz "$out"
sudo python3 -B tests/lab/installer/report.py bootstrap "$out"
```

Для сквозного переноса выполнить [сборку комплекта](../../deploy/docs/installer.md), поместить установщик, профиль и два тестовых файла VPN в отдельный каталог исходной чистой ВМ. Проверочный сценарий и `profile-test.py` поместить в другой каталог. Исходное дерево проекта установщику не требуется. Выполнить от root:

```sh
bash /var/tmp/runner/profile-lab.sh /var/tmp/inputs/hestia.run /var/tmp/inputs/stand.json source /var/tmp/source-proof
```

На второй чистой ВМ подготовить тот же установщик, экспорт `/var/tmp/source-proof/export.json` и отдельно переданные файлы VPN с сохранёнными именами. Выполнить:

```sh
bash /var/tmp/runner/profile-lab.sh /var/tmp/inputs/hestia.run /var/tmp/inputs/export.json imported /var/tmp/target-proof
python3 -B /var/tmp/runner/report.py profile /var/tmp/target-proof
```

Сравнить в двух отчётах `normalized_snapshot_sha256` и SHA-256 второго файла из `final_runtime_sha256` (конфигурация sing-box). Хеш снимка до нормализации может различаться из-за пробелов после ручного изменения входного JSON.
