# Порядок групп и выходов на трёх WireGuard-пирах

Проверяем фактический путь нового TCP-соединения после перестановки выходов внутри группы и после смены первой группы. Отдельно проверяем выбор при двух одинаковых доменных масках, отклонение новой конфигурации и сохранение через браузерную панель.

## Среда

Выделенная Lima ВМ hestia-binding-test с Debian 12 ARM64 и systemd. Три независимых WireGuard-пира в сетевых пространствах имён отвечают на одном адресе `198.18.42.42:18080`. Серверы возвращают метки alpha, reserve и beta. Каждый запрос запускает отдельный curl через SOCKS sing-box 1.14.4, передавая шлюзу имя. Ключи генерируются внутри ВМ и остаются там.

Исходно group-alpha — первая группа, её выходы расположены в порядке exit-alpha, exit-reserve. В group-beta только exit-beta. Все три подключения доступны. Два разных списка содержат одну маску `*.tie.lab.test`. В профиле первым записан список для group-beta, вторым — для group-alpha. Маски `*.alpha.lab.test` и `*.beta.lab.test` закрепляют контрольные соединения за своими группами. Имя для проверки маршрута по умолчанию не соответствует ни одному правилу.

## Результаты

| Состояние | Без совпадения | Общая маска | Контроль alpha | Контроль beta |
|---|---|---|---|---|
| Исходное | alpha | alpha | alpha | beta |
| Внутри alpha первым назначен reserve | reserve | reserve | reserve | beta |
| После этого beta назначена первой группой | beta | beta | reserve | beta |
| Отклонён устаревший или некорректный порядок | beta | beta | reserve | beta |
| Служба не запустилась с новым порядком | beta | beta | reserve | beta |
| Возвращён исходный порядок | alpha | alpha | alpha | beta |

При успешных изменениях сервер ответил 200 с полным подтверждённым порядком. При несовпадении ожидаемого состояния вернул 409. Пропуск группы и перенос выхода в чужую группу вернули 422. Запрос больше 64 КиБ получил 413. При инъекции отказа запуска sing-box запрос вернул 503. Проверка сравнила SHA-256 пяти управляемых файлов до и после отклонения, затем открыла новые соединения. Привязки, маски и административная доступность сохранились. [Протокол API и трафика](evidence/verification.txt).

Chromium загрузил main-YZH4SAE7.js от действующей панели ВМ через локальный SSH-туннель. Мышью передвинули group-beta наверх, а внутри group-alpha подняли exit-reserve. Попытка перенести выход в другую группу не изменила принадлежность выходов. Стрелки клавиатуры перемещали выбранный элемент. Переход между вкладками и обновление снимка сохранили рабочий порядок. До нажатия «Сохранить» шлюз возвращал исходный порядок, а запросов записи браузер не отправлял. Нажатие отправило один PUT и получило 200. После перезагрузки панели у exit-reserve остался приоритет 1. Новые соединения без маски и по общей маске вернули beta, а по маске alpha — reserve. [Протокол браузера](evidence/browser.txt) · [Трафик после сохранения](evidence/browser-traffic.txt) · [Среда и бинарники](evidence/environment.txt).

Сборка выполнена из рабочего дерева на основе d4e5db1947565a5eb635c55b450bc97eac1f9ac9 инструментами Go 1.27.3. SHA-256 проверенных бинарников указаны в манифесте.

Тест охватывает новые TCP-потоки в изолированном лабораторном сегменте. Сохранение уже открытых соединений и работа на физическом шлюзе требуют отдельных испытаний. Панель запущена отдельной системной учётной записью, которой через sudo разрешена только команда `/usr/local/bin/hestia -apply-group-order`.

## Повторение

Используйте отдельную ВМ hestia-binding-test с профилем [Debian 12 ARM64](../fakeip/vm/lima.yaml), инструментами wireguard-tools, dnsmasq-base, curl, sudo, iproute2 и Python 3. На машине разработки выполните из корня проекта:

    CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go -C backend build -o /tmp/hestia-order-controller ./cmd/hestia
    CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go -C backend build -o /tmp/hestia-order-panel ./cmd/hestia-panel
    (cd frontend && npm ci && npm run build)

Передайте в отдельный каталог гостя оба бинарника, каталоги `deploy/`, `experiments/group-order/`, `frontend/dist/hestia/browser/`, общий сценарий `experiments/list-binding/peer.sh` и официальный архив sing-box 1.14.4. Выполните в этом каталоге свежего гостя:

    sudo bash experiments/group-order/peers.sh
    sudo bash deploy/install.sh --config /var/tmp/hestia-group-order/profile.json \
        --controller-binary ./hestia-order-controller --sing-box-archive ./sing-box-1.14.4-linux-arm64.tar.gz
    sudo bash experiments/group-order/panel.sh ./hestia-order-panel ./frontend/dist/hestia/browser
    sudo python3 -I experiments/group-order/verify.py

Первый прогон должен завершиться строкой PASS и восстановить исходный порядок. Перенаправьте локальный порт по SSH на 127.0.0.1:18439 этой ВМ. Откройте `/#/groups`, передвиньте group-beta на первое место, затем внутри group-alpha передвиньте exit-reserve перед exit-alpha. Нажмите «Сохранить» и дождитесь подтверждения шлюза. Выполните в госте:

    sudo python3 -I experiments/group-order/verify.py --after-browser

Временный systemd drop-in для инъекции отказа удаляется после проверки. Сценарии запускаются только на явно выбранном госте. После испытаний ВМ выключают, сохранив диск.

### Перенос мышью между группами, 4 ноября 2026

На hestia-stage1 с установленной сборкой main-OMW2YZZF.js проверили, формирует ли перетаскивание выхода в пустую группу запрос с правильной позицией. В Chromium открыли «Группы», перетащили за ручку awg-home из default в «Внешний мир». Получили ожидаемую позицию 1. Чтобы сохранить рабочую конфигурацию, Playwright перехватил PUT до отправки на шлюз ([результат](evidence/drag-transfer.txt)). На ВМ проверен жест, а сохранение и восстановление списка после перезагрузки проверены с тестовым API: из frontend выполнить `npm run build && npm run test:browser`. Серверный перенос через компилятор профиля и обработку устаревшей исходной группы проверяет `make check`.

Последующая проверка от 4 ноября изменила критерий: переносы остаются в черновике до «Сохранить». Chromium подтвердил отсутствие записи при перетаскивании и отмене, один запрос при сохранении и новое распределение после перезагрузки. Это локальный тест с подменой API, а не операция на рабочем шлюзе. [Результат](../group-names/evidence/groups-toast.txt).
