# Независимая проверка сохранённых свидетельств VLESS

Дата проверки: 2026-11-06. Проверка выполнена локально по сохранённым файлам; к маршрутизатору и ВМ не обращались.

## Вывод

Сохранённые материалы попытки 08 согласованно подтверждают локальные TCP и UDP пробы с корректным синтетическим UUID, а также отказ TCP-пробы с неверным UUID при живых процессах и неизменном счётчике TCP-ответчика. Входные Go helper и три конфигурации попытки 08 совпадают по SHA-256 с исходными копиями попыток 03 и текущими прототипами. Независимая локальная сборка ARM64 helper из снимка попытки 08 дала SHA-256 `01ac83304e486a1b8c4dfac9bb1d7d12d15ccd12b22899f085c50b1bf28dff12`, совпавший с хешем helper из манифеста попытки 03 и удалённой проверки попытки 05.

## Сверка цепочки входов

- Попытка 03 (19:05:00Z) фиксирует SHA-256 helper `d2601eb1…19273a82` и конфигураций: valid `f167677a…ee1486a`, server `8f53b01b…e7cc6d5c`, wrong UUID `5ffc5e5d…18e406c4`.
- Манифест попытки 08 (19:08:15Z) фиксирует те же SHA-256 для снимка исходника, конфигураций и `remote-run.sh`. Локальная проверка подтвердила полные SHA-256 снимков попыток 08, 03 и прототипов; они совпадают.
- Попытка 04 (19:05:25–19:05:34Z) сообщает об успешной передаче отдельных файлов, включая sing-box, helper и все три JSON; архив не использовался.
- Удалённая проверка попытки 05 (19:05:48Z) сообщает SHA-256 sing-box `d953af88…2b4908a`, helper `01ac8330…28dff12` и тех же трёх конфигураций. Там же зафиксирована неудачная команда `sing-box --version` с кодом 1.
- Попытка 06 (19:06:04Z) исправила вызов версии на `sing-box version`, вывела sing-box 1.14.4 (Go 1.26.10 linux/arm64) и завершила три проверки конфигураций с кодом 0. Попытка 07 (19:06:20Z) независимо завершила каждую из тех же трёх проверок с кодом 0.
- Повторная локальная сборка helper из `attempt-08-run/source/vless-local-harness.go`, с `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 GOTOOLCHAIN=local GOPROXY=off go build -trimpath -buildvcs=false`, дала точный SHA-256 `01ac83304e486a1b8c4dfac9bb1d7d12d15ccd12b22899f085c50b1bf28dff12`. Артефакт помещён вне репозитория в `/private/tmp/hestia-vless-validator-20261106`.

## Проверка поведения по transcript

`attempt-08-run/manifest.txt` связывает снимки входов и скрипт с удалённым запуском 19:08:15–19:08:19Z и кодом 0. Скрипт задаёт отдельные PID для VLESS server, good-UUID client, wrong-UUID client, выполняет helper с лимитом 35 секунд и снимает хеши маршрутов/правил до и после.

В сохранённом выводе helper:

- прямые контроли получили TCP и UDP ответы; счётчики каждого endpoint стали 1;
- VLESS TCP получил маркер `HESTIA-VLESS-TCP-19312`, TCP-счётчик стал 2;
- VLESS UDP получил маркер `HESTIA-VLESS-UDP-19313`, UDP-счётчик стал 2;
- до и после неверного UUID PID сервера и обоих клиентов присутствовали; TCP-счётчик остался `2 → 2`, marker не вернулся;
- helper завершился `harness_exit=0`, финальные счётчики `tcp=2 udp=2`;
- журнал сервера содержит отказ `unknown UUID: 22222222-2222-4222-8222-222222222222`;
- IPv4/IPv6 route/rule hashes до/после совпали;
- скрипт отметил отсутствие процессов и слушателей тестового диапазона по завершении.

Попытка 09 (19:08:45Z) подтверждает удаление приватного каталога `/opt/tmp/hestia-vless-local.20261106-1905` и его отсутствие.

## Пробелы и ограничения

- В манифесте именно попытки 08 записаны хеши исходника, конфигураций и run script, но не хеши ELF sing-box и helper. Для связи исполняемых файлов с live run необходима цепочка: снимок/передача в попытках 03–04, проверка целевых хешей в попытке 05 и отсутствие перезаписи того же удалённого рабочего каталога до запуска 08. Отдельного повторного `sha256sum` на целевой стороне непосредственно перед попыткой 08 нет; прямую аттестацию ELF в момент запуска следует считать косвенной.
- Transcript попытки 08 не является raw byte-for-byte terminal stream: startup-строки, несущие топологические сведения, заменены маркером по сохранённой команде `sed` в `remote-run.sh`. Остальные сохранённые строки подтверждают маркер, счётчики, UUID-ошибку, жизнеспособность процессов и route/rule hashes.
- Отрицательная проба для неверного UUID была только TCP; UDP с неверным UUID не проверялся. Опыт остаётся loopback-проверкой выбранной версии и не доказывает внешний VPN, WAN, клиентский транзит или производительность.

## Воспроизведение локальной проверки

Из корня репозитория:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 GOTOOLCHAIN=local GOPROXY=off go build -trimpath -buildvcs=false -o /private/tmp/hestia-vless-validator-20261106 experiments/keenetic-vless-local/evidence/attempt-08-run/source/vless-local-harness.go
shasum -a 256 /private/tmp/hestia-vless-validator-20261106
```

Эта локальная проверка пересобирает helper и сверяет его идентичность. Она не повторяет сетевую пробу и не обращается к устройству.
