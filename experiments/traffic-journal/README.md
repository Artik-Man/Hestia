# Запись клиентского трафика в локальный журнал

Исходники проверки: [tests/lab/traffic-journal](../../tests/lab/traffic-journal/). Отчёт и свидетельства остаются здесь. Перед повторным запуском применяйте [правила выбора стенда](../../agents/virtual-machines.md); исторические имена ВМ не являются указанием создать или запустить их.

Имена ВМ в описании приведены к принятой 6 ноября 2026 года схеме [prod/dev/client](../../AGENTS.md#виртуальные-машины). Исходные имена в свидетельствах и путях резервных копий сохранены.

5 ноября 2026 года проверили, попадают ли короткие TCP-соединения и UDP-поток через настоящий sing-box в HTTP API панели и сохраняются ли настройки и история после перезапуска.

На выделенной ВМ Lima `hestia-dev` запустили Linux ARM64-панель из рабочего дерева поверх `0c9b759` и sing-box 1.14.4 в отдельном сетевом пространстве только с loopback. Тест запустил панель с временным хранилищем и подпиской на локальный Clash API. Клиент дважды запросил главную страницу через SOCKS5 и отправил датаграмму через SOCKS5 UDP ASSOCIATE. Контрольный получатель проверил её содержимое. Ожидали две записи TCP и одну UDP с отдельными ID. Проверили выход и чтение по одной записи на страницу. После изменения настроек до 16 МБ и 72 часов и перезапуска панели все три записи и новые настройки должны были сохраниться.

Проверки прошли. Фильтр по адресу, протоколу и подключению вернул две записи TCP, выбор UDP вернул одну запись. Все три указывают `lab-exit` и статус «выход не подтверждён». Клиент получил ответ, источник журнала сообщил только о выборе подключения. Стенд не измерял потери при длительной нагрузке, не проверял маршрутизацию через физический интерфейс и не обращался к личной ВМ. Сообщение sing-box об отсутствии маршрута по умолчанию ожидаемо при изоляции loopback. [Результаты и SHA-256 бинарных файлов](evidence/arm64.txt).

Для повторения соберите Angular и панель. Перенесите бинарник, каталог браузерной сборки, sing-box для Linux ARM64, `deploy/bootstrap/snapshot.json` и `verify.py` в отдельный каталог на проектной ВМ. В гостевой системе нужны Python 3, curl, iproute2 и unshare.

```sh
(cd frontend && npm run build)
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go -C backend build -buildvcs=false -o ../dist/hestia-panel ./cmd/hestia-panel
# В каталоге опыта на изолированной ВМ hestia-dev:
sudo unshare --net --pid --fork --mount-proc sh -ec 'ip link set lo up; python3 verify.py ./hestia-panel ./sing-box ./browser ./snapshot.json'
```

Виртуальная прокрутка проверяется отдельно тестом Chromium. Он использует управляемые ответы на запросы страниц и проверяет фильтры, обновление, настройки и навигацию по журналу из 10 020 строк.

```sh
cd frontend
npm run build
node --test tests/browser/traffic.mjs
```

## Проверка двух способов блокировки

На macOS ARM64 запустили тот же sing-box 1.14.4, временную SQLite и настоящий сборщик Go. Все клиентские запросы шли через локальный SOCKS без заданного тега. Две короткие HTTP-попытки к числовому адресу и имени получили ответ. Две другие попытки отклонили правило `reject` и выход типа `block` с отдельным тегом. Ожидали четыре строки и отдельную причину для каждой блокировки. Тест прошёл. При нескольких DNS-адресах сборщик сохранил домен, а для выбранного прямого выхода показал отсутствие подтверждения внешнего интерфейса. В этом прогоне проверялся TCP. Обработку форматов UDP, IPv6 и FakeIP покрывают тесты разбора записей. [Протокол прогона](evidence/sing-box-loopback.txt).

Для повторения передайте путь к установленному sing-box 1.14.4 для своей ОС.

```sh
HESTIA_TEST_SING_BOX=/path/to/sing-box go -C backend test -count=1 -v ./internal/trafficcapture
```

## Локальная проверка обновления журнала и QUIC — 13 ноября 2026 года

На macOS ARM64 в рабочем дереве проверены период по умолчанию 5 минут, переключение автообновления раз в 5 секунд, сохранение фильтров и открытых подробностей, скрытие уведомления о восстановлении и счётчика потерь. Chromium использовал подменённый API и 10 020 событий; к Keenetic не обращались. Проверка прошла; один промежуточный запуск остановился на нестабильной анимации списка, повторный прошёл. Go-тесты подтверждают классификацию QUIC только по сообщению sing-box того же потока, сохранение и фильтрацию. Реальная полнота распознавания на устройстве этим прогоном не проверялась.

Сборка, линтер и 25 тестов frontend, Go-тесты, проверки установщика, workflow и документации прошли. Общий `make check` ограничен отсутствующим ShellCheck; DNS lab-тестам не хватает Python-модуля `dns`. Команды, версия и границы вывода записаны в [свидетельстве](evidence/ui-refresh-quic-20261113.txt). Повторение: `cd frontend && npm run lint && npm test && npm run build && node --test tests/browser/traffic.mjs`; из корня — `make test test-installer test-workflows docs-check`.
