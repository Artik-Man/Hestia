# SOCKS TCP/UDP и block sing-box на IPv6 loopback

## Вопрос и критерии

Подтверждает ли sing-box 1.14.4 поведение SOCKS5 TCP и UDP при работе только через IPv6 loopback `::1`: разрешённые TCP/UDP-порты возвращают маркер, а отдельные TCP/UDP-порты блокируются правилом `block`? Опыт должен использовать только собственные локальные ответчики на `::1`, не обращаться к DNS или внешней сети и оставить наблюдаемые маршруты и правила без изменений.

Критерии для аппаратного прогона:

1. `sing-box check` принимает конфигурацию именно версии 1.14.4.
2. SOCKS5 TCP `CONNECT` к `[::1]:19431` возвращает TCP-маркер; SOCKS5 UDP `ASSOCIATE` с IPv6 `ATYP=4` и запросом к `[::1]:19432` возвращает UDP-маркер.
3. Прямые контрольные TCP- и UDP-запросы к свидетелям `[::1]:19433` и `[::1]:19434` успешно возвращают маркеры. Те же запросы через SOCKS не возвращают маркеры; счётчики обоих свидетелей не растут, процесс sing-box остаётся жив.
4. Слушатели, клиенты и целевые адреса используют только `::1`; вход SOCKS ограничен `[::1]:19430`. Другие адреса, DNS, WAN, VPN, клиентский транзит и изменение системного состояния не задействуются.
5. Удаляются только процессы и временные файлы данного опыта; фиксируются все команды, UTC-время, исходные хеши и коды возврата.

## Состояние

6 ноября 2026 года ограниченный опыт выполнен на KN-1012 с sing-box 1.14.4 после координации диапазона и проверки строгого SSH host key. Прямые и SOCKS-маркеры подтвердили положительные TCP/UDP-пробы на `::1`; outbound `block` не пропустил TCP и UDP к двум локальным свидетелям. Попытки 1 и 2 остановились до запуска harness из-за ошибок ожидания готовности; каждая сохранена отдельно. После успешной попытки собственные процессы, порты и временный каталог очищены.

Локальный прототип состоит из:

- [`singbox-ipv6-loopback.json`](prototype/singbox-ipv6-loopback.json): SOCKS только на `::1:19430`; порты `19431` и `19432` направляются в `direct`, финальное действие — `block`.
- [`ipv6-loopback-harness.go`](prototype/ipv6-loopback-harness.go): IPv6-only TCP/UDP ответчики и SOCKS5-клиент. TCP блок проверяется отсутствием маркера и неизменностью счётчика, UDP блок — таймаутом и неизменностью счётчика; перед и после отрицательных проб проверяется живой PID sing-box.
- [`run-on-device.sh`](prototype/run-on-device.sh): ограниченный запуск с точечной проверкой `::1:19430`, watchdog 39 секунд и очистка только дочерних процессов данного runner.
- [Локальная подготовка](evidence/local-validation.txt): форматирование, `go vet`, кросс-сборка ARM64 и SHA-256 входов/сборки.

## Локальный результат

`gofmt`, `go vet` и статическая сборка для Linux ARM64 завершились с кодом 0. Первая попытка `go vet` завершилась кодом 1 из-за неиспользуемого импорта; импорт удалён, после чего проверка прошла. Бинарник не запускался, локальные сокеты не открывались. Локально отсутствовал sing-box 1.14.4; перед аппаратными пробами конфигурацию проверил целевой sing-box 1.14.4 через существующий Entware loader.

## Условия и среда

Цель — физический Keenetic KN-1012; ранее в этом же исследовательском цикле для устройства подтверждены Linux `4.9-ndm-5` и ARM64. В этом прогоне целевая версия sing-box 1.14.4 подтверждена непосредственно перед тестом. SSH-соединения использовали существующую запись host key с `StrictHostKeyChecking=yes`, `BatchMode=yes` и `IdentitiesOnly=yes`.

Для всех файлов был проверен SHA-256 на целевом устройстве. Координатор подтвердил свободный диапазон `19430–19439`, процесс/ресурс `kn1012-ipv6-loopback-20261106-01` и каталог `/opt/tmp/kn1012-ipv6-loopback-20261106-01`. Порты `19310–19359`, чужие ресурсы и `/opt/tmp/hestia-*` не использовались. UDP relay и клиент использовали временные ОС-порты только на `::1` (`58979` и `56645` в transcript); они принадлежали процессам опыта и закрылись при завершении. Третий запуск ограничивался 35 секундами harness и watchdog 39 секунд после его старта; фактическая работа заняла около 1,3 секунды, включая ожидание запрещённого UDP. Маршруты, правила, firewall, системный DNS, sysctl, VPN и службы не менялись.

## Результат на KN-1012

| Проверка | Наблюдение |
|---|---|
| Целевая конфигурация | sing-box 1.14.4 сообщил код 0 для `check`; хеши runtime, конфигурации и harness совпали с локальными |
| Прямой контроль | TCP и UDP свидетели на `[::1]:19433` и `[::1]:19434` получили по одному прямому маркеру |
| SOCKS TCP direct | `CONNECT` к `[::1]:19431` вернул `HSTIA-IPV6-TCP-ALLOW-19431`; счётчик ответчика — 1 |
| SOCKS UDP direct | `ASSOCIATE` с IPv6 `ATYP=4`, затем запрос к `[::1]:19432`, вернул `HSTIA-IPV6-UDP-ALLOW-19432`; счётчик — 1 |
| SOCKS TCP block | Запрос к `[::1]:19433` получил SOCKS reply code 2, маркер не вернулся; счётчик свидетеля остался `1 → 1` |
| SOCKS UDP block | Запрос к `[::1]:19434` завершился таймаутом 1,2 с, маркер не вернулся; счётчик свидетеля остался `1 → 1` |
| Журнал sing-box | Для обоих отрицательных направлений есть записи `outbound/block`: `blocked connection` и `blocked packet connection` |
| Маршруты и правила | SHA-256 IPv4/IPv6 routes/rules до и после совпали; сырые таблицы не сохранялись |
| Очистка | PID sing-box, harness и watchdog отсутствуют; порты свободны; каталог данного опыта удалён |

Два первых запуска не дошли до harness и не посылали маркеры. Первая попытка выявила, что BusyBox `sleep` не принимает дробное `0.2`; во второй запуск sing-box успешно открыл `[::1]:19430`, но BusyBox `netstat` не соответствовал слишком узкому условию `tcp6` в проверке готовности. Третья попытка использовала строку старта SOCKS в журнале sing-box, не меняя конфигурацию или семантику теста. Подробные команды, коды возврата, хеши, оба неуспешных прогона и успешный transcript находятся в [evidence](evidence/attempt-03.txt), [проверках маршрутов](evidence/route-rule-hashes.json) и [очистке](evidence/cleanup.txt).

Вывод ограничен SOCKS5 TCP/UDP и outbound `block` sing-box на IPv6 loopback одного KN-1012. Он не подтверждает глобальную IPv6-маршрутизацию, клиентский транзит, DNS клиентов, реальные VPN-выходы или блокировку внешних адресов.

## Воспроизведение

После отдельной координации и разрешения владельца следует заново проверить известный host key, свободное состояние только назначенных портов и точного каталога, затем SHA-256 всех входов. Перед запуском обязательна проверка конфигурации на целевой версии sing-box 1.14.4. Подробная фактическая последовательность для этого прогона приведена в [attempt-03.txt](evidence/attempt-03.txt); его временный каталог удалён, поэтому старый запуск нельзя повторить без новой координации.
