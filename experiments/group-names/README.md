# Создание и изменение названия группы

4 ноября 2026 года на Debian ARM64 ВМ `hestia-stage1` проверили форму из рабочего дерева на базе `44bb04d`. Ожидали пустое поле при создании, текущее название при редактировании и отсутствие записи при отмене. Chromium подтвердил все три условия. В этом прогоне рабочие группы не меняли.

Для повторения откройте страницу «Группы», нажмите «Создать группу», введите название и нажмите Escape. Затем нажмите «Редактировать» у существующей группы, сверьте значение поля и нажмите «Отмена». Сохранение кириллического названия и его повторное чтение проверены отдельно в локальном Chromium с тестовым API командой `npm run test:browser` из каталога `frontend`. Обработку имени и сохранение привязок проверяют тесты шлюза с компилятором профилей в `make check`.

При чтении состояния на ВМ панель также вернула `error` для `awg-home`. Журнал AWG фиксировал сбои проверки соединения и перезапуски до установки этого обновления. [Результаты проверки](evidence/stage1-20261104.txt)

### Удаление групп и уведомления, 4 ноября 2026

На рабочем дереве от 44bb04d в Chromium проверили создание, переименование и удаление группы, уведомления PrimeNG и сохранение ввода при ошибке. Тест выполнялся на собранной панели с локальным тестовым API. Проверка удаления в компиляторе использовала временный каталог: нельзя удалить текущую группу по умолчанию или группу с выходами; при удалении пустой группы доменные списки остаются без привязки, их маски сохраняются. Для повторения выполните `make check`, затем из `frontend` — `npm run build && npm run test:browser`. [Результат браузерной проверки](evidence/groups-toast.txt).
