# Разные DNS-ответы после прогрева и запрет FI

Один домен получает разные реальные IPv4 через RU и FI. У каждого ответа свой TTL и каждый адрес на стенде относится к стране своего резолвера. До отказа FI должен выиграть выбор для обычного имени. Это контроль исходного состояния. После прогрева запрещаем FI, пока ранее полученный ответ FI ещё свеж. Оба физических пути стенда продолжают передавать пакеты, поэтому обход запрета был бы виден в захватах.

| Сценарий | Проверяемый результат |
|---|---|
| Частое имя без маски до отказа | Трафик клиента по FakeIP достигает адреса FI через FI. Запросы прогрева получают разные адреса и TTL через соответствующие выходы. |
| То же имя после запрета FI | Новые TCP и UDP через сохранённый FakeIP достигают адреса RU через RU. Фиксируем, остался ли пригоден прогретый ответ RU или понадобилось новое разрешение. |
| Частое имя с явным правилом FI | При запрете FI его новый поток блокируется. Данные и DNS этого имени не переходят на RU. |

В отчёте укажем адреса, TTL, их остаток в момент запрета, DNS-запросы на интерфейсах и фактически принятые тестовым сервером пакеты. Результат относится к новым потокам и подконтрольным IPv4 A-записям.
