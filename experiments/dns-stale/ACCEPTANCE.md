# Выдача истёкшей DNS-записи при временном сбое

Проверяем два варианта поведения экспериментального шлюза для новых IPv4-потоков при сохранённом клиентом FakeIP. В строгом режиме срок TTL окончателен. В экспериментальном аварийном режиме допускаем прежнюю положительную A-запись на ограниченное время после исходного истечения, только если обновление через разрешённые резолверы завершилось временной ошибкой. Это проверка предложенной политики из [архитектуры](../../docs/architecture.md#срок-хранения-dns-ответов).

| Условие | Критерий |
|---|---|
| A истекла, временный отказ резолвера | Строгий режим возвращает ошибку. Аварийный допускает старый адрес только внутри заданного окна и при доступном разрешённом выходе. |
| Окно закончилось или прежний выход запрещён | Старый адрес не используется. Повторные запросы не продлевают окно. |
| Получен достоверный отрицательный ответ | Старое положительное значение не используется в его контексте. |
| Резолвер восстановился и вернул B | Новый поток через тот же FakeIP достигает B. |
| Явное правило FI | Внешние DNS-запросы и трафик этого имени не выходят через RU даже во время тайм-аута. |

Сверяем адрес и интерфейс клиентских пакетов, результаты резолвера и время относительно исходного TTL. Выбор производственного окна и реализация постоянного хранения остаются отдельными решениями.
