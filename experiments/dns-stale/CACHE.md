# Политика экспериментального аварийного DNS-кэша

Команда `python3 -B experiments/dns-stale/cache.py gateway --down /run/hestia-lab/fi-down` запускает строгий режим. Для опыта с аварийным окном передайте, например, `--stale-seconds 11`. По умолчанию интервал равен нулю. Это отдельный режим стенда без прогрева и без постоянного хранения. DNS-входы, формат FakeIP и маршруты совпадают с опытом ротации.

После истечения TTL каждое новое разрешение, в том числе для уже известного клиенту FakeIP, запрашивает свежий адрес через разрешённые резолверы. Одновременные запросы одной волны объединяются. При наличии свежего положительного ответа шлюз использует его сразу. Когда все допустимые попытки завершились тайм-аутом или SERVFAIL, экспериментальный режим может выдать последний положительный адрес, ранее выбранный на допустимом выходе. Шлюз сохраняет исходное время истечения и возвращает TTL 0. При возрасте `0 ≤ сейчас − исходное истечение < аварийное окно` ответ ещё допустим. На правой границе он запрещён. Повторные сбои не продлевают исходный срок. Ответ с первоначальным TTL 0 не запоминается для аварийной выдачи.

Решение принимает во внимание текущий набор разрешённых групп, исходный резолвер и интерфейс, идентичность избранной записи, последнюю волну опроса и исходное истечение. Они проверяются ещё раз перед выдачей клиенту. В журнале `stale-served` указаны домен, реальный адрес, группа, возраст в секундах, первоначальное монотонное время истечения и причина `all_temporary`. На стенде один резолвер привязан к каждому именованному интерфейсу. Если выход объявлен недоступным, его прежний адрес не выдаётся. Перезапуск теряет старые записи.

Достоверный отрицательный ответ от собственного источника аннулирует старую запись и другие выборы того же адреса в кэшах с разными наборами разрешённых групп. Для отрицательного результата требуется AA либо подходящий SOA класса IN для имени. NXDOMAIN от одного источника не отменяет свежий A от другого. При отсутствии свежего A отрицательный ответ хотя бы от одного разрешённого резолвера исключает аварийную выдачу в этой волне. Когда все разрешённые ответы согласны на NXDOMAIN или NODATA, клиенту возвращается этот результат и доступный SOA. При смеси отрицательных результатов и других ошибок клиент получает SERVFAIL. Отрицательные ответы не кэшируются.

Опыт ограничен одной прямой IN/A-записью во внутренней неподписанной зоне `lab.test.`. Запросы других имён, а также запросы с DO, CD или AD не обслуживаются этим режимом. DNSSEC, CNAME, AAAA, несколько A-записей и хранение кэша на диске выходят за границы испытания. Неподходящий источник, DNS-транзакция, неподдерживаемая форма ответа, усечённая датаграмма, REFUSED и ответы с Extended DNS Error запрещают использование старого адреса в этой волне. В подписанной зоне обычный SERVFAIL сам по себе не доказывает временный сетевой сбой.

В памяти хранится до 128 выбранных кандидатов и до 512 представлений выбора по группам. Внешние попытки ограничены 64 запросами, каждой отводится до двух секунд. При заполнении лимита ответ не выдаётся из аварийного кэша. Это границы DNS-опыта с контролируемыми клиентами. Команда `python3 -O -B -m unittest discover -s experiments/dns-stale -p test_stale.py` запускает локальные проверки. Нужен dnspython.
