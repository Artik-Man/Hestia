# Ограниченный прототип lifecycle Keenetic-профиля

`profile-lifecycle-remote.sh` выполняет один ограниченный `up` существующего native Keenetic VPN-интерфейса и восстанавливает его исходное состояние `down`. Допускаются только два точных соответствия из owner-approved inventory: `Solar (Moscow)` → `Wireguard2`/`wireguard` и `Poppuri` → `SSTP1`/`sstp`. Начальное состояние ограничено `down/no`; прочие статусы отклоняются. Скрипт проверяет pinned SHA-256 `/bin/ndmc`, читает только конкретный интерфейс и извлекает `state`, `link`, `status`, `connected` через FIFO в allowlist parser. Секреты и сырые ответы в журнал не попадают.

Каждый `ndmc` вызов ограничен таймером; poll counts ограничены отдельно для административного состояния и connected-флага. До изменения запускается 240-секундный watchdog возврата `down/no`, переживающий SSH hangup. Основной сценарий возвращает профиль сразу после пробного `up`; EXIT/HUP/INT/TERM cleanup повторяет восстановление при необходимости. Успех цикла требует административного `up`, device-reported `connected=yes`, принятого возврата в `down/no` и этих значений в readback. Это не доказательство внешнего handshake или data plane.

Локальный `run-profile-lifecycle.py` проверяет pinned SSH host key, сверяет текущий source SHA, передаёт скрипт в уникальный каталог с режимом 0700, проверяет SHA remote-копии, вызывает только один из разрешённых профилей и удаляет собственный staging файл/каталог. Подробные команды, exit codes и sanitized status lines записаны в `evidence/attempt-*lifecycle-*/result-sanitized.json`. Для каждого цикла зафиксированы отдельные source snapshots до передачи. Неизменяемые evidence snapshots описывают фактические версии, даже если рабочие файлы позже отформатированы.

Результаты выполненных native lifecycle циклов и их ограничения приведены в [отчёте опыта](../README.md#lifecycle-существующих-профилей-на-kn-1012). Текущие сценарии подтвердили только Keenetic-отображаемый connected state для двух сохранённых профилей. Handshake age отсутствовал в sanitized `show interface`; никакой TCP/UDP data transfer, Hestia runtime, новый профиль, маршрут, группа или fail-closed не проверялись.
