## Conclusion and limits

The update is installed and ready. This trace proves NDM has an exact conntrack record with a policy-valued connection mark and `ifw` equal to `opkgtun0`'s ifindex while the trace sees the tuple on `br0`. It still does not prove a packet's `skb->mark`, an RPDB lookup, delivery to the TUN file descriptor, or the reason no AF_PACKET/sing-box event appeared. `not_observed` is not a drop verdict; `[FASTNAT]` and `/proc/sys/net/hwnat/ppe_enabled=1` remain relevant caveats. Neither the trace nor this package install proves VPN egress or the return path. `hestia-prod` and VM power/configuration were not accessed.

```sh
sudo -n timeout 15 tcpdump -nn -l -i lima0 '(src host 192.168.1.124 and src port 49335 and dst host 1.1.1.1 and dst port 443) or (src host 1.1.1.1 and src port 443 and dst host 192.168.1.124 and dst port 49335)' & capture_pid=$!; sleep 1; curl -4 --interface 192.168.1.124 --local-port 49335 --connect-timeout 3 --max-time 5 --resolve one.one.one.one:443:1.1.1.1 -sS -o /dev/null https://one.one.one.one/cdn-cgi/trace; curl_status=$?; wait "$capture_pid" || true; echo curl_exit=$curl_status
```
