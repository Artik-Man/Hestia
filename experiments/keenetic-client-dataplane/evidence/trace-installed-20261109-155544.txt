Defect found and corrected during this run
An earlier package 20261109-154214 reported cleanup overhead as a DurationMs slightly greater than 15000 and rejected the summary. The implementation now clamps only the reported duration to the requested session window; the 1–15 second request validation and capture timer remain unchanged. A regression test covers 15.25 seconds elapsed -> 15000 ms. The corrected package was independently code- and security-reviewed before this update.

Conclusion and limits
The trace successfully bracketed the test flow at the Keenetic bridge but did not observe it at OpkgTun or in sing-box. Current group exits are available and the domain lists are enabled, but these decisions occur inside sing-box after TUN ingress and cannot directly explain this earlier gap. This localizes the next investigation to the bridge-to-OpkgTun segment; it does not identify whether policy classification, packet marking, RPDB lookup, another forwarding condition, or a capture limitation caused the gap. `not_observed` is not a kernel drop verdict. WAN absence, VPN egress, return routing and UDP behavior were not tested. No route or policy mutation was made.

Reproduction
On the authorized test window, start the root-only `/opt/bin/hestia -traffic-trace` with the same tuple and `durationSeconds: 15`, then immediately run the tcpdump/curl commands above from hestia-client. A trace summary is written to stdout and the bounded traffic journal. The source port must match in both commands.
