# Managed profile recovery and package configure — 10 November 2026

## Scope and pre-state

Target: Keenetic Giga KN-1012, KeeneticOS 5.02.B.3.0-2, Entware `aarch64-3.10`. Work used the pinned `keenetic-hestia` SSH alias after the owner asked to resolve the failed installation. No client traffic, external probes, policy changes, or manual route changes were made.

The already-unpacked package was `20261110-094102-e2ca76bd1fc4` (`install user unpacked`). Hestia services were stopped. The managed profile validator failed because the saved sing-box ingress route targeted `Остальной мир`, while the current profile safety predicate returned no eligible ingress group and expected `deny`. The group contained the ready Zarubin AmneziaWG exit and Laurel Hysteria 2. At the time of repair, the active Keenetic default route used `eth3`, matching the stored `keenetic-uplink` binding.

A root-only backup was created at `/opt/tmp/hestia-profile-repair-20261110T154523Z/`, containing `/opt/etc/hestia`, opkg status, and IPv4/IPv6 default-route snapshots. The existing `package-maintenance` marker was confirmed to be a secure root-owned regular file with no matching live `opkg` process; it was preserved for the package's normal configure step. Existing `*-opkg` conffile sidecars were left untouched.

## Recovery

The owner had previously approved moving Laurel to `Россия` at priority 2, leaving Zarubin as the sole exit in `Остальной мир`. An offline candidate was compiled from the verified installed profile/backend, using the installed `profile.py` generation helpers. It passed the managed-profile validator, Hestia controller snapshot check, and sing-box config check before publication.

Five active files were replaced individually via same-directory atomic renames: `profile.json`, `profile-source.sha256`, `sing-box.json`, `profile-backend.sha256`, and `snapshot.json`. On any post-publication validation error, the procedure restored those files from the root-only backup. The published profile/backend/snapshot SHA-256 values match the previously approved candidate:

- `profile.json`: `d844b6b8b37484f5903604f256d6b827bda6e1aa45effce0047668535b08ff37`
- `sing-box.json`: `47602ac0e7323a10dc61cac7cb800d3439ee957a0264adad8c1aaf9d43fc64ec`
- `snapshot.json`: `8bc0176e150ae2259356a62027f7eaa5f3c27d0fe5df5495c1dcca93451ed2a0`

Managed-profile, controller snapshot, and sing-box checks all passed on the active files. `/opt/bin/opkg configure hestia` then completed with exit 0 and cleared the package-maintenance marker.
