# Перезапуск DNS-прототипа и движка FakeIP

На одноразовой Debian ARM64 сравниваем новый процесс DNS-кэша с новым процессом sing-box. В третьем прогоне разрешаем sing-box записать только соответствия FakeIP в отдельный файл стенда. Реальный DNS-кэш sing-box выключен. После каждого перезапуска проверяем идентичность обоих процессов, ранее выданные адреса и адреса, выданные повторно.

| Проверка | Свидетельство |
|---|---|
| Исходное состояние | Явное FI-имя получает FakeIP первым. Второе имя без маски получает другой FakeIP. TCP и UDP к обоим достигают FI. Фоновый прогрев второго имени получает положительные ответы FI и RU с разными IP и TTL. |
| Холодный DNS | После первого прогрева, пока минимум два клиентских запроса ещё внутри окна, запрещаем FI и перед перезапуском получаем действующий RU-ответ A по старому FakeIP. Только затем меняем запись авторитета с A на B. При перезапуске только DNS новый поток по старому FakeIP обычного имени должен получить свежий B от RU. В захвате есть внешний запрос до ответа, который использовал B. |
| Перезапуск sing-box | Проверяем старые FakeIP до и после выдачи нового имени. Положительный DNS-кандидат RU, если ещё действителен, должен сохранить прежний срок. После действительного истечения следующий поток должен получить B через новое внешнее разрешение. |
| Защита явного имени | С момента запрета FI запрос DNS для него получает SERVFAIL. Новые TCP/UDP по сохранённому явному FakeIP не должны выйти ни через FI, ни через RU, в том числе после выделения адреса другому имени. Любая доставка — отрицательный результат с ненулевым кодом, даже если текущая карта имен формально корректна. |
| Доступность RU и границы | Другое имя клиента по вновь выданному FakeIP получает ответы через RU. Захваты LAN, RU и FI, журналы авторитетов и конечной точки содержат идентификаторы запросов и данных. |

Состояние веб-интерфейса, IPv6 и существующие TCP-сессии не входят в опыт. Для сохранения карты FakeIP используем параметр [sing-box cache file](https://sing-box.sagernet.org/configuration/experimental/cache-file/), отдельно от кэша DNS-записей. Без файла карты проверяем поведение движка опытным путём.
