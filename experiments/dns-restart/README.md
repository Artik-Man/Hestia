# Перезапуск прогретого DNS-кэша и движка FakeIP

Исходники проверки: [tests/lab/dns-restart](../../tests/lab/dns-restart/). Отчёт и свидетельства остаются здесь. Перед повторным запуском применяйте [правила выбора стенда](../../agents/virtual-machines.md); исторические имена ВМ не являются указанием создать или запустить их.

Имена ВМ в описании приведены к принятой 6 ноября 2026 года схеме [prod/dev/client](../../AGENTS.md#виртуальные-машины). Исходные имена в свидетельствах и путях резервных копий сохранены.

4 ноября 2026 года на отдельной ARM64-ВМ проверили три вида перезапуска при разных DNS-ответах RU и FI. У RU авторитетный адрес был `.11`, TTL 14 секунд; у FI — `.22`, TTL 29 секунд. Перед отказом FI прогрев получили оба резолвера для `hot.lab.test`; после запрета FI активный RU-кандидат `.11` повторно использовался без внешнего DNS-запроса. Затем RU-запись переключили на `.33`. В тесте подменены внешние выходы и авторитетные DNS, адреса синтетические.

## Результаты

| Режим | Проверка | Результат |
|---|---|---|
| `dns` | Перезапустили только процесс DNS-кэша; sing-box и его карта FakeIP работали дальше | DNS-кандидат в памяти потерялся. Поток по прежнему FakeIP заново запросил RU и получил `.33` с TTL 13 с. После истечения этого TTL новый запрос снова получил `.33`; TCP и UDP прошли через RU. Истёкший TTL не продлевался. |
| `engine` | Перезапустили sing-box без сохранения FakeIP-сопоставлений | **Проверка безопасности выявила утечку.** Sing-box выдал прежний FI-only FakeIP `198.18.0.2` новому RU-разрешённому имени. TCP и UDP, отправленные клиентом на старый адрес FI-only имени, достигли `.33` через RU. Независимый проверяющий подтвердил захваты. Верификатор завершился кодом 1 именно из-за этого результата. |
| `engine-persist` | Перезапустили sing-box с `cache_file.store_fakeip=true`; файл карты оставили на месте | Сопоставление `198.18.0.2` с FI-only именем сохранилось; новое RU-имя получило `.4`. При запрещённом FI прежний адрес блокировался по TCP и UDP, RU-контроль проходил. Кандидат RU `.11` вернулся с TTL 12 с при фактическом остатке 12,84 с. После исходного срока запись обновилась до `.33` через RU. Верификатор завершился кодом 0. |

Во всех трёх режимах проверено по 20 новых помеченных TCP/UDP-потоков и 8 клиентских DNS-транзакций. После отзыва FI в захвате `fi0` нет DNS-пакетов или пакетов к тестовому сервису. Для каждого разрешённого потока фактические LAN- и WAN-захваты совпали с ответом тестового сервера. Два fault-injection теста верификатора прошли. Независимый ревьюер повторно разобрал три сохранённых набора захватов: `dns=0`, ожидаемая ошибка `engine=1`, `engine-persist=0`.

Файлы в [архиве evidence](evidence/official-livehot/) содержат PCAP LAN/RU/FI, журналы DNS и тестового сервера, сопоставления FakeIP, время процессов, версии, SHA-256 компонентов и вывод проверки по каждому режиму. [Коды завершения](evidence/official-livehot/status.txt) · [Fault-injection проверки](evidence/official-livehot/offline-tests.txt).

## Выводы для архитектуры

1. DNS-прототип хранит кэш и историю прогрева в памяти. После его перезапуска прежний положительный ответ не сохраняется; имя разрешается заново через оставшийся разрешённый резолвер. Текущий прототип не проверяет запись DNS-кэша на диске.
2. Потеря соответствий FakeIP при перезапуске опасна, если числовой псевдоадрес может быть назначен новому имени. В сценарии стенда старый FI-only адрес после повторной выдачи направил данные через RU. Кэшировать только DNS-ответ недостаточно: привязка ранее выданного FakeIP должна сохраниться либо неизвестные после рестарта адреса должны безопасно блокироваться и не переназначаться.
3. Включённый `store_fakeip` на sing-box 1.14.4 сохранил соответствия в отдельном файле и устранил повторное назначение в этом сценарии. Это экспериментальный контроль, а не интегрированная или принятая настройка Гестии. Кэш DNS-записей при этом не сохранялся (`store_dns=false`), поэтому опыт не доказывает его долговременное хранение.
4. Для сохранённых живых DNS-ответов срок остался привязан к исходному TTL. После его окончания поток дождался свежего RU-ответа `.33`; старое `.11` не использовалось как действующее.

## Среда и границы

Использована изолированная Debian ARM64 Lima-ВМ `hestia-dns-geo`, Linux `6.1.0-53-cloud-arm64`, sing-box `1.14.4`, Python dnspython `2.3.0-1`. Внутри ВМ отдельные network namespaces моделировали LAN, RU и FI. Доступность FI отозвали маркером DNS-прототипа, оставив физический лабораторный интерфейс поднятым; отсутствие выхода проверили захватами. Домены `lab.test` и адреса `203.0.113.0/24` — тестовые.

Проверялись новые потоки IPv4 с одиночными IN/A-записями. Это перезапуски процессов, не выключение питания всей ВМ. Результат не проверяет производственную службу Гестии, реальный VPN, восстановление после внезапной потери питания, испорченный файл карты, DNSSEC, CNAME, AAAA, IPv6 или открытые TCP-сессии. `hestia-prod`, адрес `192.168.1.133`, Keenetic и личные подключения не использовались. После опыта `hestia-dns-geo` остановлена.

## Повторение

На отдельной Debian ARM64-ВМ с sing-box 1.14.4, dnspython, iproute2 и tcpdump перенесите каталоги `tests/lab/dns-restart`, `tests/lab/dns-split-warm`, `tests/lab/dns-warm`, `tests/lab/dns-rotation` и `tests/lab/dns-geo`, сохраняя соседство. Скрипт отказывается запускаться, если hostname гостя не `hestia-dns-geo`/`lima-hestia-dns-geo`, архитектура не ARM64 или отсутствует TUN. Для каждого режима нужен новый пустой каталог результатов:

```sh
sudo bash tests/lab/dns-restart/lab.sh dns /var/tmp/hestia-restart-dns
sudo bash tests/lab/dns-restart/lab.sh engine /var/tmp/hestia-restart-engine
sudo bash tests/lab/dns-restart/lab.sh engine-persist /var/tmp/hestia-restart-persist
```

Код завершения 1 у режима `engine` ожидаем, если верификатор повторно обнаружил переназначение старого FI-only FakeIP. Захваты и журналы при этом остаются для разбора. Режим `engine-persist` использует отдельный тестовый файл сопоставлений и не меняет рабочую конфигурацию.

Fault-injection тесты офлайн-аудитора запускаются командой:

```sh
python3 -B -m unittest discover -s tests/lab/dns-restart -p 'test_verify.py'
```
