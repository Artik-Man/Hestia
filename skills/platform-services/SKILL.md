# Использование платформенного модуля служб

Применяй этот контракт при переносе управления службами Гестии между платформами. Описание поведения и критерии находятся в `docs/features/platform-services.md`.

- Прикладной код получает `services.Manager` и передаёт `services.Service` с ролью из `services.Kind`. Имена systemd unit формирует Linux-адаптер.
- Для AWG укажи `Instance`. Адаптер проверяет UUID или исторический тег через существующий валидатор.
- `Start` и `Stop` принимают упорядоченную группу. Ошибка может следовать за частичным выполнением. Восстановление принадлежит координатору транзакции.
- Успех `Start` дополняй штатной проверкой readiness. `Unknown` при чтении состояния сохраняет защитные ограничения. Для обязательной активности обрабатывай состояние и ошибку.
- Production-конструктор подключает `systemd.Manager{}`. Тестовая функция `Run` позволяет наблюдать команды, отмену и ошибки.
- При добавлении платформы реализуй общий контракт и проверь идентификаторы, состояния, отмену, групповые операции и восстановление вызывающего кода.
