# Применение решения контроллера

Команда читает конфигурацию из JSON, выбирает группу по домену и применяет её текущее состояние к работающему селектору sing-box. Запустите её в сетевом пространстве шлюза. Селектор должен называться как группа и содержать ровно её выходы и служебный выход `deny`. Управляющий API слушает `127.0.0.1:9090` внутри этого пространства. Правила маршрутизации по доменам, защита от утечек и изоляция DNS настраиваются в сетевом слое до запуска команды.

Например, оператор передаёт такой снимок состояния:

```json
{
  "groups": [
    {"id": "russia", "exits": ["ru-out"]},
    {"id": "finland", "exits": ["fi1-out", "fi2-out"]}
  ],
  "lists": [{"id": "fi-sites", "group": "finland", "masks": ["*.fi.lab.test"]}],
  "healthy": {"ru-out": true, "fi1-out": false, "fi2-out": true}
}
```

Соберите команду в корне репозитория и запустите:

```sh
go build -o /tmp/hestia ./cmd/hestia
/tmp/hestia -config snapshot.json -domain fi.lab.test
```

Идентификаторы выходов уникальны. Первая группа используется по умолчанию. Пустой домен обозначает соединение по IP с неизвестным именем. Отсутствующий в объекте `healthy` выход считается недоступным. Для примера команда выберет `fi2-out`. При недоступности обоих финских выходов она выберет `deny`. Оператор должен предварительно обеспечить блокировку пользовательских потоков и DNS этого выхода на уровне sing-box и Linux.

Каждый вызов применяет выбор ко всему селектору одной группы. Вызывайте команду последовательно и предоставьте ей исключительное управление соответствующим селектором. Повторный вызов уже установленного выбора только считывает состояние. Команда проверяет конфигурацию и состав выбранного селектора до записи. Ошибки проверки оставляют текущий выбор в силе. После записи команда повторно читает селектор. При ошибке связи после попытки записи фактическое состояние нужно уточнить повторным вызовом с актуальным снимком.

Успех подтверждается кодом 0 и JSON-записью с временем, группой, правилом, причиной и подтверждённым выбором селектора. Эта запись описывает решение контроллера. Фактический выход пользовательских пакетов проверяется отдельно по захватам стенда. При ошибке команда выдаёт диагностику в stderr и ненулевой код.

## Постоянная служба

Один процесс следит за файлом полного снимка. Поле `healthy` задаёт текущее состояние каждого выхода. Отсутствующий в нём выход считается недоступным. Поставщик данных записывает весь JSON во временный файл в том же каталоге и заменяет снимок через rename. Так служба видит целую версию файла. Само измерение состояния туннелей находится вне этой команды.

```sh
/usr/local/bin/hestia -watch -config /etc/hestia/snapshot.json -interval 1s
```

После запуска контроллер проверяет все группы. Затем при каждом опросе он перечитывает снимок и проверяет фактический выбор sing-box через GET для каждой группы. Команду PUT он посылает только при расхождении и подтверждает её повторным GET. Это также восстанавливает выбор после перезапуска sing-box. Обновления выполняются последовательно. При сбое одной группы контроллер продолжает с другими и повторяет сверку на следующем цикле. Тайм-аут на группу — 5 секунд. Интервал опроса не является гарантией времени переключения.

После первого подтверждения группы топология групп, выходов и доменных списков фиксируется до завершения процесса. Обновление доступности таких изменений не требует. При ошибочном снимке или недоступном файле служба сохраняет последний валидный снимок в памяти и продолжает сверку по нему. При холодном старте до появления пригодного снимка контроллер ждёт. Предварительная блокировка выхода `deny`, доменные правила и сетевые ограничения задаются в sing-box и Linux до запуска. Для изменения топологии согласуйте конфигурацию sing-box и выполните управляемый перезапуск службы. Селекторы должны иметь одного владельца.

Событие подтверждённой смены выбора попадает в stdout как JSON с группой, причиной `availability_snapshot`, исходом и целевым селектором. Начальное состояние также записывается. Ошибки попадают в stderr. Контроллер подавляет одинаковые повторяющиеся ошибки. При SIGTERM текущие запросы отменяются, процесс завершается.

## Установка

На Debian ARM64 используйте [установщик Гестии](../../docs/installer.md): он устанавливает обе службы и проверяет их взаимодействие. Ниже перечислены пути для ручной диагностики и стендов с собственной сетевой конфигурацией.

### Ручная установка unit-файла

Установите бинарник в `/usr/local/bin/hestia`, [unit-файл](../../deploy/systemd/hestia.service) в `/etc/systemd/system/hestia.service` и снимок по адресу `/etc/hestia/snapshot.json`. Каталог и файл должны быть доступны для чтения динамическому пользователю службы, а запись разрешена только владельцу снимка. Файл содержит идентификаторы групп, правила и доступность. Учётные данные туннелей хранятся отдельно.

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now hestia.service
journalctl -u hestia.service
```

API sing-box должен быть доступен по `127.0.0.1:9090` из сетевого пространства службы. Если шлюз находится в отдельном пространстве, добавьте `NetworkNamespacePath=/run/netns/<имя>` в секцию `[Service]` через systemd drop-in. Флаг `-domain` используется только в режиме однократного применения.
