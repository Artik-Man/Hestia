# Предложения по изменению API Гестии

Здесь собираем потребности интерфейса, которые действующий API пока не покрывает. Запись получает статус «К обсуждению». После решения владельца фиксируем согласованный объём и критерии приёмки в спецификации функции. Контракт и Angular-клиент генерируем при реализации из типов Go.

## API-01. Применение привязки доменного списка

**Статус — реализация операции на бэкенде.** Администратор хочет переназначить существующий список другой группе и узнать, с какого момента новые соединения используют эту группу. Для смены привязки нужно применить конфигурацию sing-box и получить подтверждение контроллера. [Спецификация и запуск](list-binding.md).

**Согласовано.** Для изменения привязки достаточно доступа к панели по её адресу. Доменный список можно привязать к одной группе подключений или оставить без группы. При переназначении меняется группа списка, все его маски сохраняются.

**HTTP-контракт.** Запрос на смену привязки завершается ответом `200 OK` с действующей привязкой после подтверждения контроллером, что новые соединения обрабатываются по обновлённому правилу. Получив этот ответ, интерфейс показывает «Применено». Проверка пути новым соединением входит в приёмочные испытания.

**Создание и редактирование.** Модальный редактор содержит название, группу и маски и позволяет подготовить новый список. Снимок API сейчас возвращает `id`, но не отдельное название; для этой формы потребуется разделить идентификатор и отображаемое имя. Предлагается единая атомарная операция полного списка с ожидаемой версией конфигурации, уникальным ID, названием, масками и nullable-группой. Она должна возвращать подтверждённые значения после применения к шлюзу, 409 для устаревшей версии и ошибки валидации с ограниченным списком полей. Создание использует ту же семантику; удаление в этот сценарий не входит. Требует согласования: остаётся ли `enabled` отдельной настройкой и входит ли она в редактор. Пока операции нет, UI хранит только помеченный локальный черновик и не меняет снимок. [Спецификация редактора](features/domain-lists-editor.md).

**Для следующей формы.** Обработать конфликт исходной группы (409) и отсутствие подтверждения применения (503). Предлагаемый критерий приёмки — успешное изменение подтверждается новым соединением по ожидаемому пути, а при отказе контроллер сохраняет последнюю рабочую конфигурацию.

Основание — [порядок загрузки снимка контроллером](../internal/controller/watch.go) и [этап редактирования правил](frontend-roadmap.md).

Кроме переназначения списка, дорожная карта предусматривает редактирование масок, изменение порядка групп и их выходов, смену группы по умолчанию и удаление группы. В снимке эти значения доступны для чтения. Перед проектированием записи нужно согласовать единицу изменения и условия отклонения конфликтующей правки. При удалении обычной группы списки и маски сохраняются без привязки. Удаление группы по умолчанию допускается только после назначения другой.

## API-02. Данные профиля подключения

**Статус — реализовано в рабочем дереве.** Типизированный API предоставляет временную проверку, создание, обновление, чтение и удаление WireGuard/AmneziaWG-профиля. Секретный конфиг не возвращается в публичной модели. Создание и обновление транзакционно проверяют и запускают выход, включают его в группу на заданной позиции и возвращают подтверждённое публичное состояние. Успешное сохранение меняет действующий путь выбранной группы; удаление также применяет и проверяет новый профиль. Форматирование, lint и сборка фронтенда проходят; code review закрыл замечания по форме.

**Граница доступа.** Эти операции пока не имеют аутентификации пользователя. Проверка `Host` и CORS-защита браузера предотвращают часть запросов с чужих сайтов, но не заменяют аутентификацию и не защищают от клиента, который уже имеет доступ к адресу панели. Панель должна слушать только конкретный loopback или частный LAN-адрес; не публикуйте её через WAN, публичный reverse proxy или внешний туннель. Для первой лабораторной проверки адрес панели считается доверенной домашней сетью. Перед внешним или недоверенным использованием потребуется отдельный механизм аутентификации и авторизации.

Можно хранить несколько проверенных профилей, но только один AWG/WireGuard-коннектор на экземпляр Гестии может быть активен (`ready`) одновременно. Создание/обновление активирует выбранный профиль и переводит ранее активный профиль в `configured`.

**Открытый блокер безопасности.** Панель передаёт полный `.conf`, включая приватный ключ, по HTTP. При перехвате трафика в LAN ключ можно раскрыть; до загрузки реального профиля нужен HTTPS для API и ресурсов панели либо транспорт, защищённый TLS до доверенного клиента. Это отдельное требование от аутентификации, которую Product Owner пока не требует.

**Осталось проверить.** Повторить независимый анализ ИБ после решения TLS; проверить выбор файла, оба формата `.conf` и успешный API-ответ на изолированном AWG-шлюзе; выполнить сетевой сценарий с резервным выходом и отказом туннеля. Для обновления профиля добавить ожидаемую версию/ETag и конфликт 409, чтобы параллельное редактирование не перезаписывало более свежие данные. Локальное preview не включает AWG API, поэтому на нём успешное сохранение не проверяется. Детали — в [спецификации коннектора](features/amneziawg-connector.md).

Основание — [требования к клиентским VPN-подключениям](requirements.md#клиентские-vpn-подключения).

## API-03. Журнал трафика

**Статус — к обсуждению.** Администратору нужны события новых потоков за выбранный период с поиском по домену или IP и фильтром протокола. Снимок конфигурации не содержит истории трафика. Для строки нужны время, назначение, выбранная группа, причина и наблюдаемый результат передачи или блокировки.

**Что решить.** Как запрашивать следующие записи при поступлении новых событий? Как отличать неподтверждённый выход от блокировки и связывать попытки DNS с потоком? Как получать и менять срок хранения? [Требования к журналу](monitoring.md).

## API-04. Карта стран

**Статус — к обсуждению.** Страница должна показывать привязки стран к группам, состав и порядок блоков и назначение для остального мира. В текущем снимке есть группы, но нет географических правил. Для просмотра нужен источник действующей карты. Для редактирования понадобится тот же порядок подтверждения применения, что для доменных правил. [Приоритеты GeoIP](requirements.md#карта-стран-geoip).

## API-05. Качество связи

**Статус — к обсуждению.** Статус доступности из снимка не показывает число проб, потери и причины переключений. Для сравнения выходов требуются время замера, цель, протокол, размер выборки и окно наблюдения. Следует определить источник истории и способ отличить полную потерю пакетов от отсутствия измерений. [План мониторинга](monitoring.md).

## API-06. DNS

**Статус — к обсуждению.** Для страницы DNS нужны действующие параметры кэша, порог частоты обращений, окно активности, интервал прогрева и сведения об именах, подходящих для обновления. Следует определить, какая служба подтверждает эти данные и применение новых настроек. [Требования к DNS-кэшу](requirements.md#долговременный-dns-кэш).

## Что требуется формам панели

Следующие записи описывают потребности фронтенда для последующего обсуждения. Операция смены привязки из API-01 уже доступна. Для остальных изменений локальный черновик в браузере не считается конфигурацией шлюза.

| Потребность | Что должен получить интерфейс | Что должна подтверждать операция |
|---|---|---|
| Группы и списки (API-01) | Действующие порядок групп и выходов, маски, связи, версия редактируемой конфигурации и возможность записи в установленном режиме. Для текущей привязки достаточно ожидаемой группы. | Сохранение масок, перестановка, выбор группы по умолчанию и удаление должны возвращать действующий результат. Определить, можно ли создавать и удалять списки, как проверять конфликты и какие изменения образуют одну операцию. |
| Профили (API-02) | Тип подключения WireGuard, поддержка импорта файла `.conf`, группа и приоритет, административное состояние, время и результат последней проверки. Секреты должны оставаться скрытыми при чтении и заменяться только явной операцией записи. | Создание, изменение, отдельная проба и включение профиля должны иметь различимые результаты. Определить формат и пределы `.conf`, область его проверки, связь результата пробы с версией профиля и конкретным выходом. |
| Журнал (API-03) | Стабильный идентификатор и время события, IP, домен при наличии, протокол, причина решения и результат передачи, связанная история DNS. Поиск и фильтр применяются ко всему выбранному периоду с постраничным чтением. | Чтение текущего срока хранения и изменение с подтверждением. Отличать пустую выдачу, отсутствие источника и потерю записей. |
| GeoIP (API-04) | Актуальная версия карты, справочник допустимых стран, собственные назначения, именованные упорядоченные блоки с составом, группа остального мира. | Атомарно принять изменения карты или сообщить об устаревшей версии. При известной стране учитывать её запись, затем первый подходящий блок, затем остальной мир. При неизвестной стране использовать группу по умолчанию. |
| Измерения (API-05) | Цели и типы проб, группы и выходы, период выборки, число попыток и потерь, задержка, время последней пробы, история смены выхода с причиной и областью действия. | Прочитать и изменить действующее окно оценки. Определить единицы времени, доступную глубину истории и поведение при недостаточной выборке. |
| DNS (API-06) | Действующие параметры хранения и выдачи при сбое, N/X/Y с единицами, перечень прогреваемых имён с типами записей и временем наблюдения. | Подтверждать изменение параметров и возвращать принятые значения. Для списка прогрева согласовать период обновления, лимиты выдачи и различение отсутствия активных имён и недоступной службы. |

Для источников истории нужно согласовать часовой формат, предел страницы и порядок продолжения чтения. Для каждой настройки нужны ограничения значений и ответ на конфликт с более свежей конфигурацией. После согласования типы задаются в Go и проходят существующий процесс генерации.

Для деталей потока API-03 нужны ID запроса DNS, имя и тип записи, адреса, выданные клиенту (включая FakeIP), время ожидания. По каждой попытке нужны резолвер, группа и выход, сетевое пространство и интерфейс, момент начала, длительность, источник (кэш или сеть), результат и адреса с TTL. Событие может не иметь связанного DNS-запроса. Поток с неизвестным доменом остаётся доступным в поиске по IP.

Для API-05 отдельно нужны исходы «ответ», «тайм-аут» и «ошибка измерителя». Общая отметка времени выборки позволяет сравнивать каналы в одном окне. Окно просмотра истории и действующее окно, по которому контроллер выбирает выход, задаются отдельно.

Для API-06 принадлежность имени к прогреву определяется по обращениям клиентов в заданном окне. Предлагаем получать домен, тип записи, выход, резолвер, число клиентских обращений, время последней успешной попытки и результат обновления. Список наблюдаемых имён может быть пустым при работающей службе.

### Особенности профилей

Пользователь согласовал отображаемый тип «WireGuard» и импорт файла `.conf`. Интерфейс читает файл только для передачи в типизированную проверку/сохранение; он не трактует параметры протокола. Backend отклоняет неизвестные директивы, проверяет диапазоны, безопасно сохраняет секрет отдельно и никогда не возвращает его в карточке профиля. Проверка — временная; подтверждённое сохранение запускает и включает один выбранный профиль как выход группы.

### Доступность операций

Текущий API позволяет попробовать применить привязку и получить 503, если панель запущена для просмотра или шлюз не подтвердил применение. Для будущих форм требуется договориться, как показать возможности конкретной установки заранее и как различить отключённую операцию, временный отказ службы, ошибку поля и конфликт версии. Модель доступа по адресу панели сохраняется.

### Сохранение порядка групп и подключений

Для сортировки реализована отдельная [операция применения полного порядка](group-order.md). Она сохраняет членство выходов, проверяет исходный порядок и возвращает подтверждённую конфигурацию. Для удаления группы и изменения состава остаются отдельные предложения API-01.
