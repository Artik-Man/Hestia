# Предложения по изменению API Гестии

Здесь собираем потребности интерфейса, которые действующий API пока не покрывает. Запись получает статус «К обсуждению». После решения владельца фиксируем согласованный объём и критерии приёмки в спецификации функции. Контракт и Angular-клиент генерируем при реализации из типов Go.

## API-01. Применение привязки доменного списка

**Статус — реализация операции на бэкенде.** Администратор хочет переназначить существующий список другой группе и узнать, с какого момента новые соединения используют эту группу. Для смены привязки нужно применить конфигурацию sing-box и получить подтверждение контроллера. [Спецификация и запуск](list-binding.md).

**Согласовано.** Для изменения привязки достаточно доступа к панели по её адресу. Доменный список можно привязать к одной группе подключений или оставить без группы. При переназначении меняется группа списка, все его маски сохраняются.

**HTTP-контракт.** Запрос на смену привязки завершается ответом `200 OK` с действующей привязкой после подтверждения контроллером, что новые соединения обрабатываются по обновлённому правилу. Получив этот ответ, интерфейс показывает «Применено». Проверка пути новым соединением входит в приёмочные испытания.

**Создание и редактирование.** Редактор передаёт название, группу и маски одной операцией. Сервер назначает постоянный идентификатор при создании и возвращает подтверждённый список. При изменении клиент передаёт исходное состояние открытого списка для проверки конфликта. Пустая группа снимает привязку. [Спецификация редактора](features/domain-lists-editor.md).

**Для следующей формы.** Обработать конфликт исходной группы (409) и отсутствие подтверждения применения (503). Предлагаемый критерий приёмки — успешное изменение подтверждается новым соединением по ожидаемому пути, а при отказе контроллер сохраняет последнюю рабочую конфигурацию.

Основание — [порядок загрузки снимка контроллером](../backend/internal/controller/watch.go) и [этап редактирования правил](frontend-roadmap.md).

Кроме переназначения списка, дорожная карта предусматривает редактирование масок, изменение порядка групп и их выходов, смену группы по умолчанию и удаление группы. В снимке эти значения доступны для чтения. Сохранение порядка и переносов реализовано [единым условным запросом](group-order.md); удаление — через `DELETE /api/groups/{id}` с проверкой текущей группы по умолчанию и отсутствия подключений. При удалении обычной группы списки и маски сохраняются без привязки. Удаление группы по умолчанию допускается только после назначения другой.

## API-02. Данные профиля подключения

**Статус — реализовано в рабочем дереве.** Типизированный API предоставляет временную проверку, создание, обновление, чтение и удаление WireGuard/AmneziaWG-профиля. Секретный конфиг не возвращается в публичной модели. Создание и обновление транзакционно проверяют и запускают выход, включают его в группу на заданной позиции и возвращают подтверждённое публичное состояние. Успешное сохранение меняет действующий путь выбранной группы; удаление также применяет и проверяет новый профиль. Форматирование, lint и сборка фронтенда проходят; code review закрыл замечания по форме.

**Граница доступа.** Эти операции пока не имеют аутентификации пользователя. Проверка `Host` и CORS-защита браузера предотвращают часть запросов с чужих сайтов, но не заменяют аутентификацию и не защищают от клиента, который уже имеет доступ к адресу панели. Панель должна слушать только конкретный loopback или частный LAN-адрес; не публикуйте её через WAN, публичный reverse proxy или внешний туннель. Для первой лабораторной проверки адрес панели считается доверенной домашней сетью. Перед внешним или недоверенным использованием потребуется отдельный механизм аутентификации и авторизации.

Можно хранить несколько проверенных профилей, но только один AWG/WireGuard-коннектор на экземпляр Гестии может быть активен (`ready`) одновременно. Создание/обновление активирует выбранный профиль и переводит ранее активный профиль в `configured`.

Это временное ограничение первой версии, а не целевая архитектура. Его нужно устранить, добавив динамические имена интерфейсов, отдельные таблицы и метки маршрутизации и fail-closed обработку для нескольких одновременно активных выходов.

**Открытый блокер безопасности.** Панель передаёт полный `.conf`, включая приватный ключ, по HTTP. При перехвате трафика в LAN ключ можно раскрыть; до загрузки реального профиля нужен HTTPS для API и ресурсов панели либо транспорт, защищённый TLS до доверенного клиента. Это отдельное требование от аутентификации, которую Product Owner пока не требует.

**Осталось проверить.** Повторить независимый анализ ИБ после решения TLS; проверить выбор файла, оба формата `.conf` и успешный API-ответ на изолированном AWG-шлюзе; выполнить сетевой сценарий с резервным выходом и отказом туннеля. Для обновления профиля добавить ожидаемую версию/ETag и конфликт 409, чтобы параллельное редактирование не перезаписывало более свежие данные. Локальное preview не включает AWG API, поэтому на нём успешное сохранение не проверяется. Детали — в [спецификации коннектора](features/amneziawg-connector.md).

Основание — [требования к клиентским VPN-подключениям](requirements.md#клиентские-vpn-подключения).

## API-03. Журнал трафика

**Статус — экран, хранилище и сбор событий sing-box реализованы.** `GET /api/traffic` возвращает события в порядке от новых к старым. Поиск по домену или IP, протокол, выход и обе границы времени применяются до разбиения на страницы. Ответ содержит общее число совпадений, выходы за период, состояние источника и счётчик известных потерь. Первая страница выдаёт `snapshot` с верхней границей последовательности событий. Следующие запросы передают этот маркер, прежние фильтры, `offset` и `limit` до 500. Обновление начинает новую выборку. Очистка по сроку или объёму может удалить старые записи во время просмотра.

`GET /api/traffic/settings` читает ограничения, `PUT /api/traffic/settings` принимает прочитанные настройки в `expected` и новые значения в `proposed`. При совпадении сохраняет объём в МБ и срок в часах и очищает устаревшие записи. Если настройки уже изменились, возвращает HTTP 409 и сохраняет историю. Источник sing-box сообщает о выборе выхода и блокировке. Связь с попытками клиентского DNS и наблюдение физического выхода требуют дополнительных источников. [Экран и границы наблюдения](features/traffic-journal.md) · [Проверка на ARM64](../experiments/traffic-journal/README.md).

## API-04. Карта стран

**Статус — к обсуждению.** Страница должна показывать состояние переключателя и ровно одну назначенную группу для каждой страны. В текущем снимке есть группы, но нет географических правил. Для просмотра нужен источник действующей карты. Для редактирования понадобится тот же порядок подтверждения применения, что для доменных правил. [Приоритеты GeoIP](requirements.md#карта-стран-geoip).

## API-05. Качество связи

**Реализовано в рабочем дереве.** `GET /api/quality` читает общие настройки проверок и все группы с их выходами в порядке выбора контроллером. Для каждого выхода ответ содержит доступность, признак подтверждённого активного выхода, баллы по проверкам и их среднее. Размер выборки, ответы и ошибки измерителя доступны отдельно для каждой проверки и каждой цели. Пустая выборка даёт балл `null`. Время снимка возвращается в `capturedAt` в формате RFC 3339. До первого отчёта, при отчёте старше минуты или после изменения настроек либо состава групп панель показывает текущую топологию с пустым `capturedAt` и неизвестными оценками.

`PUT /api/quality/settings` принимает весь набор проверок и окно в минутах. Каждая проверка задаёт протокол, цели в формате IP:порт, интервал и тайм-аут в секундах. Для UDP требуется имя для DNS-запроса. Код 200 подтверждает атомарную запись настроек и возвращает сохранённые значения. Контроллер публикует первые результаты с новыми параметрами при очередных измерениях. При некорректных параметрах сервер возвращает 422, при недоступности хранилища — 503. Настройки доступны на запись через тот же доверенный локальный адрес, что и другие изменяющие операции панели. Подробные типы и ограничения приведены в [контракте](../backend/api/openapi.yaml).

Редактор одной проверки использует `PUT /api/quality/checks/{protocol}`, подтверждение удаления — `DELETE /api/quality/checks/{protocol}`. Допустимы TCP, UDP, ICMP, DNS, HTTPS и HTTP3. Для ICMP цель задаётся IP-адресом, для остальных типов — адресом с портом. UDP и DNS используют поле dnsName. HTTPS и HTTP3 используют serverName для TLS и requestPath для GET. Операция `PUT /api/quality/window` принимает windowMinutes и меняет общий период оценки. Эти три операции возвращают сохранённые настройки. Одновременное сохранение разных проверок сохраняет обе правки.

## API-06. DNS

`GET /api/dns/policy` возвращает сохранённую ревизию, параметры кэша и прогрева, ручные домены и исключения. `PUT /api/dns/policy` принимает полную политику с `expectedRevision`. Ответ 200 содержит принятые значения. При конфликте ревизий панель получает 409 и предлагает пользователю перечитать политику. Ошибка параметров даёт 422, недоступность хранилища — 503. Сохранение подтверждает запись на диск. Состояние фонового процесса читается отдельно. [Контракт операций](../backend/api/openapi.yaml).

`GET /api/dns/warm` возвращает время наблюдения, ревизию прочитанной службой политики и автоматически отобранные домены с числом обращений клиентов. Служба также передаёт в необязательном объекте `clientUdp` три накопительных счётчика: число UDP-попыток `attempts`, попыток с последующим повтором `retriedAttempts` и попыток, для которых исчерпан лимит учёта, `unclassifiedAttempts`. Панель принимает и снимки прежней службы без этого объекта. Свежий снимок без подходящих имён содержит пустой массив. Панель возвращает 503, если файл снимка отсутствует, повреждён, датирован будущим или старше 15 секунд. Раздел использует отдельные пути панели `-dns-policy` (сохранённая политика) и `-dns-report` (снимок службы). [Поведение интерфейса](dns-settings.md).

## Что требуется формам панели

Таблица различает доступные операции и требования к следующим версиям. Запись настроек подтверждается ответом соответствующей операции шлюза.

| Потребность | Что должен получить интерфейс | Что должна подтверждать операция |
|---|---|---|
| Группы и списки (API-01) | Действующие порядок групп и выходов, маски, связи, версия редактируемой конфигурации и возможность записи в установленном режиме. Для текущей привязки достаточно ожидаемой группы. | Сохранение масок, перестановка, выбор группы по умолчанию и удаление должны возвращать действующий результат. Создание и редактирование списков реализованы. Удаление проверяет исходное состояние списка и возвращает подтверждение применения. |
| Профили (API-02) | Тип подключения WireGuard, поддержка импорта файла `.conf`, группа и приоритет, административное состояние, время и результат последней проверки. Секреты должны оставаться скрытыми при чтении и заменяться только явной операцией записи. | Создание, изменение, отдельная проба и включение профиля должны иметь различимые результаты. Определить формат и пределы `.conf`, область его проверки, связь результата пробы с версией профиля и конкретным выходом. |
| Журнал (API-03) | Стабильный идентификатор и время события, IP, домен при наличии, протокол, причина решения и результат передачи, связанная история DNS. Поиск и фильтр применяются ко всему выбранному периоду с постраничным чтением. | Чтение текущего срока хранения и изменение с подтверждением. Отличать пустую выдачу, отсутствие источника и потерю записей. |
| GeoIP (API-04) | Актуальная версия карты, справочник допустимых стран, признак включения, полное соответствие стран существующим группам. | Атомарно принять изменения карты или сообщить об устаревшей версии. При включённой карте использовать назначение известной страны. При неизвестной стране использовать группу по умолчанию. |
| Измерения (API-05) | Цели и типы проб, группы и выходы, период выборки, число попыток и потерь, задержка, время последней пробы, история смены выхода с причиной и областью действия. | Операции чтения оценок и сохранения параметров реализованы. История переключений и задержек остаётся отдельной задачей. |
| DNS (API-06) | Сохранённые параметры, ручные имена и исключения. Отдельный снимок содержит домены автоматического отбора, числа обращений, время и ревизию. | Реализованы запись по ожидаемой ревизии, ответ с подтверждёнными значениями и различение пустого снимка и недоступности наблюдений. |

Для источников истории нужно согласовать часовой формат, предел страницы и порядок продолжения чтения. Для каждой настройки нужны ограничения значений и ответ на конфликт с более свежей конфигурацией. После согласования типы задаются в Go и проходят существующий процесс генерации.

Для деталей потока API-03 нужны ID запроса DNS, имя и тип записи, адреса, выданные клиенту (включая FakeIP), время ожидания. По каждой попытке нужны резолвер, группа и выход, сетевое пространство и интерфейс, момент начала, длительность, источник (кэш или сеть), результат и адреса с TTL. Событие может не иметь связанного DNS-запроса. Поток с неизвестным доменом остаётся доступным в поиске по IP.

Для API-05 отдельно нужны исходы «ответ», «тайм-аут» и «ошибка измерителя». Общая отметка времени выборки позволяет сравнивать каналы в одном окне. Окно просмотра истории и действующее окно, по которому контроллер выбирает выход, задаются отдельно.

В API-06 пока отсутствуют детали отдельных попыток прогрева по типу записи, выходу и резолверу. Их можно добавить для диагностики вместе с временем и результатом последнего обновления.

### Особенности профилей

Пользователь согласовал отображаемый тип «WireGuard» и импорт файла `.conf`. Интерфейс читает файл только для передачи в типизированную проверку/сохранение; он не трактует параметры протокола. Backend отклоняет неизвестные директивы, проверяет диапазоны, безопасно сохраняет секрет отдельно и никогда не возвращает его в карточке профиля. Проверка — временная; подтверждённое сохранение запускает и включает один выбранный профиль как выход группы.

### Доступность операций

Текущий API позволяет попробовать применить привязку и получить 503, если панель запущена для просмотра или шлюз не подтвердил применение. Для будущих форм требуется договориться, как показать возможности конкретной установки заранее и как различить отключённую операцию, временный отказ службы, ошибку поля и конфликт версии. Модель доступа по адресу панели сохраняется.

### Сохранение порядка групп и подключений

Для сортировки реализована отдельная [операция применения полного порядка](group-order.md). Она сохраняет членство выходов, проверяет исходный порядок и возвращает подтверждённую конфигурацию. Для удаления группы и изменения состава остаются отдельные предложения API-01.
