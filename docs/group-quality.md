# Выбор основного выхода по нескольким целям

Эксперимент проверяет два разных повода для потери ответа. Если FI-1 доставляет пробы хуже FI-2 сразу до нескольких независимых целей, основной выход группы для новых потоков должен перейти на FI-2. Если одна цель перестаёт отвечать по обоим путям, а другая остаётся доступной, группа сохраняет текущий выход. Критерий проверяем на клиентском адресе, который не участвует в измерениях.

На стенде рассматриваем одну группу с двумя выходами и минимум два разных IPv4-адреса контрольных серверов. Пробы TCP и UDP до одного IP не дают двух независимых голосов. Для смены выхода нужны согласованные результаты по разным адресам. Равенство, противоречивые или недостаточные данные сохраняют выбор. Возврат на прежний выход требует измеренного преимущества. Пороговые параметры стенда требуют отдельного подбора для реальных провайдеров.

Проверяем фактические новые TCP- и UDP-потоки через захваты на обоих путях. Сопоставляем с ними измерения, смену селектора и причину решения. Отдельно проверяем, что отказ одного контрольного сервера через оба пути не блокирует исправную группу. Испытания используют изолированную ВМ hestia-dynamic.

Экспериментальный режим запускается через `hestia balance`. Для опыта доступность выходов задана заранее. Пока команда владеет селектором, перед административным изменением группы её нужно остановить. Для эксплуатации требуется общий порядок применения доступности, блокировки и измерений.
