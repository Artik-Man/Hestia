# Качество связи подключений

Карточки в разделе «Качество связи» задают проверки для всех подключений, включая резервные. Карандаш на карточке открывает модальное окно только выбранной проверки. В нём можно изменить цели, интервал, тайм-аут и специфичные для этой проверки поля. «Сохранить» применяет параметры ко всем подключениям, «Отмена» закрывает окно. Кнопка добавления открывает форму соответствующего типа. Корзина запрашивает подтверждение удаления одной проверки. Общее окно оценки, изначально 60 минут, редактируется отдельно.

| Проверка | Условие успешной пробы |
|---|---|
| TCP | Установилось TCP-соединение с заданным IP и портом. |
| UDP | Пришёл соответствующий запросу ответ DNS по UDP от одного из двух заданных резолверов. Даже SERVFAIL подтверждает состоявшийся обмен. |
| ICMP | С заданного IP получен Echo Reply с идентификатором, номером и данными отправленного запроса. Для SOCKS-выходов нативного WireGuard raw ICMP недоступен. При включённом ICMP на таком подключении полная оценка недоступна. |
| DNS | Указанный резолвер разрешил контрольное имя в адрес IPv4. Учитываются цепочки CNAME. При усечённом ответе шлюз повторяет запрос по TCP через тот же выход к тому же резолверу. Ошибочный код DNS означает неуспех проверки. |
| HTTPS | Шлюз подключился к заданному IP и порту по TCP, проверил сертификат для настроенного имени сервера и получил HTTP 2xx на GET по указанному пути. |
| HTTP/3 | Тот же сценарий запроса к сервису выполнен через QUIC по UDP с проверкой TLS и ответом HTTP/3 2xx. |

В начальной конфигурации включены TCP и UDP с интервалом 30 секунд и тайм-аутом 3 секунды. Цели по умолчанию — 1.1.1.1 и 8.8.8.8, для DNS-датаграммы используется A-запрос для example.com. Дополнительные проверки включаются явно, чтобы администратор выбрал сервисы для своей сети. Все включённые типы участвуют в среднем с одинаковым весом. При совместном включении UDP и DNS один успешный обмен и одно правильное разрешение имени оцениваются как разные операции.

В таблице каждой группы балл проверки равен проценту успешных завершённых обменов. Полученный SERVFAIL подтверждает доставку DNS-ответа и учитывается отдельно как ошибка DNS. Истёкший тайм-аут входит в знаменатель. Ошибка локальной настройки сокета исключается из расчёта. При 990 успешных TCP-пробах из 1000 и 98 успешных UDP-пробах из 100 общий балл равен 98,5. Если хотя бы одна настроенная проверка ещё не дала результата или список проверок пуст, общий балл недоступен.

Контроллер сначала рассматривает доступные выходы, затем сравнивает общие баллы. При равенстве сохраняет действующий выход. Для перевода с доступного выхода текущая реализация требует полного результата на обоих выходах и преимущества кандидата на двух различных IP с тремя или более завершёнными пробами по каждой сравниваемой паре. Это стартовый порог для испытаний. При недостаточной выборке строка с лучшим баллом может оказаться выше фактически активного подключения. Недоступность действующего выхода вызывает обычный перевод на доступный резерв. При потере всей группы контроллер выбирает блокировку.

Измеритель работает в службе hestia в режиме `-watch -quality`. Для прямых и управляемых WireGuard-подключений сокет привязывается к интерфейсу и использует маршрутную метку выхода, если она задана. Для нативных пользовательских WireGuard-выходов sing-box компилятор создаёт локальные SOCKS-порты с индивидуальной аутентификацией. Подтверждение выбора поступает из селектора. Панель читает отчёт через GET /api/quality. Сохранение и удаление затрагивают только выбранную проверку. Окно оценки имеет свою операцию API. Настройки переживают перезапуск. После перезапуска контроллера или изменения параметров проверки для неё набирается новая выборка.

При проверке безопасности 5 ноября 2026 года команда ограничила сетевые цели публичными адресами и проверила границы диапазона CGNAT, специальные диапазоны IPv4 и адреса IPv6 с вложенным IPv4. SOCKS-порты слушают loopback и требуют пароль, а файл с паролями доступен только службе измерителя. Учёт за длинное окно использует накопительные счётчики и компактное хранение завершённых проб. Допустимую нагрузку при максимальной частоте ещё предстоит проверить на целевом устройстве. Для новой зависимости `golang.org/x/net` выбрана версия v0.62.0. Запрос OSV для этой версии от 5 ноября 2026 года вернул пустой список уязвимостей.

Шлюз проверяет адреса целей при сохранении. Для защиты памяти шлюза бюджет окна ограничен 32 768 наблюдениями на одно подключение. Если выбранные частота, число целей и окно превышают бюджет, увеличьте интервал или сократите окно. При единственной цели сравнить два независимых IP для смены работающего выхода невозможно.
