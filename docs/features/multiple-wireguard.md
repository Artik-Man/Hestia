# Несколько одновременных подключений WireGuard и AmneziaWG

Спецификация согласована 4 ноября 2026 года. До изменения runtime использовал фиксированный awg0 (internal/awg/runtime_service_linux.go); deploy/profile.py привязывал выходы к нему и разрешал максимум один ready. Простое удаление проверки оставит выходы на одном интерфейсе.

За ID подключения сохраняется номер N от 0 до 49, выделяемый под блокировкой установки. Ему соответствуют интерфейс `awgN`, метка `0x202 + N`, таблица `202 + N` и приоритет `1002 + N`. Диапазон таблиц заканчивается на 251 и не заходит в зарезервированные системные таблицы Linux. Из номера определяются имя интерфейса, метка, таблица и приоритет правил. Имя профиля, группа и позиция на них не влияют. При конфликте с чужим ресурсом операция завершается с диагностикой без изменения этого ресурса. Номер освобождается только после удаления принадлежащих подключению ресурсов.

Каждому включённому профилю соответствует экземпляр runtime со своим интерфейсом, секретом, состоянием здоровья и защитой маршрутов IPv4/IPv6. Выход sing-box использует интерфейс и метку этого профиля; внешний UDP идёт обычным маршрутом шлюза. Отмеченный трафик при потере интерфейса блокируется. Выбор другого доступного выхода остаётся решением политики группы. Обновление или удаление одного профиля не перезапускает соседний туннель. После перезагрузки назначения восстанавливаются: на Keenetic supervisor сначала запускает восстановление сохранённых AWG-профилей, затем запускает маршрутизатор и контроллер. Если восстановить профили не удалось, маршрутизация не запускается. При обновлении установки первый действующий профиль сохраняет awg0 и прежние сетевые параметры; сохранённые неактивные профили автоматически не включаются.

В «Подключениях» администратор импортирует второй профиль как первый, без ручного выбора интерфейса или таблицы. У каждого подключения свой статус и своя ошибка. Ready требует проверки выхода через соответствующий туннель.

Критерии приёмки на отдельной изолированной Linux-ВМ:

1. Два независимых профиля с пересекающимися AllowedIPs (включая default) одновременно готовы. Из двух групп наблюдается трафик на двух ожидаемых peer; основной маршрут шлюза не меняется.
2. Остановка, неудачное обновление и удаление второго профиля не прерывают контрольный поток первого. При остановке без разрешённого запасного выхода трафик второго не уходит напрямую ни по IPv4, ни по IPv6.
3. Перезагрузка восстанавливает оба назначения. Параллельный импорт не выдаёт один номер дважды; сбой применения не оставляет частично включённого выхода.
4. Обновление с одним активным awg0 сохраняет его привязку к группе. Панель показывает результаты для каждого профиля отдельно, без секретов.

**Проверено на Linux ARM64:** обычный WG и AmneziaWG с совпадающими внутренними адресами работают одновременно. Каждая из двух групп sing-box получила ответ нужного VPN-сервера через собственный DNS. Открытое соединение первой группы пережило остановку, неудачный запуск и восстановление второго туннеля. При недоступном втором туннеле проверены блокировка IPv4 и IPv6 и отсутствие запрещённых пакетов на обычном сетевом интерфейсе. [Протокол и порядок воспроизведения](../../experiments/awg-multi/README.md).

**Границы результата:** замена ключа или адреса без изменения конфигурации прокси оставляет общий sing-box запущенным, если подтверждены защитные правила обоих семейств IP. Добавление и удаление выхода меняют конфигурацию прокси: соседний туннель сохраняется, но открытые через прокси TCP-сессии могут оборваться. В этой части критерий 2 не выполнен полностью. Перенос действующего профиля в слот 0, откат и запуск после перезагрузки проверены автоматическими тестами; миграция работающего awg-home впоследствии [подтверждена на stage1](../../experiments/awg-multi/evidence/stage1-update.txt). Перезагрузка ВМ остаётся непроверенной.
