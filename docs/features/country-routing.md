# Маршрутизация по стране назначения

## Цель

Администратор может включить маршрутизацию новых соединений по стране IP-адреса назначения, назначив каждой стране существующую группу подключений. Явное доменное правило имеет приоритет; для неизвестной страны используется группа по умолчанию. Базовые требования описаны в разделе [«Карта стран GeoIP»](../requirements.md#карта-стран-geoip), фактические проверки — в [отчёте country-routing](../../experiments/country-routing/README.md).

## Подтверждённое поведение

- Карта выключена по умолчанию; при её первом создании всем странам назначается текущая группа по умолчанию.
- Для каждой страны справочника хранится ровно одна существующая группа. Изменение группы по умолчанию не переназначает страны.
- Карта вместе с признаком включения сохраняется как единая версия политики. Если кандидат не проходит проверку, применяется прежняя конфигурация.
- Для новых соединений доменное правило имеет приоритет над GeoIP. При выключенной карте или неизвестной стране используется группа по умолчанию.
- Для трафика Keenetic `hestia-keenetic-ingress` применяется тот же порядок: доменное правило, страна назначения, затем безопасная группа по умолчанию. Целевые группы могут использовать готовые AWG/Hysteria2 без рекурсивного underlay и прямой `keenetic-uplink`, только если он привязан к проверенному текущему WAN. Невалидный кандидат не публикуется.

## Исправление сохранения на Keenetic — проект критериев

**Статус: критерии согласованы Product Owner 11 ноября 2026 года; исправление установлено и сохранение подтверждено на KN-1012.**

1. На поддерживаемом Keenetic-комплекте с установленными данными GeoIP включение переключателя «Выбирать группу по стране назначения» и сохранение завершаются подтверждённым успехом. После повторной загрузки страницы переключатель остаётся включённым.
2. Если сохранение завершилось ошибкой, интерфейс переходит в конечное состояние, сохраняет черновик для повторной попытки и показывает понятное сообщение. Он не остаётся в состоянии «Сохраняем…» бесконечно.
3. Существующие назначения стран, резервная группа по умолчанию, приоритет явного доменного правила и откат невалидной транзакции остаются без изменений.

На KN-1012 повторный `PUT /api/country-map` вернул HTTP 503 `Применение изменения не подтверждено`; readback подтвердил, что политика не изменилась. Журнал panel показал `managed service operation failed: smoke` перед ответом. Controller log сначала записал для группы переход в `deny`, затем примерно через секунду — на доступный Hysteria exit. Первая версия исправления повторяла проверку selector до пяти секунд, но запись всё ещё завершалась тем же 503. Это показало, что новая генерация может менять ожидаемый selector вместе со свежими health/quality данными; проверка сравнивала live selector и события controller с одним устаревающим снимком. Уточнённый фикс перечитывает quality report на протяжении окна сходимости и ждёт, пока live selector и подтверждённые controller events совпадут с текущей целью. Устойчивое несовпадение по-прежнему отклоняется. Предыдущее сообщение `src_valid_mark` относилось к другому endpoint и этим отказом не подтверждено.

Уточнённый IPK установлен на KN-1012. `PUT /api/country-map` вернул HTTP 200; последующий GET и сохранённый controller snapshot подтвердили `enabled=true` и все 249 назначений. После перезагрузки страницы переключатель оставался включённым, кнопка сохранения была неактивна, назначения не изменились. Supervisor и `smoke-current` готовы, default route hashes не изменились. Перезагрузка Keenetic и сквозной country routing клиентского трафика отдельно не проверялись.

## Проверки после согласования

- Регрессионная проверка подтверждает, что сохранение включённой карты успешно публикует политику и её состояние переживает повторное чтение.
- Негативная проверка подтверждает откат невалидной конфигурации и конечное состояние интерфейса с сохранённым черновиком.
- Linux-only тесты подтверждают, что краткий переход селектора допускается после сходимости, а устойчивое несовпадение по-прежнему отклоняется.
- Приёмочная проверка на изолированном поддерживаемом Keenetic подтверждает включение, сохранение и повторное чтение настройки. До такой проверки фактическое применение GeoIP на клиентском трафике не считается подтверждённым.
