# Редактор доменных списков

## Поведение интерфейса

На странице «Доменные списки» кнопка «Создать список» оформлена директивой PrimeNG `pButton` и открывает PrimeNG Dialog с пустыми полями. Нажатие на название существующего списка открывает это же окно с текущими значениями. Окно, подложку и элементы формы оформляет стандартная светлая тема PrimeNG Aura. Поля: название, группа (включая «Группа не назначена») и маски — по одной на строку; применяются PrimeNG InputText, Select и Textarea. Иконка info рядом с полем масок открывает PrimeNG Popover при наведении или фокусе; задержка закрытия позволяет перевести указатель с иконки на вынесенную popover-панель, а повторное наведение отменяет закрытие. Popover располагается поверх PrimeNG Dialog. Касание и щелчок также открывают popover. Некорректные маски показывают ошибку и запрещают сохранение.

«Сохранить» отправляет название, группу и маски на шлюз одной операцией. Пустая группа снимает привязку. Название должно быть уникальным, до 80 символов. Список может содержать до 1024 масок. Шлюз применяет профиль и возвращает сохранённый список. Пока идёт запрос, повторное нажатие недоступно. При ошибке редактор остаётся открыт с введёнными значениями.

В каждой строке карандаш открывает редактор выбранного списка. Корзина открывает диалог с названием списка и действиями «Отмена» и «Удалить». Отмена закрывает диалог без запроса. Удаление убирает список и его правила со шлюза после проверки исходного состояния. Обе кнопки имеют доступные имена с названием списка.

## Контракт масок в текущей модели

Поддерживается DNS-имя с обязательным префиксом `*.` и ASCII DNS-метками, например `*.example.org` и `*.deep.example.org`. Суффикс охватывает сам домен и поддомены любой глубины. Пустые строки игнорируются. Порядок строк не влияет на приоритет. Ограничения согласованы с `docs/requirements.md` и валидатором `frontend/src/domain-lists.ts`.

## Операция шлюза

При создании шлюз выдаёт постоянный идентификатор. Переименование сохраняет этот идентификатор и ссылки на список. Старые списки без отдельного названия отображаются под своим ID. Привязка к группе определяет, активен ли список.

При редактировании клиент вместе с изменениями передаёт исходный список, который видел при открытии формы. Шлюз сверяет его под блокировкой записи. Если другой пользователь уже изменил список, запрос завершается конфликтом и сохраняет чужие изменения. Успешный ответ содержит действующие значения после подтверждения применения. Ошибка проверки или применения не должна частично сохранить поля.

### Запросы панели

| Запрос | Тело | Успешный ответ |
|---|---|---|
| `POST /api/domain-lists` | `{"name":"Новости","group":"","masks":["*.example.org"]}` | `201` и сохранённый список с назначенным ID |
| `DELETE /api/domain-lists/{id}` | Исходный список из снимка | `204` после применения удаления |
| `PUT /api/domain-lists/{id}` | `expected` — исходный список из снимка, `list` — новые значения в формате создания | `200` и сохранённый список с прежним ID |

Неизвестный список или группа дают `404`, конфликт текущего состояния — `409`, недопустимые поля — `422`. Операции записи включает флаг панели `-enable-domain-lists` с установленным снимком `/etc/hestia/snapshot.json`. Панель с отключённой записью возвращает `503`. Изменения профиля проходят через ту же транзакцию установки, что и смена привязки. Применение правил перезапускает sing-box и контроллер. Если конфигурация AWG прежняя, сохранение списка и откат этой операции должны сохранять работающий туннель и его маршруты. Пока запись держит блокировку, чтение снимка может вернуть временный ответ `503`.

## Критерии приёмки UI

1. Создание открывает пустую форму, редактирование по нажатию на список — заполненную. В обоих случаях окно отображается по центру поверх затемнённой страницы. Escape закрывает окно, и фокус возвращается к кнопке, открывшей редактор.
2. Название, группа и маски доступны для редактирования; группа содержит все группы текущего снимка и вариант без группы.
3. Наведение, фокус или нажатие на `info` раскрывает примеры масок поверх PrimeNG Dialog; popover доступен с клавиатуры.
4. Маски проверяются до сохранения; ошибка указывает некорректные строки.
5. После создания список появляется в таблице и доступен после перезагрузки страницы. Редактирование обновляет ту же строку.
6. При конфликте или отказе шлюза форма показывает ошибку и сохраняет введённые значения. «Отмена» закрывает форму без записи.

## Проверка API и интерфейса

Тест транзакции использует рабочий компилятор профиля и временные файлы. Он проверяет правило sing-box с новой маской, повторное создание, редактирование старого списка без названия, конфликт и побайтовое восстановление файлов после ошибки применения. Внешние службы маршрутизации в этом тесте заменены тестовыми обработчиками.

Браузерный тест проверяет запросы формы через собранную панель с тестовыми HTTP-ответами. Он покрывает перезагрузку после сохранения, сохранность ввода при конфликте и отказ от неполного подтверждения шлюза.

## История проверок локального прототипа

**Проверка ИБ, 4 ноября 2026 года.** Подтверждённых находок нет. Черновик хранится в состоянии компонента, не отправляется на шлюз и отображается через Angular bindings. Это статическая проверка без запуска тестов, сканеров и браузера. Повторная проверка обязательна при добавлении API записи.

**Ревью кода, 4 ноября 2026 года.** В первом проходе обнаружено, что модальному окну не задано доступное имя. Исправление повторно проверено по исходнику: `<dialog>` ссылается через `aria-labelledby="list-editor-title"` на заголовок `h2` с тем же ID. Заголовок условно отображается для обоих режимов и меняет текст между «Новый список» и «Изменить список», поэтому доступное имя задано в обоих случаях. Замечание закрыто. Проверка статическая; браузерные действия не проводились.

**Проверка PrimeNG-элементов ИБ, 4 ноября 2026 года.** Подтверждённых находок нет. Popover статичен, обработчики меняют только локальное состояние интерфейса, зависимостей и API-записей не добавлено. Проверка статическая; тесты, браузер и сканеры не запускались. Повторить при появлении серверного сохранения списков.

**Ревью PrimeNG-контролов, 4 ноября 2026 года.** Замечание DL-PRIME-01: компонент PrimeNG переносит overlay в `body`, поэтому немедленное закрытие по `mouseleave` не давало перейти от иконки к панели. Исправлена задержка закрытия 350 мс и её отмена при наведении на содержимое и возврате к иконке. Повторная статическая проверка подтвердила обработчики и классы стилей. В браузере также обнаружено, что нативный `<dialog>` помещал popover под верхний слой, несмотря на изменившийся `aria-expanded`. Редактор переведён на PrimeNG Dialog; popover получил более высокий базовый z-index. Ожидается повторная проверка в браузере после сборки.

**Состав элементов UI.** Для редактора используются компоненты PrimeNG: Dialog, Button, InputText, Select, Textarea и Popover. Нативный `<dialog>`, `<select>` и `<textarea>` не используются.
