# Редактор доменных списков

## Поведение интерфейса

На странице «Доменные списки» кнопка «Создать список» оформлена директивой PrimeNG `pButton` и открывает PrimeNG Dialog с пустыми полями. Нажатие на название существующего списка открывает это же окно с текущими значениями. Поля: название, группа (включая «Группа не назначена») и маски — по одной на строку; применяются PrimeNG InputText, Select и Textarea. Иконка info рядом с полем масок открывает PrimeNG Popover при наведении или фокусе; задержка закрытия позволяет перевести указатель с иконки на вынесенную popover-панель, а повторное наведение отменяет закрытие. Popover располагается поверх PrimeNG Dialog. Касание и щелчок также открывают popover. Некорректные маски показывают ошибку и запрещают сохранение.

Пока шлюз не предоставляет API создания и изменения списка, «Сохранить черновик» сохраняет значения только в состоянии страницы и помечает их как локальный черновик. Он не вызывает API, не меняет показанный снимок шлюза и не означает, что новые потоки используют эти значения. Закрытие и повторное открытие модального окна не теряет черновик; повторная загрузка страницы его сбрасывает.

## Контракт масок в текущей модели

Поддерживается DNS-имя с обязательным префиксом `*.` и ASCII DNS-метками, например `*.example.org` и `*.deep.example.org`. Суффикс охватывает сам домен и поддомены любой глубины. Пустые строки игнорируются. Порядок строк не влияет на приоритет. Ограничения согласованы с `docs/requirements.md` и валидатором `frontend/src/masks-draft.ts`.

## Операция шлюза

Текущий API читает `id`, `masks`, `group`, `enabled` и позволяет отдельно менять только `group` для существующего списка. Поэтому единый Save редактора пока является локальным действием. Требуемую серверную атомарную запись с проверкой актуальной версии, результатом применения и конфликтом фиксируем в [предложениях API](../api-proposals.md#api-01-применение-привязки-доменного-списка).

## Критерии приёмки UI

1. Создание открывает пустую форму, редактирование по нажатию на список — заполненную.
2. Название, группа и маски доступны для редактирования; группа содержит все группы текущего снимка и вариант без группы.
3. Наведение, фокус или нажатие на `info` раскрывает примеры масок поверх PrimeNG Dialog; popover доступен с клавиатуры.
4. Маски проверяются до сохранения; ошибка указывает некорректные строки.
5. Сохранённый черновик виден в таблице как черновик и остаётся там при закрытии/повторном открытии модального окна.
6. Ни создание, ни сохранение черновика не посылают запрос и не изменяют снимок шлюза.

## Независимые проверки

**Проверка ИБ, 4 ноября 2026 года.** Подтверждённых находок нет. Черновик хранится в состоянии компонента, не отправляется на шлюз и отображается через Angular bindings. Это статическая проверка без запуска тестов, сканеров и браузера. Повторная проверка обязательна при добавлении API записи.

**Ревью кода, 4 ноября 2026 года.** В первом проходе обнаружено, что модальному окну не задано доступное имя. Исправление повторно проверено по исходнику: `<dialog>` ссылается через `aria-labelledby="list-editor-title"` на заголовок `h2` с тем же ID. Заголовок условно отображается для обоих режимов и меняет текст между «Новый список» и «Изменить список», поэтому доступное имя задано в обоих случаях. Замечание закрыто. Проверка статическая; браузерные действия не проводились.

**Проверка PrimeNG-элементов ИБ, 4 ноября 2026 года.** Подтверждённых находок нет. Popover статичен, обработчики меняют только локальное состояние интерфейса, зависимостей и API-записей не добавлено. Проверка статическая; тесты, браузер и сканеры не запускались. Повторить при появлении серверного сохранения списков.

**Ревью PrimeNG-контролов, 4 ноября 2026 года.** Замечание DL-PRIME-01: компонент PrimeNG переносит overlay в `body`, поэтому немедленное закрытие по `mouseleave` не давало перейти от иконки к панели. Исправлена задержка закрытия 350 мс и её отмена при наведении на содержимое и возврате к иконке. Повторная статическая проверка подтвердила обработчики и классы стилей. В браузере также обнаружено, что нативный `<dialog>` помещал popover под верхний слой, несмотря на изменившийся `aria-expanded`. Редактор переведён на PrimeNG Dialog; popover получил более высокий базовый z-index. Ожидается повторная проверка в браузере после сборки.

**Состав элементов UI.** Для редактора используются компоненты PrimeNG: Dialog, Button, InputText, Select, Textarea и Popover. Нативный `<dialog>`, `<select>` и `<textarea>` не используются.
