# Версия и целевая платформа в панели

## Цель

Показывать в шапке панели версию приложения вместе с целевой платформой сборки, чтобы администратор мог отличить Linux-комплект для виртуальной машины от Keenetic-комплекта.

## Предлагаемое поведение

- Базовая версия берётся из единого источника версии панели — `frontend/package.json`.
- Комплект `linux-arm64` получает метку `vm`; панель показывает, например, `0.1.2-vm`.
- Комплект `keenetic-arm64-experimental` получает метку `keenetic`; панель показывает, например, `0.1.2-keenetic`.
- Обе платформы используют одну базовую версию в рамках одной сборки.
- Метка платформы задаётся сборщиком для каждой платформы отдельно; готовые frontend assets не разделяются между комплектами.
- `npm run build` без платформенной настройки сохраняет базовое отображение версии без суффикса, чтобы обычная локальная сборка не заявляла целевую платформу.
- Формат манифестов, имена комплектов и версии пакетов не меняются.

## Согласованные критерии приёмки

1. В браузере из Linux-комплекта рядом с логотипом отображается `<версия>-vm`.
2. В браузере из Keenetic-комплекта рядом с логотипом отображается `<версия>-keenetic`.
3. Обе панели показывают одну и ту же базовую версию из `frontend/package.json`.
4. Сборка frontend без платформенного параметра показывает только базовую версию.
5. Проверка сборки подтверждает, что в каждый комплект помещены assets именно его платформы.

## Границы

Изменение касается только подписи в шапке панели и передачи платформенной метки при упаковке frontend assets. Оно не меняет версию IPK или комплектов, API, backend runtime и правила публикации.

## План реализации после согласования

1. Добавить типизированную конфигурацию платформы frontend с допустимыми значениями `vm` и `keenetic` и без суффикса для стандартной локальной сборки.
2. Собирать frontend отдельно для каждого платформенного комплекта и копировать соответствующие assets.
3. Проверить собранные assets обоих комплектов и стандартной локальной сборки.
4. Обновить документацию сборки и выполнить форматирование, линтинг и применимые проверки.
