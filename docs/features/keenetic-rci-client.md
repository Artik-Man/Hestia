# Клиент Keenetic RCI для экспериментов и Go-коннекторов

Согласовано Product Owner 7 ноября 2026 года: создать переиспользуемый клиент аутентификации для исследовательских запросов и Go-клиент, на котором работает read-only Ethernet-коннектор. Проверенная точка входа — локальный JSON RCI `127.0.0.1:79`; удалённые исследования достигают её временным SSH-туннелем. Токен передаётся в `X-NDMA-TKN` и читается из защищённого источника.

## Область и контракты

- Общий Go-клиент и Ethernet-коннектор находятся в `backend/pkg/keeneticrci`; исследовательские команды размещаются в `backend/cmd/`. Эксперименты и продуктивные коннекторы используют одну реализацию аутентификации и HTTP-транспорта.
- `Client.ReadVersion` разбирает `GET /rci/show/version` в `RouterVersion`, включая JSON-ключ `arch`; неполный или неверного типа ответ отклоняется как ошибка схемы. Установочный preflight использует общий тип вместо локальной копии структуры.
- Клиент принимает фиксированный base URL, `TokenSource` и именованную операцию; Ethernet-коннектор вызывает только `GET /rci/show/interface` и преобразует подтверждённые поля в типизированные Ethernet-порты.
- Клиент отправляет токен только на настроенный адрес. Он не следует HTTP redirects и не использует ambient proxy. Незащищённый HTTP допускается только к loopback; удалённый endpoint требует HTTPS.
- Ответы ограничены размером: стандартный предел — 2 MiB, абсолютный предел настройки — 16 MiB. Тело запроса ограничено 1 MiB. Клиент принимает только успешный HTTP-статус и JSON Content-Type, валидирует JSON до выдачи вызывающему коду и возвращает отдельную категорию для превышения request limit. Ошибки не содержат токен или тело ответа.
- Парсер `show/interface` ограничивает обход дерева глубиной 32 уровня и 16 384 JSON-узлами. Превышение лимита приводит к ошибке схемы без частичного инвентаря; JSON-фрагменты обрабатываются без промежуточного копирования в строку.
- Общий `DescribeSchema` для Go-экспериментов описывает bounded JSON без scalar values и произвольных ключей; для неразрешённых имён он выводит только число и уникальные формы вложенных значений. Один обход ограничен глубиной 8 и 256 узлами; массивы и объекты, чья ветвь превышает оставшийся лимит, отклоняются до обхода детей/сортировки ключей. Вложенная RCI ошибка отклоняется в том же обходе.
- Классификация операции по эффекту не выводится из HTTP-метода: в RCI `POST /rci/show` запускает read-only show-команды и принимает JSON-параметры. Клиент разрешает такой `POST` только при `changes_state=false`, валидном JSON и точном пути `/rci/show`. Остальные state-changing `POST` требуют `changes_state=true` и отдельного `AllowWrites`; произвольный shell/CLI интерфейс не предоставляется.
- Токен из файла читается при каждом запросе; файл должен быть обычным, принадлежать текущему пользователю и не иметь прав доступа для группы/остальных. Файл открывается с `O_NOFOLLOW|O_NONBLOCK`, чтобы не принять симлинк или FIFO при подмене пути между проверкой и открытием. Токен не включается в командную строку, stdout, журнал или свидетельства.

## Критерии приёмки

1. Конфигурация выбирает адрес и источник токена независимо; ошибка одного endpoint не переключает запрос на другой.
2. `GET /rci/show/interface` с проверенным токеном возвращает JSON; Ethernet-коннектор отбирает только записи `type=Port` с ID `GigabitEthernetN/M`, дедуплицирует повторы и возвращает ID, link и доступные speed/duplex.
3. Неизвестное значение link, конфликтующие дубликаты, некорректный JSON, не-JSON ответ, oversized response и отказ авторизации приводят к явной безопасной ошибке без публикации сырого тела.
4. Перенаправление, неканонические/пустые сегменты, path traversal, query/fragment/percent-encoding в RCI path и не-loopback HTTP отклоняются. Принимаются только абсолютные `/rci/...` пути с ASCII-командными сегментами. Изменяющие состояние операции запрещены по умолчанию; read-only `POST /rci/show` разрешён только как явно объявленная операция без изменения состояния.
5. Ошибки и штатные метаданные не содержат токен; завершённый исследовательский запрос сохраняет только санитизированные поля и необязательный digest ответа.
6. Ethernet-коннектор не меняет конфигурацию и не трактует `link=down` как доказательство пустого разъёма.
7. Исследовательские schema-команды используют общий RCI-клиент и сохраняют только разрешённые имена полей, типы, длины массивов и digest; неразрешённые имена интерфейсов и скалярные значения не выводятся.

## Проверенное поведение и границы

На KN-1012 / KeeneticOS 5.2 Beta 3 `GET /rci/show/version` и `GET /rci/show/interface` вернули HTTP 200 JSON с `X-NDMA-TKN` через временный SSH-туннель к loopback RCI. Общий Go-клиент повторил Ethernet-запрос и выдал те же пять физических port-записей; санитизированный результат, binary/source hashes и preflight сохранены в [свидетельстве Go-прогона](../../experiments/keenetic-ethernet-management-20261106/evidence/attempt-20261106T230806Z-go-rci-carrier/README.md). Исходный snapshot и ограничения приведены в [отчёте Ethernet](../../experiments/keenetic-ethernet-management-20261106/README.md) и [свидетельстве RCI](../../experiments/keenetic-ethernet-management-20261106/evidence/attempt-20261106T221126Z-rci-interface-filtered/result.json).

Это не подтверждает поддерживаемость других путей/методов, схемы записи, RCI на других прошивках, запрос из установленной Hestia на роутере или передачу пользовательского трафика. Go research CLI прошёл read-only запрос; watcher carrier использует Linux sysfs interface names, а RCI используется только для отдельного native port inventory. Kernel interface inventory и carrier ещё не запускались на KN-1012. Read-only список портов интегрирован в REST-модель и UI как `nativeEthernetPorts`, отдельно от Linux `interfaceName`. Добавлен, но ещё не проверен на target JSON-схеме `WISPConnector`: он извлекает только идентификатор станции и оперативные поля, игнорируя SSID, description, ключи, адреса и произвольные RCI значения. Reader пока не включён в REST-модель, не доказывает соответствие WISP станции kernel device и не заменяет typed site-survey либо управление профилями; все Wi-Fi/WISP mutations остаются unsupported.

Официальный [справочник KN-1012, раздел HTTP API](https://storage.googleapis.com/docs.help.keenetic.com/cli/4.3/en/cli_manual_kn-1012.pdf) уточняет, что action-команды не меняют настройки, `POST /rci/show` выполняет их с JSON-параметрами, а результат повторяет структуру запроса. Поэтому общая библиотека допускает этот единственный read-only POST-путь без разрешения записи. Официальный список команд также описывает `show site-survey <interface>` как чтение доступных беспроводных сетей без изменения настроек. Фактический `POST /rci/show` с token на KN-1012 ещё не выполнялся.

## Использование

Go-эксперимент вызывает `go run ./cmd/keenetic-rci-ethernet` из `backend/`; schema исследования запускают `go run ./cmd/keenetic-rci-interface-schema` или `go run ./cmd/keenetic-rci-survey-schema`. Ограниченный WISP status reader можно проверить командой `go run ./cmd/keenetic-rci-wisp-status`; она выдаёт только ID станции, operational status и безопасные транспортные метаданные. Все команды используют транспорт из `pkg/keeneticrci`. Для новых типов запросов применяйте `NewClient(Config{...})` и `Client.Do`, затем добавляйте узкие типизированные коннекторы. Не логируйте `Response.Body` для несанитизированных операций. Примеры и ограничения описаны в [инструкции](../../experiments/keenetic-rci-readonly/prototype/README.md) и [SKILL](../../skills/keenetic-rci/SKILL.md).
