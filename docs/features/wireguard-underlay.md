# Через какое подключение устанавливается WireGuard
Согласованная цель: в редакторе поле «Подключаться через» по умолчанию показывает «Любое интернет-подключение». Для ручного режима можно отметить существующие подключения, кроме текущего, и перетащить их в порядке предпочтения. Циклические зависимости запрещены. Выбор сохраняется при повторном открытии. Профили без настройки используют обычный маршрут.
Шлюз направляет транспорт WireGuard через первый работоспособный выбранный выход, переходит к следующему при устойчивой деградации и возвращается после устойчивого восстановления. При исчерпании списка транспорт блокируется. Критерий проверки — наблюдение фактических пакетов в изолированной сети при нормальной работе, ухудшении и восстановлении. После проверки установить на stage1.

## Работа в редакторе

Откройте «Подключаться через» и отметьте подключения. Первое отмеченное получает высший приоритет. Для изменения порядка перетащите выбранную строку на другую или нажмите стрелку рядом с названием. Нажмите «Сохранить». Чтобы вернуться к обычному маршруту, выберите «Любое интернет-подключение». В таблице профилей кнопка «Обновить состояния» показывает текущий выбор шлюза.

## Как движется трафик

В ручном режиме каждый выбранный выход получает локальный UDP-порт sing-box, связанный с адресом и портом WireGuard-сервера. Это позволяет направить транспорт в прямой интерфейс, нативный WireGuard-выход sing-box или управляемый туннель. Выбор касается внешних UDP-пакетов данного туннеля. Измерение доступности кандидатов и проверка DNS и HTTPS внутри туннеля служат разным целям: первое оценивает сам выход, вторая подтверждает работу соединения с пиром. Локальные служебные сокеты рассчитаны на доверенные процессы шлюза.

Одиночный неудачный замер не вызывает перехода. Шлюз учитывает три последовательных неудачных замера либо три потери в окне из восьми. Если выход отвечает на HTTPS, но не доставляет пакеты до WireGuard-пира, шлюз проверяет следующий выход. Перед возвратом на предпочтительное подключение он отдельно проверяет путь до пира, продолжая работать через резерв.

При возврате шлюз проверяет доступность пира через предпочтительный выход служебными DNS-запросами внутри туннеля. Для профилей AmneziaWG с переменным дополнением пакетов эта проверка использует пакет размером с MTU интерфейса. Если путь или DNS-сервер не пропускает такую пробу, шлюз продолжает использовать рабочий резерв.
