# Смена реального IPv4 при сохранённом FakeIP

На стенде клиент один раз разрешает имя и запоминает FakeIP. До истечения исходного TTL авторитетный резолвер меняет A-запись с адреса A на B. Старый адрес служит контрольной целью и продолжает отвечать. При свежей записи новые соединения могут использовать A. После истечения TTL и успешного получения B новые TCP- и UDP-потоки через тот же FakeIP должны попадать на B. Клиент повторно имя не запрашивает.

Для имени без явного правила стенд относит A и B к разным странам и проверяет изменение фактического выхода. Для имени с явной маской смена адреса сервиса должна сохранить назначенную группу. Нужны наблюдения со стороны резолвера, целевого сервера и выходных интерфейсов. Состояние уже установленных соединений, выдача устаревшего ответа при ошибке DNS и фоновый прогрев — отдельные сценарии.

Предыдущий прототип после истечения TTL возвращал ошибку разрешения на новых потоках с сохранённым FakeIP. Исправленный прототип повторяет выбор разрешённого резолвера и получает актуальный ответ по запросу нового потока. Параллельные потоки используют общую попытку обновления.
