# Редактор доменных списков

## Поведение интерфейса

На странице «Доменные списки» кнопка «Создать список» открывает модальное окно с пустыми полями. Нажатие на название существующего списка открывает это же окно с текущими значениями. Поля: название, группа (включая «Группа не назначена») и маски — по одной на строку. Кнопка `info` рядом с полем масок открывает popover с примерами и кратким пояснением формата. Некорректные маски показывают ошибку и запрещают сохранение.

Пока шлюз не предоставляет API создания и изменения списка, «Сохранить черновик» сохраняет значения только в состоянии страницы и помечает их как локальный черновик. Он не вызывает API, не меняет показанный снимок шлюза и не означает, что новые потоки используют эти значения. Закрытие и повторное открытие модального окна не теряет черновик; повторная загрузка страницы его сбрасывает.

## Контракт масок в текущей модели

Поддерживается DNS-имя с обязательным префиксом `*.` и ASCII DNS-метками, например `*.example.org` и `*.deep.example.org`. Суффикс охватывает сам домен и поддомены любой глубины. Пустые строки игнорируются; одинаковые маски в одном списке запрещены. Порядок строк не влияет на приоритет. Ограничения согласованы с `docs/requirements.md` и валидатором `frontend/src/masks-draft.ts`.

## Операция шлюза

Текущий API читает `id`, `masks`, `group`, `enabled` и позволяет отдельно менять только `group` для существующего списка. Поэтому единый Save редактора пока является локальным действием. Требуемую серверную атомарную запись с проверкой актуальной версии, результатом применения и конфликтом фиксируем в [предложениях API](api-proposals.md#api-01-группы-правила-и-доменные-списки).

## Критерии приёмки UI

1. Создание открывает пустую форму, редактирование по нажатию на список — заполненную.
2. Название, группа и маски доступны для редактирования; группа содержит все группы текущего снимка и вариант без группы.
3. Кнопка `info` раскрывает примеры масок и доступна с клавиатуры.
4. Маски проверяются до сохранения; ошибка указывает некорректные строки.
5. Сохранённый черновик виден в таблице как черновик и остаётся там при закрытии/повторном открытии модального окна.
6. Ни создание, ни сохранение черновика не посылают запрос и не изменяют снимок шлюза.
