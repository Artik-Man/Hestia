## PolyWAN 2.0

Кандидат для управления маршрутами на Linux общего назначения. Демон видит интерфейсы, созданные pppd или сетевым менеджером, проверяет каждый выход через его интерфейс, отдельно отслеживает IPv4 и IPv6 и закрепляет соединение за выбранным выходом. Есть веса и приоритеты, события, API и метрики Prometheus. PolyWAN сам не устанавливает SSTP-соединения. [Репозиторий и требования к платформе](https://github.com/drsound/polywan)

| Возможность | Значение для проекта |
|---|---|
| Проверки ICMP Echo и TCP, пороги потерь, RTT и джиттера | Обнаруживают деградацию канала. Для оценки UDP до конкретного сервиса нужен внешний сигнал. |
| Окно качества от 2 до 100 раундов | Перевод в минуты зависит от частоты проб. Выбор среди прошедших пороги каналов учитывает приоритет и вес. Для ранжирования двух живых каналов по часовым потерям нужна дополнительная логика. |
| Правило по IP назначения, протоколу и порту с одним полем `uplink` | Можно применить решение «UDP к X через FI-2». Выбор правила и момент переключения должен определить отдельный компонент. |
| `fallback = "block"` для правила и `all_down_policy = "ready"` либо `"keep"` для общей балансировки | Блокировка одного выбранного выхода поддерживается. Цепочка «FI-1 → FI-2 → блокировка» целиком одним правилом не выражается. |
| Политики распространяются на пересылаемые новые соединения | Трафик локального DNS-резолвера требует отдельной привязки к выходу. |

Для стенда нужно проверить, какие интерфейсы видит демон при размещении PPP в отдельных пространствах, и выбрать одного владельца правил маршрутизации. [Конфигурация PolyWAN](https://github.com/drsound/polywan/blob/main/docs/configuration.md) · [Устройство маршрутизации](https://github.com/drsound/polywan/blob/main/docs/how-it-works.md)

## failoverd (sector-f)

Демон позволяет задавать контрольные адреса, частоту проб, окно истории и Lua-функции для обработки результатов. По описанию подходит для простого мониторинга потерь. Для двух SSTP обнаружены следующие ограничения. [README проекта](https://github.com/sector-f/failoverd)

- История и последняя статистика индексируются адресом назначения `Dst`. При проверке одной цели X через два канала внутри одного процесса измерения смешиваются. [Код хранения результатов](https://github.com/sector-f/failoverd/blob/main/internal/ping/pinger.go)
- Имя интерфейса преобразуется в его первый IPv4-адрес, который становится источником пробы. При совпадающих `172.16.3.33` это не различает два туннеля. Можно запускать по экземпляру в каждом namespace и собирать результаты отдельно. [Создание и запуск пробы](https://github.com/sector-f/failoverd/blob/main/internal/ping/probe.go)
- Описанный в README «UDP ping» использует непривилегированный datagram-сокет для ICMP Echo в библиотеке pro-bing v0.1.0. Успешная проба совместима с потерями прикладного UDP. Изоляция процессов не меняет протокол пробы. [Зависимости failoverd](https://github.com/sector-f/failoverd/blob/main/go.mod) · [Реализация pro-bing](https://github.com/prometheus-community/pro-bing/blob/v0.1.0/ping.go)

В роли основного источника данных для выбора маршрута failoverd не покрывает сценарий «один UDP-сервис, два выхода». Его можно использовать отдельно как ICMP-индикатор.

## Другие компоненты

| Компонент | Какую задачу закрывает | Что остаётся проверить или реализовать |
|---|---|---|
| OpenWrt mwan3 | Политика содержит список участников с приоритетами. При отказе всех участников `last_resort = unreachable` или `blackhole` обеспечивает блокировку. Из рассмотренных механизмов это ближе всего к модели группы стран. | Потребуется выбрать OpenWrt и совместимую версию пакета. Официальная реализация и порт на nftables различаются. Отдельно остаются домены на общем IP и UDP-потери по назначениям. [Документация OpenWrt](https://openwrt.org/docs/guide-user/network/wan/multiwan/mwan3-nft) |
| sing-box | FakeIP, правила по суффиксу имени, выбор резолвера и привязка исходящих подключений к интерфейсу или namespace. Кандидат для правил стран при общем IP у разных доменов. | Проверить порядок исключений, раздельные DNS-кэши и путь DNS и данных при отказе канала. [FakeIP](https://sing-box.sagernet.org/configuration/dns/server/fakeip/) · [Правила](https://sing-box.sagernet.org/configuration/route/rule/) · [Исходящие подключения](https://sing-box.sagernet.org/configuration/shared/dial/) |
| iperf3 | Управляемые UDP-тесты с заданной интенсивностью, привязкой к интерфейсу и выводом JSON. Подходит для проверки потерь и пропускной способности между шлюзом и своим сервером. | Для непрерывного мониторинга нужны планирование и сбор результатов. По тесту до своего сервера нельзя установить потери до стороннего X. [Руководство ESnet](https://software.es.net/iperf/invoking.html) |

В качестве примера обычного multi-WAN также рассматривался pfSense. Его документация описывает выбор шлюза по правилам, мониторинг контрольного IP и обращение с состоянием существующих соединений при отказе. [Multi-WAN в pfSense](https://docs.netgate.com/pfsense/en/latest/multiwan/concepts.html)

Для Linux общего назначения предложено испытать PolyWAN для управления каналами, sing-box для доменов и iperf3 как инструмент стенда. OpenWrt с mwan3 — отдельный кандидат, если допустима такая платформа. Собственная логика нужна прежде всего там, где история по паре «канал и цель» превращается в решение о переключении отдельного назначения либо всей группы.


## Клиентские протоколы и панель 3X-UI

3X-UI — ориентир для формы выбора протокола и редактирования его параметров. Для Гестии основная операция — добавить исходящее подключение к удалённому серверу и проверить его как выход конкретной группы. Кандидаты для опытов: VLESS outbound и WireGuard endpoint в sing-box, отдельная userspace-реализация AmneziaWG. Для VLESS нужно проверять совместимость с транспортом и настройками защиты конкретного сервера. Для AmneziaWG нужно зафиксировать поколение протокола и параметры обеих сторон. Само наличие реализации не подтверждает работу в Гестии. [3X-UI](https://github.com/MHSanaei/3x-ui) · [VLESS](https://sing-box.sagernet.org/configuration/outbound/vless/) · [WireGuard](https://sing-box.sagernet.org/configuration/endpoint/wireguard/) · [AmneziaWG](https://github.com/amnezia-vpn/amneziawg-go)
