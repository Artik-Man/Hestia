# Страницы и дорожная карта локальной панели

В меню панели семь разделов. Стартовая страница «Группы подключений» показывает действующий снимок. Изменение привязки списка использует подтверждение шлюза. Остальные операции, которым пока недостаёт данных или команд API, представлены локальными черновиками либо состоянием «данные недоступны». [Предложения для следующей итерации бэкенда](api-proposals.md).

## Меню и страницы

| Пункт меню | Задача администратора | Какие страницы открываются внутри |
|---|---|---|
| Группы подключений | Посмотреть группы и приоритет выходов. | Диалог [создания и переименования группы](features/connection-groups.md), сортируемый список групп и выходов, ссылки на карточки. Перетаскивание меняет черновик, кнопка «Сохранить» [применяет порядок на шлюзе](group-order.md). |
| Доменные списки | Найти или подготовить список доменных масок. | Создание и редактирование открываются в модальном окне: название, группа, textarea масок и popover с примерами. В строке есть карандаш для редактирования и корзина для удаления с подтверждением. Сохранение и удаление проверяют ответ шлюза. Смена группы на карточке по-прежнему использует подтверждённую операцию. |
| Подключения | Настроить конкретный выход и проверить его до включения в трафик. | Для WireGuard и AmneziaWG доступен единый редактор с импортом файла, ручным вводом и чтением сохранённых ключей. |
| Карта стран | Определить маршрут по реальному IP, когда не совпала доменная маска. | Таблица назначений по стране, редактор блока стран и порядка блоков, назначение «Остальной мир». Для неизвестной страны показывается правило группы по умолчанию. |
| Журнал трафика | Найти соединение и понять причину выбора или блокировки. | Поиск по домену либо IPv4/IPv6 вместе с фильтром протокола. В деталях события видны решение, подтверждённый выход либо отсутствие подтверждения, связанные попытки DNS. Здесь же задаётся срок хранения, исходно 24 часа. |
| Качество связи | Понять, почему переключился основной выход или почему другой выход выбран только для одного назначения. | Вверху страницы расположены проверки UDP, TCP и других настроенных протоколов. У каждой проверки здесь доступны все её настройки, включая общие для подключений цели, интервал и тайм-аут. Ниже одновременно показаны все группы, по одной таблице на группу. Каждая строка содержит название подключения, статус, балл каждой проверки по шкале от 0 до 100 и объём её выборки в отдельной колонке и общую оценку — среднее арифметическое баллов всех проверок подключения. Таблица показывает порядок выбора выходов контроллером по текущему качеству и отмечает фактически активный выход. Для разбора результата доступны цель, окно оценки, потери, объём выборки, время и причина переключения. Предусмотреть переход в локальную Grafana для подробных графиков после её подключения. |
| DNS | Настроить поведение кэша и проверить, какие имена прогреваются. | Параметры хранения и выдачи при сбое, порог обращений и окно активности, интервал обновления. DNS-сервер конкретного подключения задаётся в его карточке. |

В разделах с неполными данными панель указывает, какие действия доступны. Создание, редактирование и подробности открываются из соответствующего списка. Например, из группы можно перейти к конкретному подключению, а из записи журнала — к группе и выходу, которые фигурируют в решении.

## Внешние ссылки в меню

Рядом с разделами Гестии предусмотрена группа «Внешние сервисы». Первый пункт — «Grafana ↗». Он открывает локальную Grafana в новой вкладке, чтобы администратор мог вернуться к настройкам шлюза. Панель показывает ссылку при наличии адреса в настройках уже развернутой интеграции.

| Интеграция | Как ей пользуется администратор |
|---|---|
| Grafana | Открывает из меню графики каналов, DNS и ресурсов шлюза. Проектный адрес — `https://grafana.home.arpa`. |
| Prometheus и node_exporter | Смотрит в Grafana метрики, которые Prometheus собирает с контроллера и экспортёров. Прямой доступ к этим службам предусмотрен внутри шлюза. |
| Alertmanager | Получает сгруппированные уведомления по настроенному каналу. Получатель ещё не выбран. По текущей схеме интерфейс Alertmanager доступен локальным службам. |
| Loki и Alloy | Возможное расширение для поиска системных журналов в Grafana. Решение зависит от потребности в таком поиске. |

Критерий приёмки ссылки: с клиентского устройства в домашнем Wi-Fi при недоступном внешнем интернете открыть Grafana из меню, войти по HTTPS и увидеть дашборд. Исходная вкладка Гестии сохраняет открытую страницу. Условия локального DNS, сертификата и доступа описаны в [плане мониторинга](monitoring.md#как-открыть-grafana-из-wi-fi).

Предложения по API для следующих страниц собираем в [реестре для обсуждения](api-proposals.md).

## Порядок разработки

| Очередь | Результат | Зависимость и проверка |
|---|---|---|
| 0. Группы и правила, просмотр | Готово и проверено локально. | Снимок с двумя группами загружается без внешнего интернета. Повторная загрузка восстанавливает экран после ошибки. |
| 1. Группы и правила | Навигация, просмотр, применение привязки через типизированный сервис. Сортировка групп и выходов применяется отдельной операцией. Маски доступны в черновике; удаление пустой группы подтверждается шлюзом. | Смена привязки должна дождаться ответа шлюза, при конфликте перечитать состояние. Для прочих записей см. API-01. |
| 2. Подключения | Действующий перечень и карточки выходов, создание, редактирование и удаление профилей WireGuard. | [Сценарии редактора](features/wireguard-editor.md). |
| 3. Журнал трафика | Фильтры, представление событий и деталей, настройка срока хранения в черновике. | Источник событий и сохранение настроек требуют API-03. |
| 4. Карта стран | Локальное редактирование назначений и порядка блоков, проверка выбора группы по правилам черновика. | Чтение и применение карты требуют API-04. |
| 5. Качество связи | Настройки проверок и таблицы всех групп с результатами измерений и текущим порядком выбора выходов. | Панель получает действующие настройки, результаты и подтверждённый выход через API-05. История решений остаётся отдельным этапом. |
| 6. DNS | Подготовка параметров кэша и прогрева. | Состояние резолверов, список прогреваемых имён и применение настроек требуют API-06. |

Для каждого раздела до реализации согласуем поведение и приёмку. Контракт и Angular-сервисы генерируются из Go по [правилам проекта](../AGENTS.md). Очереди со второй по шестую можно менять местами по готовности серверных функций. При включении нового пункта проверяем навигацию, открытие страницы по прямой ссылке и работу без внешнего интернета.

Основание для карты страниц — [требования](requirements.md), [состав событий журнала и мониторинга](monitoring.md) и [общая дорожная карта](roadmap.md).
