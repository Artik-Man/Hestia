# Страницы и дорожная карта локальной панели

Предложение для согласования. Сейчас доступны [«Группы и правила» и «Подключения»](frontend.md). Стартовая страница — «Группы и правила». Стартовая страница отвечает на вопрос «как настроена маршрутизация?». На вопрос «куда ушло конкретное соединение?» отвечает журнал. Это разделение важно, когда настроенный первым выход отличается от фактического.

## Меню и страницы

| Пункт меню | Задача администратора | Какие страницы открываются внутри |
|---|---|---|
| Группы и правила | Понять порядок групп и выходов, найти привязку доменного списка и изменить её. | Из общего просмотра открываются карточки группы и доменного списка с масками и привязкой. Редактор списка запланирован. |
| Подключения | Настроить конкретный выход и проверить его до включения в трафик. | Из перечня открывается карточка выхода с группой, приоритетом и доступностью. Тип протокола, результат последней проверки и создание профиля ожидают данных API. |
| Карта стран | Определить маршрут по реальному IP, когда не совпала доменная маска. | Таблица назначений по стране, редактор блока стран и порядка блоков, назначение «Остальной мир». Для неизвестной страны показывается правило группы по умолчанию. |
| Журнал трафика | Найти соединение и понять причину выбора или блокировки. | Поиск по домену либо IPv4/IPv6 вместе с фильтром протокола. В деталях события видны решение, подтверждённый выход либо отсутствие подтверждения, связанные попытки DNS. Здесь же задаётся срок хранения, исходно 24 часа. |
| Качество связи | Понять, почему переключился основной выход или почему другой выход выбран только для одного назначения. | Сравнение подключений группы по цели и протоколу, окно оценки, потери, объём выборки, время и причина переключения. Предусмотреть переход в локальную Grafana для подробных графиков после её подключения. |
| DNS | Настроить поведение кэша и проверить, какие имена прогреваются. | Параметры хранения и выдачи при сбое, порог обращений и окно активности, интервал обновления. DNS-сервер конкретного подключения задаётся в его карточке. |

В меню предлагаются только готовые разделы. Создание, редактирование и подробности открываются из соответствующего списка. Например, из группы можно перейти к конкретному подключению, а из записи журнала — к группе и выходу, которые фигурируют в решении.

## Внешние ссылки в меню

Под страницами Гестии предлагается группа «Внешние сервисы». Первый пункт — «Grafana ↗». Он открывает локальную Grafana в новой вкладке, чтобы администратор мог вернуться к настройкам шлюза. Предусматриваем место для этой группы на этапе навигации. Саму ссылку показываем после настройки интеграции, независимо от готовности страницы «Качество связи».

| Интеграция | Как ей пользуется администратор |
|---|---|
| Grafana | Открывает из меню графики каналов, DNS и ресурсов шлюза. Проектный адрес — `https://grafana.home.arpa`. |
| Prometheus и node_exporter | Смотрит в Grafana метрики, которые Prometheus собирает с контроллера и экспортёров. Прямой доступ к этим службам предусмотрен внутри шлюза. |
| Alertmanager | Получает сгруппированные уведомления по настроенному каналу. Получатель ещё не выбран. По текущей схеме интерфейс Alertmanager доступен локальным службам. |
| Loki и Alloy | Возможное расширение для поиска системных журналов в Grafana. Решение зависит от потребности в таком поиске. |

Критерий приёмки ссылки: с клиентского устройства в домашнем Wi-Fi при недоступном внешнем интернете открыть Grafana из меню, войти по HTTPS и увидеть дашборд. Исходная вкладка Гестии сохраняет открытую страницу. Условия локального DNS, сертификата и доступа описаны в [плане мониторинга](monitoring.md#как-открыть-grafana-из-wi-fi).

Предложения по API для следующих страниц собираем в [реестре для обсуждения](api-proposals.md).

## Порядок разработки

| Очередь | Результат | Зависимость и проверка |
|---|---|---|
| 0. Группы и правила, просмотр | Готово и проверено локально. | Снимок с двумя группами загружается без внешнего интернета. Повторная загрузка восстанавливает экран после ошибки. |
| 1. Навигация и редактирование правил | Общая навигация готова, включая настраиваемую ссылку Grafana. Далее — редактор масок и привязки списка. Затем управление порядком групп, выходов и группой по умолчанию. | Сначала согласовать права на запись, момент применения и поведение при ошибке. Изменить привязку, подтвердить выбор группы для нового соединения. При отклонении изменения продолжает действовать прежняя конфигурация. Удаление обычной группы сохраняет списки и маски. Удаление текущей группы по умолчанию блокируется. |
| 2. Подключения | Перечень и карточка выхода по снимку готовы. Далее — данные профиля, создание, проверка и включение. | Нужен API профилей и проверки через конкретный выход. Первый протокол выбираем по готовности сквозного испытания. Пройти создание двух профилей одного типа, проверить каждый и включить выбранный. Целевой набор — SSTP, VLESS, WireGuard и AmneziaWG. |
| 3. Журнал трафика | Поиск, фильтр, детали события и срок хранения. | Нужен источник событий потоков. По IP найти запись без домена, совместить поиск с UDP, различить блокировку и подтверждённую передачу. Детализацию DNS добавить после появления связи между запросом и потоком. |
| 4. Карта стран | Назначения стран и блоков, их порядок, правило остального мира. | Нужен рабочий GeoIP в контроллере. Проверить приоритет маски, отдельной страны и пересекающихся блоков. Проверить отдельно известную страну без записи и неизвестную страну. |
| 5. Качество связи | История проб и объяснение переключений, настройка окна оценки (исходно 60 минут). | Нужны история измерений и события контроллера. Различить отсутствие измерений и полную потерю пакетов, адресное переключение и смену выхода для всей группы. |
| 6. DNS | Управление кэшем и прогревом. | Нужна интеграция DNS в службу. Изменить параметры и подтвердить по наблюдениям, что частое имя обновляется, а редкое выбывает из прогрева. Семантику выдачи истёкших ответов согласовать до реализации формы. |

Для каждого раздела до реализации согласуем поведение и приёмку. Контракт и Angular-сервисы генерируются из Go по [правилам проекта](../AGENTS.md). Очереди со второй по шестую можно менять местами по готовности серверных функций. При включении нового пункта проверяем навигацию, открытие страницы по прямой ссылке и работу без внешнего интернета.

Основание для карты страниц — [требования](requirements.md), [состав событий журнала и мониторинга](monitoring.md) и [общая дорожная карта](roadmap.md).
