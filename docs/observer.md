# Независимые измерения каналов

Первый результат этапа 4 — работающий в режиме наблюдения измеритель. На Linux ARM64 он посылает одинаковые активные пробы через каждый указанный интерфейс группы, включая резерв. Цель задаётся IPv4-адресом тестового echo-сервера, портом и протоколом. TCP и UDP учитываются отдельно. Отсутствие ответа обычного интернет-сервиса на произвольный UDP-пакет ничего не говорит о потере пакетов, поэтому для этого опыта используем сервер с известным ответом.

Каждый цикл даёт сопоставимые измерения для одной цели на всех выходах. Решения принимаются в скользящем окне, по умолчанию 60 минут. Недостаток данных и равенство сохраняют текущий выбор. Изменение рекомендации для UDP до X не меняет результаты TCP до X или UDP до Y. Диагностика отличает локальную ошибку пробы от потери ответа. Вывод показывает цель, протокол, выходы, количество измерений и причину рекомендации. Пороговые значения на стенде экспериментальные.

Приёмка на ARM64 включает равные условия, выбор FI-2 только для UDP до X при потерях на FI-1 и восстановление. Рекомендация записывается в журнал, клиентские маршруты продолжают действовать по текущей конфигурации. Реальное часовое окно проверено в [764 раундах на ARM64](../experiments/observer/README.md#реальное-окно-60-минут). Сквозные проверки этапа 4 и оставшиеся условия эксплуатационной готовности учтены в [дорожной карте](roadmap.md#учёт-оставшихся-экспериментов-этапа-4).

Для длительного прогона проверяем границу реального окна. В начале сеанса стенд вносит потери на одном пути, затем восстанавливает доставку. Измеритель продолжает опрос обоих путей, пока ранние потери не покинут окно. В отчёте нужны фактическая длительность, параметры прогона и счётчики до и после истечения старых наблюдений. Если после восстановления оба пути равны, текущая рекомендация сохраняется.

Измеритель привязывает сокет к Linux-интерфейсу, доступному в его сетевом пространстве. Это позволяет различить выходы стенда. Для подключения, реализованного внутри sing-box без интерфейса ядра, потребуется отдельный способ отправлять пробу через конкретный выход.

Установочный комплект поставляет измеритель в составе бинарника Гестии и отдельный unit. Оператор создаёт конфигурацию измерений в `/etc/hestia/observer.json`, после чего включает наблюдение командой `sudo systemctl enable --now /usr/local/lib/hestia/hestia-observe.service`. Записи доступны через `journalctl -u hestia-observe -f`. Команда `sudo systemctl disable --now hestia-observe.service` останавливает пробы. После обновления бинарника перезапустите включённую службу через `sudo systemctl restart hestia-observe.service`.

[Формат конфигурации и журналов](../cmd/hestia-observe/README.md). [Методика испытаний на ARM64](../experiments/observer/README.md).
