# Первый экран локальной панели Гестии

Спецификация согласована 4 ноября 2026 года. Администратор открывает панель из домашней сети, чтобы выяснить, какие выходы настроены в каждой группе и какие доменные списки к ней привязаны.

## Границы первой версии

Экран «Группы и правила» работает в режиме просмотра. Локальный API читает тот же снимок конфигурации, который принимает контроллер. Панель показывает доступность по данным снимка. Фактический путь отдельного соединения требует других данных.

## Приёмка

1. При отключённом внешнем интернете браузер загружает приложение, стили и иконки со шлюза.
2. На конфигурации с двумя группами видны их выходы в настроенном порядке и отметка группы по умолчанию. Доступность выхода соответствует снимку.
3. Для каждого списка видны маски, признак включения и группа. У непривязанного списка видна пометка «Группа не назначена».
4. При недоступности API панель сообщает об ошибке. После восстановления API администратор может повторить загрузку без перезагрузки страницы.
5. Открытие и обновление экрана не меняют конфигурацию и селекторы маршрутизации.

Стек и требования к следующим операциям описаны в [требованиях к панели](requirements.md). Редактирование правил и [журнал трафика](features/traffic-journal.md) входят в этап 6.

## Сборка и запуск

Для сборки и запуска панели по этому примеру используйте Linux ARM64. Нужны Node.js 24 LTS (от 24.15) и Go 1.26 или новее. Из корня репозитория соберите статические файлы и запустите панель со снимком из эксперимента по переключению выходов.

```sh
(cd frontend && npm ci && npm run build)
go -C backend run ./cmd/hestia-panel -assets ../frontend/dist/hestia/browser \
  -snapshot ../experiments/controller-service/evidence/failover-snapshot.json
```

Откройте в браузере [локальную панель](http://127.0.0.1:8080). В этом примере группа `russia` выбрана по умолчанию, а у группы `finland` первый выход `fi1-out` недоступен и второй `fi2-out` доступен. Маска `*.fi.lab.test` привязана к `finland`.

Для доступа с домашнего Wi-Fi запустите собранный для шлюза `hestia-panel` с флагом `-listen <LAN-IP>:8080`, укажите каталог со статическими файлами и снимок службы. По умолчанию сервер слушает только адрес обратной петли. Панель рассчитана на доверенную сеть: любой клиент с доступом к этому адресу может прочитать настройки групп и списков. Для работы собранной панели Node.js и внешний интернет не требуются.

## Данные экрана

При открытии и повторной загрузке браузер запрашивает `GET /api/groups-and-rules`. Сервис перечитывает файл, проверяет его теми же правилами, что и контроллер, и возвращает только поля экрана. Первая группа в снимке считается группой по умолчанию. Отсутствующая запись о доступности выхода означает «недоступен». В текущей модели список участвует в выборе маршрута, когда у него есть привязка к группе. При ошибке чтения или проверки снимка панель предлагает повторить загрузку.

Чтобы перенести сервер с машины разработки на шлюз Debian ARM64, выполните из корня репозитория:

```sh
mkdir -p dist
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go -C backend build -o ../dist/hestia-panel ./cmd/hestia-panel
```

Перенесите на шлюз бинарный файл, файл уведомлений о лицензиях `frontend/dist/hestia/3rdpartylicenses.txt` и содержимое `frontend/dist/hestia/browser/`. Процессу нужен доступ на чтение к каталогу сборки и файлу снимка.

## Проверка 4 ноября 2026 года

В Chromium на localhost прошли все пять критериев приёмки. При заблокированных внешних запросах браузер получил HTML, CSS, JavaScript, SVG и ответы API только с адреса панели. После восстановления снимка повторная загрузка с клавиатуры вернула данные без навигации. Содержимое и время изменения файла сохранились. Проверка на ширине 360 пикселей прошла без горизонтальной прокрутки.

Проверка зависимостей через npm audit не выявила известных уязвимостей в production-зависимостях. Полный аудит отметил два предупреждения средней важности в инструментах разработки: [minimatch](https://github.com/advisories/GHSA-g3hv-75wg-m249) и [glob](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4). Линтер использует фиксированные шаблоны проекта. Сборка панели не обходит недоверенные каталоги с отменой через AbortSignal. На шлюз поставляются статические файлы.

## Изменение API

Меняйте типы ответа и регистрацию операции на стороне Go. Из корня репозитория выполните `make generate-api`: Huma v2.40.0 строит из регистрации операции и Go-типов OpenAPI 3.0.3. Первый шаг сохраняет машиночитаемый контракт в `backend/api/openapi.yaml`, второй запускает OpenAPI Generator 7.21.0 с генератором `typescript-angular`. Для генерации нужны Go, Node.js и Java 21. При первом запуске команда скачивает JAR и сверяет его SHA-256. Для обычной сборки панели используются сохранённые в репозитории исходники клиента.

Компонент вызывает `PanelService.getGroupsAndRules()` и проверяет полученные данные перед отображением. Изменения Go-кода, контракта и клиента передавайте вместе. CI повторяет генерацию и проверяет добавленные, удалённые и изменённые файлы.

Проверка `govulncheck` для `./cmd/hestia-panel` на Go 1.27.3 с Huma v2.40.0 не обнаружила известных уязвимостей в используемом коде. Повторная генерация дала побайтово одинаковые файлы YAML и TypeScript.

## Навигация и просмотр подключений

Стартовый адрес открывает «Группы подключений» (`/#/groups`) с порядком групп и выходов. На отдельной вкладке «Доменные списки» (`/#/domain-lists`) видны маски и привязки. На странице `/#/connections` он видит названия и типы подключений, их доступность и выбранный транспорт. Пустой перечень и ошибка чтения различимы. Обе страницы должны открываться по прямой ссылке и после обновления браузера, а кнопки «Назад» и «Вперёд» должны восстанавливать выбранный раздел.

Адрес Grafana задаётся при запуске панели флагом `-grafana-url`, например `-grafana-url https://grafana.home.arpa`. Укажите адрес настроенной локальной интеграции. Панель получает ссылку через сгенерированный сервис для `GET /api/navigation`. При пустом адресе в меню остаются внутренние страницы. При заданном адресе Grafana открывается в новой вкладке. Загрузка страниц не требует обращения к Grafana.

Форма смены группы вызывает [операцию подтверждённого применения](list-binding.md). На установленном шлюзе она включает подготовку профиля, перезапуск служб и проверку действующих селекторов. При просмотре карточки запрос применения не выполняется. Страница доменных списков открывает существующий список в модальном редакторе и позволяет создать новый. Кнопка «Сохранить» применяет название, группу и маски на шлюзе. [Поведение и критерии редактора](features/domain-lists-editor.md).

## Группы подключений и карточка доменного списка

В «Группах подключений» кнопки создания и редактирования открывают диалог названия. Переименование сохраняет ID группы. [Правила названий групп](features/connection-groups.md).

Старая закладка на группу открывает общий список групп. Из «Доменных списков» открывается карточка списка. Раздел «Подключения» показывает три таблицы: Ethernet, Wi-Fi и виртуальные подключения. Старая закладка на карточку выхода открывает этот раздел. Карточка списка показывает маски, состояние и привязку. При проверке используем тот же снимок, что и для обзорных страниц.

Ссылку можно сохранить и открыть напрямую. После обновления карточки данные должны соответствовать новому снимку. Если объект исчез, пользователь видит сообщение и может вернуться к перечню. При недоступности API сохраняется повторная загрузка.

## Работа со страницами панели

В меню сверху вниз идут «Качество связи», «Журнал трафика», «Подключения», «Группы подключений», «Доменные списки», «Маршруты по странам» и «DNS». Адреса новых страниц используют фрагмент URL, например `/#/country-map` и `/#/traffic`. Браузер открывает страницу по сохранённой ссылке и после перезагрузки. Старая ссылка `/#/groups-and-rules` ведёт в группы, а с параметром `?list=...` — в доменные списки. Сохранённый путь `/connections` без фрагмента открывает перечень подключений.

**Применение привязки.** Откройте карточку доменного списка, выберите группу или «Группа не назначена» и нажмите «Применить привязку». Форма отправляет в сгенерированный сервис текущую и выбранную группы. Подтверждение должно содержать ожидаемые ID списка и группы. После ответа панель перечитывает снимок. При конфликте выберите действие заново по обновлённым данным. Запись требует запуска панели в режиме применения привязок на управляемом шлюзе. [Настройка режима записи](list-binding.md).

Таблица Ethernet обновляется при открытии страницы, вручную и каждые 15 секунд на открытой вкладке. В ней видны адаптеры, состояние кабеля и названия уже настроенных прямых выходов, например `keenetic-direct`. Карандаш в его строке открывает форму с единственным полем «Название подключения». Новое название используется в таблице, группах и при выборе транспорта туннеля; внутренний идентификатор продолжает связывать подключение с маршрутами.

**Подключения WireGuard и AmneziaWG.** Выберите «Добавить» → «WireGuard». Загрузите файл `.conf` или заполните поля вручную, выберите группу, затем нажмите «Сохранить». Карандаш открывает тот же редактор с сохранёнными параметрами и полными значениями ключей. Красная корзина в строке профиля запрашивает подтверждение удаления. Туннели отображаются в таблице виртуальных подключений. Новое подключение попадает в конец выбранной группы. Для изменения порядка перетащите его на странице «Группы подключений» и сохраните изменения. [Редактор подключения](features/wireguard-editor.md).

**DNS.** Откройте страницу DNS, чтобы сохранить настройки кэша и прогрева. Под формой одновременно видны автоматически добавленные домены, чёрный список и ручной список. Панель отдельно показывает недоступность наблюдений. [Настройка DNS и управление доменами](dns-settings.md).

**Маршрутизация по странам.** Каждая колонка после названия страны соответствует группе подключений. При первом открытии все страны назначены текущей группе по умолчанию, а переключатель карты выключен. Выберите другую группу в строке страны или нажмите кнопку ↓ под названием группы. При смене группы по умолчанию назначения в таблице сохраняются. Завершив редактирование, нажмите «Сохранить» над таблицей. Панель запишет все назначения и состояние переключателя одним запросом. При следующем открытии панель читает их со шлюза. Ранее созданный локальный черновик остаётся в браузере. На управляемом шлюзе сохранение применяет маршруты для новых соединений. Явная доменная маска имеет приоритет. Далее шлюз ищет страну реального IP по точному уточнению, затем по локальной базе DB-IP. Если страна неизвестна, работает группа по умолчанию. Ошибка применения сохраняет предыдущую конфигурацию.

**Порядок групп и выходов.** На вкладке групп перетащите группу или выход, в том числе из одной группы в другую, затем нажмите «Сохранить». Панель отправит исходный и новый порядок на шлюз и дождётся подтверждения. [Контракт операции и включение записи](group-order.md). Остальные локальные черновики сбрасываются при перезагрузке страницы.

**Диагностика.** В [журнале трафика](features/traffic-journal.md) фильтры назначения, страны, протокола, периода и выхода размещены в шапке таблицы. Кнопка обновления слева от настроек перечитывает события с выбранными фильтрами. В разделе «Качество связи» редактируются общие проверки UDP и TCP, их цели, интервал, тайм-аут и окно оценки. Под настройками каждая группа показывает подключения в порядке контроллера. Колонки содержат статус, баллы и объём выборки по каждой проверке, а также средний балл. При отсутствии измерений таблица показывает «нет данных». Подробности по каждому разделу указаны в [реестре предложений по API](api-proposals.md).

## Проверка страниц

Из каталога `frontend` выполните `npm test`, `npm run format:check`, `npm run lint` и `npm run build`. Установите браузер командой `npx playwright install chromium` или задайте путь к Chromium в `CHROME_BIN`. После сборки `npm run test:browser` проверяет выбор файла, сохранение и удаление через собранную панель с синтетическим конфигом и локальными ответами API.

Для сквозного прогона на разрешённом шлюзе задайте `HESTIA_E2E_URL` с адресом панели и выполните `npm run test:e2e` из `frontend`. Перед выбором файла тест требует пустого списка профилей WireGuard / AmneziaWG на шлюзе: тест публикует новую конфигурацию общего прокси. Затем тест передаёт файл из `private/hestia_amnezia_for_awg.conf` на этот шлюз, запускает проверку, сохраняет выход с уникальным ID в конце списка выбранной группы и удаляет его с подтверждением через панель. После обоих действий тест заново открывает страницу. Для другого файла задайте `HESTIA_E2E_CONFIG`, для выбора группы — `HESTIA_E2E_GROUP`. По умолчанию используется первая группа.

В Chromium проверены прямые ссылки на шесть страниц, старые закладки, управление с клавиатуры и ширина 360 пикселей. Сценарии формы привязки проверены на отключённой записи в локальной панели и с тестовыми ответами для подтверждения, конфликта и ошибки. Отдельная проверка компонентов с тестовыми наблюдениями подтвердила вывод деталей потока и DNS, полной потери пакетов и списка имён в прогреве.

Для уведомлений панель использует общий PrimeNG Toast. На странице DNS результаты сохранения, конфликты и ошибки отображаются рядом с формой. Ошибки ввода остаются у полей, а состояния загрузки и недоступности страницы остаются видимыми до изменения состояния.

В таблице Wi-Fi кнопка «Добавить Wi-Fi» открывает выбор адаптера, диапазона, SSID и защиты. Для защищённой сети введите пароль. При редактировании пустое поле сохраняет прежний пароль. Для подключения шлюзу нужны Wi-Fi-адаптер и работающий NetworkManager.
