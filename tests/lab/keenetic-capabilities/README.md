# Изолированная проба сетевого пространства Keenetic

`netns-probe.go` проверяет один системный вызов `unshare(CLONE_NEWNET)` на закреплённом потоке. Создание нового пространства меняет только сетевой контекст этого потока. После записи JSON завершается весь процесс; пространство уничтожается вместе с ним. Проба не создаёт сокетов, интерфейсов, маршрутов, правил или дочерних процессов, не меняет сеть родительского SSH-процесса и не пробует обходной путь при отказе.

## Сборка и запуск

Из корня репозитория:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 GOTOOLCHAIN=local GOPROXY=off \
  go build -trimpath -buildvcs=false -o /tmp/hestia-netns-probe \
  tests/lab/keenetic-capabilities/netns-probe.go
```

Перенос на роутер, проверка SHA-256 и запуск выполняются отдельно после согласования доступа. Не запускайте пробу на случайной машине. Команда внутри выделенного временного каталога:

```sh
./netns-probe --probe-netns
```

Без аргументов и с `--help` выводится справка, системный вызов не выполняется. Код 0 означает полученное наблюдение, в том числе отказ ядра. Поле `status` различает `created_and_process_exiting` и `rejected`; при отказе записаны errno и его стандартное описание. Неверные аргументы дают код 2, ошибка вывода — код 1.

Успех не подтверждает работоспособность TUN, маршрутизации, Netfilter или VPN. Отказ не разрешает изменения сети хоста. Для последующих проб нужен отдельный план. Состояние существующих маршрутов и правил сравнивается по хешам до/после; сырые адреса и топология в свидетельства не публикуются. Операция запуска ограничивается таймаутом на машине оператора; тестируемый процесс не запускает фоновые службы.

Результаты сохраняются в [отчёте Keenetic](../../../experiments/keenetic-capabilities/README.md).
