# Гестия (Hestia)

**Гестия (Hestia)** — название проекта и Linux-шлюза, который управляет несколькими интернет-подключениями. Гестия выбирает страну выхода по правилам для доменов, а подключение внутри страны — по качеству связи. Например, когда UDP-пакеты до одного сервера теряются на первом финском VPN, шлюз должен уметь перевести трафик к этому серверу на второй финский VPN. Если все финские выходы недоступны, трафик этой группы блокируется.

Рабочая поставка Гестии предназначена для Linux ARM64. Команда `make build` создаёт в `dist/artifacts/<версия>/` два комплекта: `linux-arm64` и `keenetic-arm64-experimental`, каждый с контроллером, наблюдателем, панелью и манифестом. Keenetic-комплект пока содержит универсальные ARM64-бинарники: платформенные адаптеры и `.ipk` ещё не реализованы, установка этого комплекта отклоняется. Зависимости и подготовка закреплённых runtime-входов описаны в [инструкции сборки](scripts/build/readme.md).

Исходники Go и контракт API находятся в [backend/](backend/), приложение Angular — во [frontend/](frontend/). Сценарии установки, конфигурация systemd и инструкции по развёртыванию собраны в [deploy/](deploy/).

## Порядок работы

Согласованный порядок — **SDD → эксперимент, MVP или прототип при необходимости → TDD**. Сначала описываем ожидаемое поведение и критерии приёмки и согласуем их с Product Owner. Эксперимент отвечает на конкретный открытый вопрос; его результат и границы применимости записываем рядом со свидетельствами. Реализацию проверяемого поведения начинаем с теста, который воспроизводит требование и падает до внесения изменения.

## Проверки кода

[Сценарии проекта](scripts/readme.md) разделяют сборку (`make build`), тесты исходников (`make test-source`), установку готового комплекта (`make deploy-dev BUNDLE=...`) и проверку установленной версии (`make test-dev`). Установка и тесты явно выбирают стенд; питание ВМ не меняется.

[Проверки и инструменты стенда](tests/lab/README.md) находятся в `tests/lab/`, [отчёты и свидетельства](experiments/README.md) — в `experiments/`. Для модульных проверок стенда используйте `make test-lab`; они также входят в `make check`.

Из корня репозитория выполните `make fmt`, чтобы применить gofmt к коду контроллера и shfmt к Bash-сценариям установки и стенда. Команда `make check` проверяет форматирование, запускает `go vet`, ShellCheck и тесты. Те же проверки выполняются в GitHub Actions для push и pull request.

На машине разработки установите shfmt 3.11.0 (`go install mvdan.cc/sh/v3/cmd/shfmt@v3.11.0`) и ShellCheck 0.11.0 (например, `pipx install shellcheck-py==0.11.0.1`). Добавьте каталоги с установленными командами в `PATH`. Установщику на целевом шлюзе эти инструменты не нужны.
