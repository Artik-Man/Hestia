# Гестия (Hestia)

Гестия — Linux-шлюз, который управляет несколькими интернет-подключениями и направляет клиентский трафик через выбранные выходы. Она предназначена для работы рядом с существующим домашним или офисным роутером: устройства продолжают подключаться к своей сети, а Гестия выбирает, через какого провайдера или VPN-подключение пойдёт их трафик.

## Функциональные возможности

Целевая функциональность Гестии включает:

- **Группировать подключения по назначению.** Подключения объединяются в группы, например «Россия» и «Финляндия». Администратор задаёт приоритет групп и порядок выходов внутри каждой группы.
- **Выбирать маршрут по доменам.** Доменные списки позволяют направлять сайты и сервисы через нужную группу. Более конкретное доменное правило имеет приоритет над менее конкретным.
- **Назначать выход по стране адреса.** Карта GeoIP позволяет выбрать группу подключений для страны назначения. Явное доменное правило имеет приоритет над GeoIP.
- **Следить за качеством подключений.** Гестия проверяет доступные и резервные выходы, сравнивает потери и другие показатели и может выбрать более стабильное подключение. Если в выбранной группе нет доступного выхода, её трафик блокируется.
- **Обслуживать DNS.** Шлюз кэширует DNS-ответы и поддерживает фоновое обновление часто используемых записей. Для групп и подключений могут применяться разные DNS-серверы.
- **Управлять настройками через панель.** Веб-панель предназначена для управления группами, подключениями, доменными списками и настройками шлюза, а также для просмотра состояния и журнала трафика.

Подробное описание требований, сценариев, ограничений и состояния реализации находится в [оглавлении документации](DOCUMENTATION.md).

## Платформы и состояние поставки

Рабочая целевая платформа — Linux ARM64 (AArch64). Команда `make build` собирает комплекты в `dist/artifacts/<версия>/`: `linux-arm64` и `keenetic-arm64-experimental`. Linux-комплект предназначен для установки на Linux ARM64. Экспериментальный комплект Keenetic собирается отдельным Go-вариантом с Entware-путями `/opt` и включает `.ipk` с default deny-профилем и opkg lifecycle hooks. IPK `20261107-123735-f9fea441ebfd` установлен на KN-1012; базовые службы готовы, веб-панель доступна из LAN по `http://192.168.1.1:8080/`, а API групп и read-only инвентаризации физических портов возвращают HTTP 200. RCI Ethernet link подключён к watcher-композиции; нативные port ID остаются отдельными от Linux device names. Автоматический rollback обновления отсутствует. RoutePolicy/dataplane, DNS, Wi-Fi/WISP и полноценный путь клиентского трафика ещё не готовы. Неподдерживаемые операции отказывают явно. Подробности установки, панели и границ проверки — в [отчёте пакета](experiments/keenetic-ipk-packaging/README.md).

Детали сборки и фактические результаты испытаний описаны в документации проекта; обзор документов дан в [DOCUMENTATION.md](DOCUMENTATION.md).
