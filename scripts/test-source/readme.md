# Проверки исходников

`python3 scripts/test-source/run.py [--output КАТАЛОГ]` запускает форматирование без записи, линтеры и unit-тесты (`make check`), проверку воспроизводимости OpenAPI/клиента, frontend unit/build/browser и Go race. К стендам сценарий не подключается; поставочные комплекты не создаёт. Сборка фронтенда нужна его браузерным тестам.

Нужны Go, Python 3 с dnspython из [закреплённых зависимостей тестов](../../tests/lab/requirements-test.txt), Node/npm, Java, зависимости frontend, браузер Playwright/`CHROME_BIN`, shfmt 3.11.0 и ShellCheck 0.11.0. `SHFMT` и `SHELLCHECK` принимают пути инструментов. API генерируется в отдельном временном каталоге. Рабочие исходники не перезаписываются; frontend обновляет свой локальный `dist`. Для проверки API требуется заранее заполненный `frontend/.cache` с закреплённым OpenAPI Generator: после `npm --prefix frontend ci` его создаёт штатная команда `npm --prefix frontend run generate`. Подготовка Python-окружения описана в [инструкции лабораторных тестов](../../tests/lab/README.md#автоматические-проверки).

Результаты и журналы сохраняются в новом `experiments/dev-validation/evidence/source-*` либо `--output`. Ошибка обязательного этапа означает ненулевой код. `scope.json` явно отмечает платформу: успешные проверки на macOS не доказывают Linux-only возможности ядра. Изолированные Linux-сценарии установленной версии запускаются отдельно через [test](../test/readme.md).

`source.json` содержит ревизию Git, признак незакоммиченных изменений и хеши фактических исходников: HEAD не выдаётся за полное описание грязного дерева. Удобный алиас — `make test-source`. Время зависит от кэшей Go/npm и браузера; обычно несколько минут, с заметной загрузкой CPU и временными артефактами сборки.

Linux-only Go unit-тесты raw sockets и offline NetworkManager могут пропускаться на хосте без соответствующих возможностей. Installed-test проверяет отдельные сетевые сценарии с копиями установленной версии; он не заменяет эти Linux Go unit-тесты и не обещает их покрытие.

`make check` включает `make test-workflows`: файлы `scripts/**/test_*.py` запускаются по одному, включая каталоги с дефисами без `__init__.py`. Пустое дерево или модуль без тестов возвращают ошибку. Поэтому общий source-run не дублирует эти проверки отдельным обходом.
