# Общие модули

`common.py` предоставляет `Stand`, `Run` и проверку манифеста для [сборки](../build/readme.md), [установки](../deploy/readme.md) и [проверок](../test/readme.md). Напрямую модуль не запускается. `paths.sh` проверяет владельца, права и отсутствие неожиданных ссылок перед привилегированной заменой файлов.

Описание стенда — JSON: `name`, `transport` (`lima` или `ssh`), `expected_hostname`, `platform` (`linux-arm64`), `fixture` (необязательная информационная метка; сама по себе не разрешает менять конфигурацию). Для Lima нужны `instance` и `lima_home`; для SSH — `host`, `user`, `port`. Паролей в описании нет: используется обычная конфигурация ключей SSH с обязательной проверкой известного ключа сервера. IPv6 SSH-адреса пока не поддерживаются. Необязательный `panel_url` — HTTP-адрес с числовым IP; тест дополнительно проверяет принадлежность адреса выбранному гостю.

Примеры: [dev](stands/dev.json), [prod](stands/prod.json), [SSH](stands/ssh.example.json). В примере prod адрес панели соответствует существующим сценариям поставки: `http://192.168.1.133:8080`; при другой настройке его нужно изменить. Пути и ожидаемую идентичность задают явно. `LIMACTL` переопределяет путь Lima. Проверка требует уже запущенной ВМ; модуль не создаёт, не запускает и не останавливает машины. Наличие примера prod не разрешает агенту обращаться к нему.

Манифест содержит полную опись файлов и SHA-256. Проверка отклоняет недостающие, лишние, изменённые файлы и ссылки. Хеши обнаруживают повреждение, но не удостоверяют автора: комплект и содержащиеся в нём сценарии должны происходить из доверенной сборки. Журнал `results.json` фиксирует команды, время, PASS/FAIL/SKIP; ошибки сохраняются и не считаются успехом.

`test_common.py` выполняет офлайн-проверки манифестов, отказа неверному стенду и распространения ошибки в отчёт: `python3 -m unittest discover -s scripts/shared`. Он не подключается к сети.
