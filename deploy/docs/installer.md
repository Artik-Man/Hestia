# Установка Гестии

Цель первого установщика — на Debian ARM64 с systemd одной командой установить и запустить текущий контроллер и совместимую версию sing-box. Для первого запуска достаточно локальной конфигурации с заблокированным выходом. Установщик не переводит клиентский трафик на шлюз и не меняет основной маршрут машины. Реальные VPN-профили и параметры сети зависят от места установки.

Критерии приёмки: установка на машине без заранее установленного контроллера и sing-box; работоспособность обеих служб и локального API после установки; повторный запуск сохраняет конфигурацию оператора; ошибка установки видна через код завершения. Проверяем в гостевой системе ARM64. Успешный запуск службы сам по себе не доказывает, что Wi-Fi-клиенты используют Гестию.

В конце каждого запуска установщик сам выполняет локальную проверку с ограничением времени: обе службы активны, API отвечает, контроллер и селектор согласованы. При ошибке команда возвращает ненулевой код и указывает, какую службу диагностировать. Проверка занимает несколько секунд после запуска служб; скачивание, сборка и установка в это время не входят. Она не переключает реальные подключения для теста.

Перед запуском systemd-служб установщик публикует проверенные файлы и освобождает блокировку конфигурации: служба восстановления получает её самостоятельно. При ошибке установщик повторно получает блокировку и восстанавливает прежние файлы только если опубликованное поколение не изменилось. Если другая операция уже создала новую конфигурацию или оставила незавершённую транзакцию, автоматический откат отказывается перезаписывать её и сохраняет резервную копию по указанному в ошибке пути. [Проверка на dev](../../experiments/dev-validation/README.md).

## Переносимый комплект и профиль стенда

Комплект предназначен только для виртуальной машины или физического устройства с Linux ARM64. На машине сборки нужен Go. Соберите ARM64-бинарник и упакуйте его вместе с официальным архивом sing-box 1.14.4 для Linux ARM64:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go -C backend build -trimpath -buildvcs=false -o /tmp/hestia-linux-arm64 ./cmd/hestia
bash deploy/build-installer.sh /tmp/hestia-linux-arm64 sing-box-1.14.4-linux-arm64.tar.gz hestia-arm64.run
```

Перед созданием `.run` упаковщик проверяет, что контроллер собран для `linux/arm64`, и сверяет SHA-256 архива sing-box с закреплённой суммой Linux ARM64-релиза.

Скопируйте на новую Debian ARM64-ВМ доверенный `hestia-arm64.run`, свой `stand.json` и VPN-файлы, на которые ссылается профиль. Положите VPN-файлы рядом с JSON. Единственная команда на ВМ: `sudo bash hestia-arm64.run --config stand.json`. Git и Go там не нужны. Минимальной системе может понадобиться доступ к репозиторию Debian для стандартных утилит. Без параметра `--config` установка сохраняет настройки существующей Гестии; на чистой ВМ запускается конфигурация без клиентского входа. Явный `--config` заменяет топологию.

Возьмите [пример профиля](../examples/stand.json). Сам JSON не содержит ключей. Соседние `ru-wg.conf` и `fi-wg.conf` содержат синтетические данные для примера. Замените их конфигурациями своих серверов и установите права `0600` на секретные файлы. Поле `interfaces` задаёт виртуальные WireGuard-интерфейсы sing-box с собственными адресом, ключами, пиром и DNS. Одинаковый внутренний IP допустим. Они работают в userspace; установка не перенастраивает Ethernet и основной маршрут ВМ. Вход стенда — SOCKS5 на loopback; для доменных правил передавайте имя через SOCKS, например с `curl --socks5-hostname 127.0.0.1:1080`. Реальный VPN-сервер на другой стороне должен уже существовать.

В `groups` первая группа — группа по умолчанию, порядок `exits` задаёт предпочтение. Списки `lists` с пустой строкой в `group` сохраняются выключенными. Более длинная маска важнее, равенство разрешает порядок групп. В примере `www.deepseek.com` попадает в Россию, остальной `*.com` — в Финляндию. В `healthy` укажите доступность выходов стенда; в примере ни один не объявлен доступным. Самопроверка подтверждает решение контроллера, но не доступность пиров. Профиль версии 1 поддерживает WireGuard и IPv4; SSTP, VLESS, AmneziaWG и прозрачный перехват клиентского трафика этим форматом пока не разворачиваются.

## Экспорт для новой машины

```sh
sudo hestia-export-config stand-backup.json
```

Команда создаёт новый JSON с правами `0600`: в нём только имена VPN-файлов, списки (включая неназначенные) и доступность из текущего снимка. Ключи и содержимое VPN-файлов не экспортируются. Существующий файл не перезаписывается. При ручном изменении конфигурации служб, которое нельзя представить исходным профилем, экспорт возвращает ошибку. Перенесите JSON и отдельно исходные VPN-файлы по защищённому каналу и передайте его тому же установщику через `--config`. Экспортированные значения доступности — состояние стенда на момент экспорта, а не замер качества на новой ВМ. Копия с теми же ключами представляет того же WireGuard-клиента: для двух одновременно работающих шлюзов назначьте разные ключи и настройте пиры соответственно.


Укажите в `config_file` только имя обычного файла в каталоге профиля. Абсолютные пути, переходы в родительский каталог и символьные ссылки отклоняются. Для WireGuard поддержан один раздел `[Interface]` с `Address`, `DNS`, `PrivateKey` и один `[Peer]` с `PublicKey`, `Endpoint`, `AllowedIPs`. Если приватный ключ лежит отдельно, удалите `PrivateKey` из VPN-конфига и укажите в записи интерфейса JSON `"private_key_file": "fi.key"`. Команды wg-quick вроде `PostUp` не выполняются. После установки службам доступна закрытая рабочая конфигурация; для будущего переноса храните собственные исходные VPN-файлы отдельно.

Рабочие файлы можно хранить вне репозитория или в исключённом из Git каталоге `stand.local/`. Встроенная проверка SHA-256 выявляет повреждение комплекта, но не заменяет проверку его происхождения. Стенд рассчитан на доверенную локальную ВМ: SOCKS и управляющий API доступны локальным процессам без индивидуальной аутентификации.

### Доступ к панели и AWG-коннектор

Операции API управления WireGuard/AmneziaWG пока не имеют пользовательской аутентификации. `Host` и CORS-проверки не заменяют её: любой клиент с доступом к адресу панели может отправлять разрешённые операции. Слушайте только loopback или конкретный частный LAN-адрес и не публикуйте панель через WAN, публичный reverse proxy или внешний туннель. На текущем лабораторном этапе предполагается доверенная домашняя сеть; для недоверенной сети сначала потребуется отдельная аутентификация и авторизация.

На странице «Подключения» выберите «Добавить» → «WireGuard». Заполните поля или импортируйте файл, выберите группу и позицию выхода. Несколько профилей WireGuard/AmneziaWG могут быть готовы одновременно. Политика группы выбирает выход по доступности и порядку. В таблице профилей кнопка «Обновить состояния» повторно запрашивает статус каждого туннеля. [Ресурсы и пределы проверки](../../docs/features/multiple-wireguard.md).

На шлюзе с установленным профилем панель может менять привязку доменного списка через [локальный помощник](../../docs/list-binding.md). При установке также добавляется служба восстановления незавершённой транзакции до запуска sing-box.
