# Установка из доверенной копии проекта

На Debian ARM64 с systemd запустите из корня проекта:

```sh
sudo bash deploy/install.sh
```

Установщик временно скачивает и проверяет по SHA-256 Go 1.27.3 и архив sing-box 1.14.4 для ARM64, собирает контроллер из этой копии проекта и настраивает службы `hestia` и `hestia-sing-box`. Если компилятор и внешний доступ на целевой системе нежелательны, используйте [переносимый комплект](../docs/installer.md). Для проверки на ВМ можно передать доверенный бинарник параметром `--controller-binary` и официальный архив параметром `--sing-box-archive`. При необходимости установщик добавляет системные утилиты через APT.

На чистой машине без профиля установка создаёт селектор `bootstrap` с единственным выходом `deny`. Входов для клиентского трафика нет. Для применения своего профиля передайте `--config stand.json`. Ссылки на файлы разрешаются относительно каталога этого профиля. Профиль храните вместе с нужными файлами доступа. Обработанная конфигурация sing-box может содержать ключевой материал. В `/etc/hestia` она доступна только root, а служба читает приватную копию через systemd credentials. Снимок доступности читает только root и служебная группа контроллера.

Повторная установка без `--config` сохраняет настройки оператора. Явный `--config` применяет новый профиль. Установщик проверяет оба конфигурационных файла до замены, переносит файлы атомарно и перезапускает службы. При неудачном запуске или проверке он восстанавливает предыдущие файлы и состояние служб. Предварительно установленные пакеты Debian остаются в системе.

При загрузке шлюза служба `hestia-binding-recovery.service` восстанавливает последнюю подтверждённую конфигурацию при наличии незавершённой операции. Затем `hestia-binding-watch.path` начинает следить за журналом незавершённой операции и `hestia-sing-box` загружает конфигурацию через systemd credentials. Если процесс применения завершается до подтверждения, служба `hestia-binding-watch.service` дожидается освобождения блокировки и восстанавливает предыдущую конфигурацию. Поддержка записи и условия применения описаны в [спецификации привязки списка](../docs/list-binding.md).

Самопроверка в конце установки занимает до шести секунд. Она сверяет владельца слушающего сокета на `127.0.0.1:9090`, содержимое загруженной конфигурации sing-box, состояние двух служб, запись о выбранном выходе в журнале именно текущего запуска и выбор управляющего API. Эта проверка читает локальное состояние. Доставку TCP, UDP и DNS до удалённых пиров проверяйте отдельно.

```sh
systemctl status hestia hestia-sing-box
journalctl -u hestia -u hestia-sing-box -b
```

## Чистая установка на hestia-stage1

Из корня рабочей копии на Mac выполните:

```sh
make stage1-fresh
```

Команда собирает текущие локальные исходники контроллера, панели и Angular, а также закреплённые версии инструментов AmneziaWG. Нужны запущенная ВМ, Go 1.27.3, npm и доступ к зависимостям. Для личного стенда команда находит Lima в `/private/tmp/hestia-vm-run`. Другой путь можно указать через `LIMACTL` и `LIMA_HOME`.

При каждом запуске службы шлюза кратковременно останавливаются. Содержимое `/etc/hestia`, включая сохранённые VPN-профили, и состояние `/run/hestia-awg` удаляются. Команда применяет `deploy/scheme3/guest-profile.json` с группой `default` и выходом `keenetic-direct`. После запуска служб она проверяет панель на `192.168.1.133:8080` и оба API. При ошибке после сброса повторите команду после устранения причины.
